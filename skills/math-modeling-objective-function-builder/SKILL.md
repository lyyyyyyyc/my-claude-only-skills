# 数学建模目标函数构建器

## 概述
- 第一动作必须调用 `math-modeling-brainstorm`，先把题意、变量、目标类型和约束来源对齐，再进入目标函数构建。
- 将题面/附件/约束转化为可解释的目标函数（单目标或多目标）。
- 输出 Markdown，包含清晰文字解释 + LaTeX 公式，并给出参数/权重建议。

## 什么时候优先用本 skill
- 用户已经明确在做“目标函数构建”这一件事，而不是整题建模路线选择。
- 用户问“这题目标函数怎么写”“这个目标到底该最大化还是最小化”“多目标如何合并”。
- 用户已经有题意、变量或约束材料，希望把它们转成可写进论文的优化目标表达。
- 用户不是要直接写代码，而是要先把目标函数的数学表达、含义和权重口径讲清楚。

## 第一优先动作
当本 skill 被触发时，先做以下四件事，再进入目标函数构建：

1. 先调用 `math-modeling-brainstorm`，确认当前是在做哪个题目、哪一问、哪一阶段的目标函数。
2. 先确认目标类型：单目标还是多目标，最大化还是最小化。
3. 先确认约束来源和参考材料来自题面、附件还是现有文档。
4. 先确认关键变量、单位、尺度或权重口径，再开始写公式和解释。

## 证据链与逻辑严谨性（必须遵守）
- 对用户任何结论性回答，必须给出完整且可核查的证据链，至少包含：`已知事实/数据来源 -> 分析方法 -> 推理步骤 -> 结论 -> 不确定性与验证建议`。
- 结论必须逐条对应证据，不得跳步推理，不得以主观经验替代证据。
- 若证据不足，必须明确标注“证据不足”，先补充提问或给出可执行核验方案，再输出结论。
- 涉及目标函数形式、权重设定、归一化策略时，必须说明“为何这样设定”，并解释改动后可能带来的影响。
- 最终建议必须附带可复现检查点（如：目标定义来源、公式编号、关键参数、验证方式）。

## 固定流程（一步一问，优先选择题）
> **选择题必须使用数字选项（如 1/2/3），用户只需回数字即可。**
1) **确认目标函数的任务范围（一句话）：**
   - 若用户未明确具体题目/小问，必须先问清“针对哪个题目/哪一问/哪一阶段”。
   - 示例选择题（数字选项）：
     1. 题目 X 的第 1 问
     2. 题目 X 的第 2 问
     3. 自定义（请给一句话范围）

2) **确认约束来源/参考材料：**
   - 若用户未说明，必须询问“约束条件来自哪里（题面/附件/文档）”。
   - 示例选择题（数字选项）：
     1. 题面文字
     2. 附件数据表（请给文件名）
     3. 现有文档（请给文档名/路径）

3) **确认目标类型：**
   - 单目标（最大化/最小化）或多目标（加权、分层、ε-约束等）。
   - 示例选择题（数字选项）：
     1. 单目标最大化
     2. 单目标最小化
     3. 多目标（默认加权求和，可改）
     4. 先由 Codex 初步判断目标类型，再与用户确认
   - 若选 4：先给出基于题面/数据的初步判断，并用一句话说明依据，再让用户确认或改选。
   - **多目标默认组合方式说明（需简要解释含义与优缺点）：**
     - 加权求和：多个目标线性叠加，需归一化与权重设定。
     - 分层/优先级：先满足主目标，再在不显著损失主目标前提下优化次目标。
     - ε-约束：主目标优化，其他目标转为阈值约束（如 \(f_2 \le \epsilon\)）。

4) **确认变量/尺度/单位与权重：**
   - 要求用户给出关键变量含义、单位、尺度或数据范围；如多目标需给权重或偏好。
   - 若目标函数系数来自前问估计、预测模型或代理模型，必须记录其来源、适用范围和不确定性。必要时同时给出确定性、情景或鲁棒版本，不得把带误差的估计值直接当作绝对精确常数。

## 不确定性处理（必须遵守）
- 任何不确定或信息不足之处，必须明确说明并向用户提问；在信息完全确定前不得隐含假设。

## 思考流程（必须调用）
- **调用 `math-modeling-brainstorm`** 先做结构化思考，得到：
  - 目标候选与取舍
  - 关键变量与约束摘要
  - 数据字段映射
- 以其结果为依据构建目标函数与解释。

## 输出规范（推荐 Markdown 文档）
必须包含以下部分，顺序固定：

1. **任务范围（一句话）**
   - 若用户未给，先补问。

2. **目标函数文字说明**
   - 用自然语言解释“优化什么、为什么、结果如何理解”。
   - **必须详细说明**，保证非专业读者仅看文字即可理解目标函数含义与优化方向。

3. **符号与变量定义**
   - 逐条解释变量、索引集合、单位与尺度。

4. **目标函数（LaTeX）**
   - 公式用 LaTeX 表达。
   - **规则：**“MPE 中公式行首不要直接写 `-`，用 `\;\-\;` 或 `aligned` 前置 `&`。”

5. **多目标组合方式说明（若为多目标）**
   - 说明采用：加权求和 / 分层优先级 / ε-约束，并给出选择理由。

6. **权重/参数含义与取值建议**
   - 给出权重含义、可行范围、默认建议与调参影响。

7. **假设与约束来源**
   - 列出关键假设与约束来源（题面/附件/文档名）。

8. **（可选）替代方案与取舍**
   - 至少 1 个替代目标函数，并说明优缺点。

## 质量检查
- 单位一致性、方向（max/min）明确
- 目标函数与约束不冲突
- 多目标权重可解释、尺度归一化合理

## Common Mistakes
- 没先确认任务范围，就直接写出一个看似完整的目标函数。
- 直接给公式，不解释“优化什么、为什么这样写、结果如何理解”。
- 忽略约束来源，导致目标函数和题面口径脱节。
- 多目标时只给加权求和公式，却不解释权重来源和替代组合方式。
- 变量、单位、尺度没有说清，导致公式虽然能写出来但无法落地。

## 维护说明（供 Codex 按需读取）
- 若后续需要继续为本 skill 新增触发词、目标函数写法规则、权重口径说明或维护结构，请先读取 `references/add-content-guide.md` 再修改。

## 完成后强制复审（再次头脑风暴）
- 在完成“目标函数建立”后，**必须再次调用 `math-modeling-brainstorm`**。
- 复审目标：对照题目要求与附件数据（如 PDF 题面、Excel 附件），逐条核查**是否遗漏任何要求**、是否与题面一致。
- 如发现不符合或遗漏，**必须明确指出具体问题与位置**，并给出修正建议。
