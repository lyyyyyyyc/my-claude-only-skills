# 总路由与优先级规则

## 这一部分写什么

- 本文件只负责“先怎么分流、再去哪个 reference 查图型”，不重复展开各分支的专项细节。
- 它保留原分类树的排序：同一分支里越靠上越常见，第一项就是默认首选图。
- 排序不是越过数据条件的硬覆盖规则。先排除不适用图型，再在剩余候选中遵守原有顺序。
- 若某个分支已经在用户提供的分类图中给出明确顺序，仍按该顺序维护；新增条件只说明何时跳过，不额外重排整棵树。

## 先判任务模式

1. `审图或审计咨询`：转到 `08-redraw-and-delivery-audit.md`；低清或截图材料仅报告可见缺陷、未知项和所需材料，不触发渲染或导出门禁。
2. `选图咨询`：只输出图型建议、理由和一至两个备选。
3. `实际绘图或重绘`：进入主文件的字体、视觉、导出和审计门禁。
4. `方法逻辑图`：转到 `06-flowchart-and-methodology.md`。
5. `论文补图规划`：用户明确要求检查论文可视化缺口时，转到 `07-figure-gap-review.md`。
6. `统计图路由`：已有统计结果或出现专业统计图型时，转到 `09-statistical-plot-routing.md`。

## 5 步判定法

1. 先判材料与证据：
   - 原始数据和可复现过程；
   - 可编辑表格或矢量图；
   - 清晰栅格图；
   - 低清或不完整截图。
2. 再判数据家族：
   - 数值型；
   - 类别型；
   - 数值型和类别型混合；
   - 地图；
   - 网络图；
   - 时间序列；
   - 方法逻辑。
3. 再判观测结构：
   - 单个变量的分布；
   - 两列或多列一一对应的成对观测；
   - 多组独立样本；
   - 每类别一个汇总值；
   - 每类别多条观测；
   - 区域、点位、节点、边或流量。
4. 再判是否有序：
   - 时间、阶段、等级、路径、空间序列等有序结构；
   - 无天然顺序的样本集合或变量关系。
5. 最后判观察目的：
   - 分布；
   - 比较；
   - 关系；
   - 构成；
   - 层级；
   - 流向；
   - 空间位置；
   - 网络关系；
   - 流程或收敛。

## 路由建议

- 纯数值数据：转到 `01-numeric.md`。
- 纯类别数据：转到 `02-categorical.md`。
- 数值和类别混合：转到 `03-mixed.md`。
- 带经纬度、区域边界、空间落点或空间聚合：转到 `04-map-and-network.md` 的地图部分。
- 带节点、边、邻接矩阵或流量：转到 `04-map-and-network.md` 的网络部分。
- 横轴是时间或其他天然顺序：转到 `05-time-series.md`。
- 输入主要是文字步骤、模块关系、伪代码或指标体系：转到 `06-flowchart-and-methodology.md`。

## 默认推荐规则

- 同一分支中，第一张满足条件的图才是默认首选图。
- 不满足条件时，说明跳过理由，再推荐该分支中第一个适用候选；不要为了保持顺序硬推不适用的图。
- 观察目的用于定位正确分支和过滤候选，不用于任意打乱原分类树的顺序。
- 如果用户没有额外偏好，先给首选图，再补一至两个备选图即可。
- 若用户只说“我有一组连续数据”，先判断看分布、走势、关系还是比较，不直接给图名。
- 精确比较通常优先选择位置或长度编码；面积、角度和色彩更适合作为补充编码。气泡图、饼图、雷达图和热图必须说明它们为何比点图、条形图、折线图或表格更适合当前目的。

## 论文写作快捷入口

这不是自动补图规则，只是在用户明确要求论文配图建议时帮助定位观察目的：

- 问题分析、模型框架：结构、依赖、流程。
- 算法设计、求解步骤：控制流、数据流、迭代与终止条件。
- 结果分析：差异、趋势、关系、空间分布。
- 参数扫描和灵敏度分析：响应曲线、二维参数面、热图或等高线。
- 方案比较：同量纲指标的比较、构成或明确的多指标评价。
- 时间调度：甘特图、时间线或资源流。
- 指标体系：层级或指标之间的关系。

必须回到数据结构和证据条件确认图型，不能把“结果分析”固定等同于雷达图，也不能把“字数较多”当作必须补图的理由。

## 新手快速入口

- 单变量数值分布：先看 `直方图 / 密度图`。
- 两列成对数值观测：先看 `散点图`；若横轴有天然顺序，再看 `连通散点图 / 折线图`。
- 多组独立数值样本：先看 `箱线图`，并确认每组确有多条观测。
- 单个类别变量：先看 `柱状图` 或 `棒棒糖图`。
- 类别与数值混合：先判断“每类别一个汇总值”还是“每类别多条样本”。
- 地图：先判断点位、区域统计、路线还是空间密度。
- 网络：先判断结构、流向、流量还是邻接矩阵。
- 时间序列：先按走势、窗口分布、组成变化或多序列比较分流。

## 命名规则

- 能从图片稳定识别的图名，按图中原意录入。
- 若图名存在更常用的标准叫法，可采用“标准名（图中叫法）”的写法，例如：
  - `热图（热力图）`；
  - `弦图（和弦图）`；
  - `圆堆图（circle packing）`；
  - `书脊图（spine plot）`。
- `矩形树图（treemap）`、`冰柱图（icicle）` 等层级图，若图片分辨率有限但上下文清楚，可按标准名补齐。

## 不要写什么

- 不要在这里重复每种图的详细适用场景、参数或代码模板。
- 不要在路由阶段直接展开绘图库、工具网站或完整导出流程。
- 不要把变量数、组数、类别数和每组观测数混作同一个判断维度。
- 不要因为个别名字和常见译名不同，就随意打乱原图里的顺序。
