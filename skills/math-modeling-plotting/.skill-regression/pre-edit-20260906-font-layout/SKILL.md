# 数学建模：绘图选图与分类路由

## 概述
- 第一动作优先调用 `math-modeling-brainstorm`，先确认数据家族、变量个数、是否有序和观察目的，再进入选图；若该能力不可用，则在本 skill 内按同一维度完成分流，并明确说明未调用外部能力。
- 若场景是中文论文插图、中文坐标轴或中文图例，`中文字体能否正常显示` 是硬前置检查；只要出现方框字、缺字或 `Glyph missing` 警告，就先修字体，再谈图型、配色和版式。
- 字体与版式优先级为：用户明确要求或官方目标模板 > 本项目强制默认标准 > 下游技能默认值。没有更高优先级要求时，默认使用 `中文 = 宋体（SimSun）`，`英文与阿拉伯数字 = Times New Roman`。
- 本 skill 只负责“根据数据决定画什么图”，不直接输出完整绘图代码。
- 目标是先选对图，再补一句为什么适合，避免一上来就默认折线图或柱状图。
- 分类骨架采用混合方案：顶层按 `数值型 / 类别型 / 数值型&类别型 / 地图 / 网络图 / 时间序列` 分流，再吸收连续/离散、单变量/多变量、有序/无序、子类/依赖/邻接关系等子分类。
- 默认遵守一条硬规则：同一分支内，越靠上的图越常见，第一项就是默认首选图，后面的图是次选或补充图。
- 这版已经按你补的图片把当前分类树补成完整版本；图名在看得清时按图片原意记录，必要时用更标准的中文名作括注。
- 选图优先级只在“候选图已满足数据结构与观察目的”的前提下生效；不适用的首选图必须跳过并说明原因，不能因它位于分类树顶部而强行推荐。
- 先区分“变量数量”“分组数量”“每组观测数量”和“成对关系”。两列一一对应的数值观测与两组独立样本不是同一个选图问题。
- 论文图表任务必须区分审图或审计咨询、选图咨询、实际绘图或重绘、方法逻辑图、论文补图规划和统计图路由；这些模式的授权边界、证据要求和交付物不同。

## 项目论文绘图强制默认标准

本节是本 skill 在当前项目中的运行时单一事实来源（SSOT），不是建议或可选风格。凡是用户要求绘制、重绘、优化、导出数学建模论文图表，或要求生成绘图 Notebook，均必须执行本节；与本文件其他一般性默认规则冲突时，以本节为准。`模型检验与分析/code/01_第九部分敏感性与稳健性论文图表.ipynb` 仅作为该标准的历史来源说明，不是当前运行依赖；未随 skill 提供时不得声称已核验或已调用该 Notebook。

### 强制字体标准

- 本节字体规则仅在没有用户明确要求或官方目标模板时生效。中文统一使用完整的 `SimSun`（宋体），优先从 `C:\Windows\Fonts\simsun.ttc` 或完整 `simsun.ttf` 加载；严禁使用 `simsunb.ttf`，因为它可能是 `SimSun-ExtB`，不能视为常规中文宋体。
- 在本项目默认标准下，英文和阿拉伯数字使用 `Times New Roman`。必须通过 `FontProperties` 或等价的逐对象绑定实现，不能只依赖全局字体回退链。
- 逐语言字体规则仅适用于纯语言对象：纯中文用完整的 `SimSun`，不含中文的纯英文、阿拉伯数字和英文符号对象用 `Times New Roman`。含中文的混合标签、图例、注释和坐标轴文字是例外，整条统一使用完整的 `SimSun`。
- 不再对同一标签做中英文分段渲染，也不使用自定义混合字体渲染器，避免分段定位、旋转、换行和布局计算引入额外错误。
- 绘图前必须对实际字体文件检查“冲、击、强、度、风险、调整、价值、名单、情景”等必要字形。字体找不到、字形不全、出现方框字或 `Glyph missing` 警告时，任务必须停止在修字体阶段，不得交付图片。
- 不使用中文与 MathText 混合渲染；`rho`、`eta` 等参数名使用普通 Unicode 或拆分为分别绑定字体的文本对象。

### 强制视觉与线条标准

- 文字颜色统一为深灰 `#444444`；白色不透明背景；坐标轴顶部和右侧边框默认隐藏。
- 坐标轴标签字号约为 `11` pt，刻度字号约为 `9.5` pt，普通图中文字和数据标注约为 `8--9` pt，图例约为 `9` pt。
- 常规曲线线宽约为 `1.2` pt，重点曲线可适度加粗；坐标轴线宽约为 `0.8` pt，刻度线宽约为 `0.7` pt。禁止把全图文字和线条同时设置得过细或全部加粗。
- 使用 `layout="constrained"` 管理版式；图例使用白色不透明底框并放在不遮挡数据的位置；精确版面尺寸时不得用 `bbox_inches="tight"` 改变页面尺寸。
- 对无序、离散的多系列数据，默认采用 Okabe--Ito 色盲友好定性色板，颜色顺序和数据语义必须在 Notebook 或结果说明中记录。连续或发散色图不由 Okabe--Ito 覆盖，应按下游能力或本文件的可用性回退规则选择。颜色不能作为唯一编码，至少同时使用标记、线型、直接标注或分面。
- 论文图内部不得写“图1”“图2”等图号或标题性图名；图号和图名放在文件名、图注或正文中。

### 强制输出与审计标准

- Notebook 画布预览使用约 `figure.dpi=120`，PNG 保存必须使用 `savefig.dpi=600`；同时至少输出一种可编辑矢量格式，优先为 SVG 或 PDF。PDF 使用 `pdf.fonttype = 42`，SVG 使用 `svg.fonttype = "none"`。
- 每次绘图必须保留数据来源、变换步骤、字体文件、色板及顺序、单位与轴范围依据、输出尺寸和 DPI 的记录；重绘任务必须写入独立输出目录，不得覆盖原始图和原始结果。
- 交付前必须实际检查渲染图：中文字形、`Glyph missing`、图例遮挡、文字裁剪、轴范围夸大、白底可读性和灰度下的系列区分度。任一项失败都视为未完成。
- 这套标准只约束表达层，不得为了“美化”修改原始观测、模型输出、异常值处置策略或计算口径。

### 执行门禁

每次生成或修改绘图 Notebook 时，必须按以下顺序执行并在输出中留下证据：

1. 先加载完整 SimSun 和 Times New Roman，打印实际字体文件路径与字体名称。
2. 检查必要中文字形；含中文的整条标签绑定 SimSun，纯英文和数字对象绑定 Times New Roman。
3. 设置本节规定的颜色、字号、线宽、背景、布局、DPI 和矢量字体参数。
4. 实际渲染至少一张代表性图，检查输出无方框字、无 `Glyph missing`、无裁剪和图例遮挡。
5. 只有在上述证据完整且全部通过后，才可以交付 Notebook 或图表；无法通过时必须先修复，不能以“用户本地字体可能不同”作为绕过理由。

## 任务模式与授权边界

先判定任务模式，再决定是否进入实际绘图门禁和哪一份参考文件：

1. `审图或审计咨询`：用户要判断已有图的问题、可读性或重绘风险；读取 `references/08-redraw-and-delivery-audit.md`，只报告可见问题、未知项和所需材料。对于 C/D 级截图，不渲染、不导出、不执行字体门禁，也不声称核验了原始数据。
2. `选图咨询`：根据数据结构、观察目的和论文语境推荐图型与备选图；不渲染代表图，不执行字体加载、DPI 或导出门禁。
3. `实际绘图或重绘`：生成、修改、导出图表或 Notebook；必须执行“项目论文绘图强制默认标准”，并读取 `references/08-redraw-and-delivery-audit.md`。
4. `方法逻辑图`：用户要问题分析框架、算法步骤、模型架构、数据流或指标层级图；读取 `references/06-flowchart-and-methodology.md`，不得把文本中的先后关系擅自扩展为因果结论。
5. `论文补图规划`：仅在用户明确要求检查论文哪些位置适合补图时读取 `references/07-figure-gap-review.md`；先交付候选清单和证据映射，不自动生成、插入、编号或改写论文正文。
6. `统计图路由`：用户已有统计结果，或明确要求判断 ROC/PR、森林图、生存曲线、火山图等是否适用时读取 `references/09-statistical-plot-routing.md`；没有数据和分析依据时不生成统计标注或结论。

### 证据等级

- `A`：原始数据及可复现实验、模型或绘图过程。可核对数值、变换和完整性。
- `B`：可编辑矢量图或结构化表格。可核对大多数文本、对象和部分数值，但仍应说明无法确认的计算过程。
- `C`：清晰栅格图或截图。可审查可见元素和明显表达问题，不能宣称已逐点核验原始数值。
- `D`：低清、裁剪严重或缺少图例、坐标的信息。先报告缺失和不确定性；需要精确重绘时请求更完整材料。

只有用户明确授权且证据充分时，才能纠正疑似错误的数值、单位、统计标记、轴尺度、类别对应关系或模型结论。字体缺失、文字裁剪、图例遮挡和版式冲突属于表达层问题，可以按重绘授权修复；纠错版本必须另存并列明差异。

## 什么时候优先用本 skill
- 用户不是要你直接写代码，而是先判断“什么数据该画什么图”。
- 用户在数模语境里问“连续数据画啥图”“这个变量组合适合什么图”“时间序列图怎么选”“地图数据用啥图最稳”等问题。
- 用户已经知道自己有数据，但还不知道应优先展示趋势、分布、关系、构成、层级还是流向。
- 用户在论文、答卷、PPT 或结果展示阶段，需要选一种评委更容易读懂的图。

## 第一优先动作
当本 skill 被触发时，按以下顺序执行：

1. 判断任务模式与证据等级；审图咨询先报告可见问题、未知项和所需材料，只有实际绘图或重绘才执行本文件的字体、渲染、导出和审计门禁。
2. 优先调用 `math-modeling-brainstorm`，把数据问题拆成“数据家族、观测单位、变量数量、分组数量、成对关系、顺序性、观察目的”；若能力不可用，按相同维度在本 skill 内完成，并如实说明回退。
3. 若用户已经明确指定“中文宋体、英文数字 Times New Roman”等排版口径，先锁定为硬规则，后续不要被通用 fallback 策略覆盖。
4. 判断数据家族：数值型、类别型、数值型&类别型、地图、网络图、时间序列，或方法逻辑图。
5. 判断观测结构：单个变量分布、成对观测关系、独立样本组、类别汇总值、类别下的重复样本、邻接或流量关系。
6. 判断是否有序：时间顺序、空间顺序、阶段顺序、等级顺序，或无天然顺序。
7. 判断观察目的：分布、比较、关系、构成、层级、流向、空间位置、网络关系、流程或收敛。
8. 先排除不满足上述条件的图型，再在剩余候选中按对应 reference 的原有顺序给首选和一至两个备选。

## 默认规则
- 同一分支内，第一张图默认是首选图；若用户没有额外偏好，优先推荐第一项。
- 默认首选只在它满足数据结构、观测单位、观察目的、样本量与证据条件时生效；否则说明原因并选择该分支中第一个适用候选。
- 若用户只说“我有一组连续数据”，先判断它是看分布、看趋势还是看关系，不要直接给图名。
- 观察目的主要用于先选对分支，不用于打乱该分支原本“从上到下”的排序。
- 若用户明确说“我要看趋势”，再优先从该分支内部的顺序敏感图中选。
- 若用户明确说“我要看分布”，再优先从该分支内部的分布图中选。
- 若用户明确说“我要看关系、构成、层级或流向”，再优先从对应分支内部选图。
- 若图型已经非常明确，不要越界展开成整套 matplotlib / echarts 教程。
- 若场景是中文论文插图，默认把“中文正常显示”放在“配色好不好看”之前处理；只要中文还是方块字，这张图就视为不可交付。
- 若明确使用 matplotlib 出中文论文图，默认遵守：中文元素用 `SimSun`，英文与数字元素用 `Times New Roman`。
- 若标签中同时含中文和数字，整条标签统一使用 `SimSun`；只有纯英文和纯数字标签使用 `Times New Roman`。
- 同一论文中相同的模型、方案、区域、情景或数据角色应保持名称、顺序、颜色、线型和标记的一致映射；新增对象应扩展映射，不能因默认颜色循环而改变旧对象含义。
- 色彩、线型、标记、直接标注、分面和纹理都是表达编码。颜色不能作为区分系列的唯一方式；但不必为了满足形式要求给每一张单系列图强加额外编码。
- 平滑、回归、聚类、标准化、置信带、预测带和统计检验属于分析或模型表达，不是默认美化操作。未提供结果或未获授权计算时，只能提出建议，不能把它们加进图中。
- 若场景是“数模论文成图”，默认再遵守两条版式硬规则：
  - 图内部不要再写“图1”“图2”“能量图”“AAS对比图”等标题性文字；图号和图名应放在文件名、图注或正文引用里。
  - 图例要么放在带白色底框的左上角或右上角，要么整体放在图的最下方；不要把图例无底色悬浮在数据主体上。
- 若用户明确是在做“论文插图”而不是普通分析图，优先推荐：
  - 无图内标题的图面；
  - 不遮挡主体的图例布局；
  - 简洁、稳定、易于打印的版式。

## 科学绘图风格路由（配色与绘图实现前置）

- 本文件“项目论文绘图强制默认标准”是当前项目的表达层硬规则。下游 `scientific-visualization` 或 `nature-figure` 可在不与这些硬规则冲突的范围内，根据数据语义确定具体色板、连续或发散色图、可访问性和实现细节。
- 先检查下游能力是否可用。选图咨询和审图咨询可在下游能力不可用时继续完成，但不得声称已调用或通过下游技能审计。实际科学绘图优先调用可用的下游技能；二者均不可用时，可只按本文件的项目强制默认标准完成交付，并在交付说明中记录“未执行下游科学绘图审计”。若用户要求本文件未定义的外部期刊模板或出版规范，则暂停并请求该模板或可用下游能力。
- 下游技能的选择顺序固定为：
  1. 用户明确指定 Nature/Science/Cell、Nature-family 模板、投稿版式或多面板稿件图时，调用 `nature-figure`。
  2. 用户明确指定 `scientific-visualization` 时，调用 `scientific-visualization`。
  3. 没有期刊或模板硬性要求时，默认调用 `scientific-visualization`，并采用它给出的配色、绘图风格、可访问性和导出审计要求。
   4. 若首选技能运行环境不可用，应改调用另一个技能；若两个技能都不可用，按本项目强制默认标准继续仅限于本项目标准的实际绘图，并记录缺少下游审计。无序离散系列使用 Okabe--Ito；连续数据默认使用 `cividis`；仅在存在有科学意义的中点且显式记录中点与归一化方式时，使用以中点为中心的 `RdBu_r` 发散色图。不得因此宣称符合 Nature、Science 或未调用技能的规范。
- 每次实际绘图交付都要在代码或结果说明中记录：是否调用下游技能及其名称、色板名称及颜色顺序、字体口径、单位与轴范围依据、输出格式/尺寸/DPI，以及字体缺失、图例遮挡、裁剪、灰度可辨识度和元数据检查结果。
- 未调用下游技能时，不得声称采用某期刊或下游技能的风格；图型分流仍由本技能负责，配色和绘图实现优先交给可用的下游科学绘图技能。
- 使用 `scientific-visualization` 时，由它按数据语义、可访问性和当前版本的规范选择色板，并在代码或结果说明中记录实际使用的 palette name、颜色顺序及选择依据；如数据语义要求连续或发散色图，同样必须写明理由。若下游能力不可用，则采用本节第 4 条定义的项目回退，并记录这是项目回退而不是外部风格审计。
- 默认科学绘图风格为：白色不透明背景、简洁坐标轴、去除右/上边框、适度线宽、`layout="constrained"`、单位写入坐标轴、图例带白底且不遮挡数据、论文图不在图内写“图1/图2”标题；精确版面尺寸时不要使用 `bbox_inches="tight"`。
- 颜色必须匹配数据语义：无序类别用定性色板，有序量用感知均匀的连续色图，有科学中点才用发散色图；禁止把 rainbow/jet 当作默认顺序色图。
- 颜色不能是唯一编码。至少补充一种线型、标记、直接标注、分面或纹理；输出不确定性时必须写明区间类型、样本量和重复单位，不能机械添加“误差棒”。
- 交付前必须检查实际渲染结果：中文字体缺失、`Glyph missing`、图例遮挡、裁剪、轴范围夸大、灰度下系列难以区分，任一项出现都要修正后再交付。若已调用 `scientific-visualization`，按其提供的 `palette_audit.py` 和图像元数据检查；否则执行本文件规定的渲染、灰度、字体和元数据检查，并记录下游审计未执行。始终保留原始数据、变换记录和输出来源。

## 重绘任务的专用交付规则

- 当用户要求“重绘”“重新画”“按某个科学绘图技能改图”时，先把任务判定为“保留数据、替换表达层”，不得为了视觉效果修改原始观测、模型输出、异常值保留策略或计算口径。
- 重绘前按证据等级记录可核查范围：系列和类别数量、可见点位或汇总值、单位、轴范围、轴尺度、图例、统计标记、流程节点与连边。材料不足时，应明确“未验证”，不得把视觉相似写成数值完全一致。
- 原始图、原始数据和原输出目录不得被覆盖；默认将重绘结果写入独立目录（如 `_scientific` 或 `_nature`），并在图旁保存来源与变换清单。
- 没有期刊、模板或投稿尺寸硬性要求时，优先调用可用的 `scientific-visualization`；只有明确的 Nature-family 版式要求时才切换到 `nature-figure`。若二者不可用，则仅采用本 skill 的项目强制默认标准与项目回退色板，并在交付说明中记录未执行下游审计；遇到本标准未覆盖的外部模板要求时暂停并请求材料或能力。
- 每组重绘图至少应交付一种可编辑矢量格式（SVG 或 PDF）和一种无损栅格格式（PNG 或 TIFF）；精确版面尺寸时显式写入尺寸与 DPI，不用 `bbox_inches="tight"` 改变页面大小。
- 重绘交付说明必须列出：数据源、变换步骤、色板及颜色顺序、字体文件、单位与轴范围依据、输出尺寸/DPI，以及已调用下游技能的 `palette_audit.py`、图像元数据、实际渲染和灰度可辨识度检查结果；下游未调用时必须明确该项未执行。
- 重绘交付说明还应区分：图型及表达目的、发现的问题、拟改内容、实际修改、保真核查、输出文件和未解决事项。不能把“建议改图型”写成已经完成的保真重绘。
- 对时间序列、参数扫描等有序数据，优先使用折线/散点和允许区间带；颜色只作为辅助编码，必须同时使用线型、标记、参考线、直接标注或分面表达关键差异。

## 不要做什么
- 不要在图型尚未判断清楚时直接输出完整绘图代码。
- 不要把这个 skill 用成“任何可视化问题都能回答”的绘图库手册。
- 不要为了花哨而优先推荐评委不熟悉、阅读门槛高的图。
- 不要因用户仅咨询选图就渲染图表、检查字体、修改文件或启动完整导出流程。
- 不要在未获得明确授权时扫描整篇论文、自动生成补图、插入图片、修改图号、更新正文引用或改写结论。
- 不要把低清截图中的视觉估读结果描述成已核验的原始数值、统计结果或模型输出。
- 不要在没有数据、方法和授权的情况下添加误差棒、显著性星号、p 值、R²、回归线、聚类、置信带或预测带。
- 不要臆测当前图片里看不清的叶子节点名称。
- 不要把在线网站、工具入口塞进主流程；v1 不负责工具导航。
- 不要默认在图内部加“图1/图2/图3”式标题。
- 不要把图例直接压在柱体、折线、热力图等数据主体上，尤其不要无底色漂浮。

## 常见错误
- 只按数据类型选图，不看观察目的，导致图能画出来但表达错重点。
- 把有序数据当无序数据画柱状图，或者把无序数据硬画成折线图。
- 明明是“一个类别变量对应多组数值样本”，却误选成饼图或圆环图。
- 多变量关系一上来就用复杂图，而不是先给一个评委最容易读懂的默认图。
- 把“选图”技能直接当成“出代码”技能使用。
- 把同一论文中同一对象在不同图中换成不同的颜色、线型、名称或排序，导致读者误以为是不同对象。
- 仅因章节字数较多、图文比偏高或页面留白，就断定论文必须补图。
