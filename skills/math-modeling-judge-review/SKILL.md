## Model Escalation Rule

**When the review task is complex enough to require parallel reasoning across paper, PPT, result tables, screenshots, code evidence, or multiple competing judge hypotheses, you MUST use the most capable frontier model currently available with its highest supported reasoning effort.**

**Current required choice:** `gpt-5.4` with `xhigh`

**Do not downshift** to a cheaper or faster model for these cases. If a newer top-tier model replaces `gpt-5.4`, use that newer frontier model with its highest available reasoning effort instead.

# 数学建模：评委审核（CUMCM 口径）

## 概述
- 本技能用于赛前“评委视角”审查，不用于替代建模求解。
- 核心目标是提前识别会影响奖项层级的风险项，并给出最小可执行修正动作。
- 固定输出四块：`高风险扣分点`、`中风险扣分点`、`做得好的点`、`结果核查`。
- 默认不打总分；只有用户明确要求时才扩展为量化评分。

## 什么时候优先用本 skill
- 用户要你“按评委口径审”数模论文、答卷、PPT 或结果材料。
- 用户要你“查丢分点”“做冲奖前检查”“做赛前把关”。
- 用户希望把结果表、论文、PPT、截图、代码摘要放在一起做一致性复核。
- 用户不是要你重新建模求解，而是要你判风险、判证据、判说服力。

## 第一优先动作
当本 skill 被触发时，始终先做以下四件事：

1. 判断当前任务是不是“评委审查”而不是“建模求解”。
2. 明确本轮审查对象：论文、PPT、结果表、截图、代码摘要，还是全量材料。
3. 先检查材料完整度与证据充足度。
4. 明确输出将固定为：高风险扣分点、中风险扣分点、做得好的点、结果核查。

## 输入要求
支持以下任意组合输入：
- 官方讲评 PPT 截图
- 优秀论文（对标样本）
- 你的论文/答卷
- 结果表（价格、补货量、收益、误差等）
- 关键代码摘要（可选）

若输入不足以支撑结论，必须先输出“证据不足项清单”，再继续审查。

## 审核流程（一步一问）
### 步骤1：目标对齐（调用 `math-modeling-brainstorm`）
- 先调用该 skill，对齐任务边界、输入材料完整度与审核目标。
- 明确你现在是“查扣分风险”还是“做赛前冲奖优化”。
- 明确本轮审核对象：方法、结果、写作、合规，还是全量。

### 步骤2：材料完整度检查
- 检查是否具备“方法说明 + 结果表 + 结论文本”。
- 缺任一关键模块时，先给缺失影响和补充优先级。
- 若包含图片材料，必须建立“逐图审阅清单”（如：图1、图2、图3...），并在后续输出中逐图对应证据；禁止合并成笼统结论。

### 步骤3：载入官方基线并定位审查维度
- 读取 `references/cumcm-judging-baseline.md`。
- 将当前材料映射到四个主标准与合规维度。

### 步骤4：高风险筛查（先判红线）
- 先查可能导致降奖或取消评奖资格的红线项。
- 红线样例：匿名泄露、严重相似度风险、AI 披露违规、结果与支撑材料冲突。

### 步骤5：中风险筛查（影响说服力）
- 重点查逻辑链断裂、假设未经验证、参数无依据、图表与文字不一致、鲁棒性不足。
- 对随机优化算法，强制追加“稳健性双证据”检查：
  - 是否有多种子证据文件（如 `ga_seed_summary_*.csv`、`ga_summary_*.json`）；
  - 是否有参数敏感性小实验表（至少含参数、扰动值、目标变化、可行性）。
- 若用户提供了官方讲评 PPT，必须追加四项专项核查：
  - 数据整合/异常处理/可视化解释是否到位；
  - 统计方法是否“讲原理+讲边界”，而非机械套用；
  - 是否只做预测拟合而脱离题目背景与数理逻辑；
  - 优化模型与算法求解是否一致，且算法描述是否足够复核。

### 步骤6：做得好点提取
- 只记录“有证据支撑且可复核”的亮点，避免空泛夸奖。

### 步骤7：结果核查（强制）
- 按“结果核查专章”执行，不重复展开规则。

### 步骤8：形成最终审查输出
- 按固定模板输出。
- 每条问题给出“最小修正动作”，优先可在当前版本快速落地。

### 步骤9：复审（调用 `systematic-debugging`）
- 调用该 skill，对风险分级、证据链完整性、题意对齐和代码准确性做复审。
- 复审后，在结论中显式说明已执行复审，并列出“通过项/需修正项”。

## 固定输出模板
- 高风险扣分点（优先）
- 中风险扣分点
- 做得好的点
- 结果核查
- 证据来源与检索日期
- 最小修正动作清单

编号规则（强制）：
- 每个主段内部独立编号：`1, 2, 3...`
- 进入下一主段后必须重新从 `1` 开始
- 禁止使用全篇单一连续编号

结构示例（强制）：

### 高风险扣分点（优先）
1. ...
2. ...

### 中风险扣分点
1. ...
2. ...

### 做得好的点
1. ...
2. ...

### 结果核查
1. ...
2. ...

每条风险项必须包含以下字段：
- 优先级（P0/P1/P2）
- 依据来源
- 对应问题
- 风险级别
- 影响
- 修正建议

## 风险分级定义
### P0/P1/P2 缺口分级
审查时按影响交卷程度分级：

- P0：会导致结论不可信、无法交卷或严重违题的问题。
- P1：会明显影响奖项竞争力的问题。
- P2：表达、格式、补充说明类问题。

输出表：

| 优先级 | 缺口 | 影响 | 修补动作 | 负责 skill |
|---|---|---|---|---|

与现有风险分级对齐：

- `高风险扣分点` 优先标为 P0 或 P1。
- `中风险扣分点` 优先标为 P1 或 P2。
- `做得好的点` 不做 P 级缺口分级。

### 高风险扣分点（优先）
- 定义：可能直接导致奖项层级明显下降，或触发取消评奖资格风险。
- 输出要求：必须给出明确证据位置和立即修正建议。

### 中风险扣分点
- 定义：不一定致命，但会显著削弱可信度与竞争力。
- 输出要求：给出影响范围与修复优先级。

### 做得好的点
- 定义：对冲奖有正向作用且可被证据复核的内容。
- 输出要求：点出其“为什么有效”和“如何保留”。

## 结果核查专章（强制）
必须单独输出以下五类检查：
1. 口径一致性检查。
2. 数值逻辑一致性检查。
3. 结论-证据匹配检查。
4. 异常值与波动解释检查。
5. 稳健性双证据检查（随机性文件 + 参数敏感性表）。

如果任一类证据不足，明确标注“结果证据不足”，并提升为高风险或中风险。

## 强制依赖与硬规则
1. **第一动作必须调用** `math-modeling-brainstorm`，先对齐任务边界、输入材料完整度与审核目标。
2. 默认使用本地固化官方基线：`references/cumcm-judging-baseline.md`，不强制每次联网。
3. 触发联网更新仅限三类：
   - 用户明确要求“最新/当届/今年/新规”。
   - 用户给出的规则与本地基线发生冲突。
   - 本地基线版本超过一年未更新。
4. 每条结论必须写证据链：`依据来源 -> 对应问题 -> 风险级别 -> 影响 -> 修正建议`。
5. 审核不得只评方法不看结果，必须按“结果核查专章”单列结果核查。
6. **审核过程中必须调用** `systematic-debugging` skill 对风险判断和证据链进行复审，并同时审查思路或代码是否严格符合题目要求、代码实现是否准确。
7. 审核遵循“方法开放、结果严格”：不因方案与模板不同直接扣分，先看是否满足官方评审主标准。
8. 调用 `math-modeling-brainstorm` 与 `systematic-debugging` 后，必须在输出中显式写明“已调用该 skill”。
9. 输出必须符合固定输出模板与分段编号规则。
10. 对随机优化算法（GA/PSO/SA/DE）类解法，必须单列“稳健性双证据”审查：
    - 随机性稳健性：多种子文件与统计（均值/标准差/CV）；
    - 参数稳健性：关键参数（如 BAR/LAMBDA）±10% 小实验结果表。
    若只提供其中一项，默认至少判中风险。
11. 当用户提供图片（优秀论文截图、评委PPT截图、结果截图等）时，**必须逐张完整审阅**：
    - 无论图片数量多少，不得跳过任何一张；
    - 不得省略图片中的关键文字、图表、公式、注释、页脚信息；
    - 每张图片都要提取“可核查证据点”，并映射到风险项或亮点；
    - 若图片清晰度不足导致无法识别，必须单列“证据不足（图像不可辨）”，不得直接下结论。

## 官方评审主标准（固化口径）
- 假设合理性
- 建模创造性
- 结果正确性
- 文字表述清晰程度

注：四项来自 CUMCM 官方章程口径，详细条款和扩展解释见 `references/cumcm-judging-baseline.md`。

## 官方讲评补充扣分画像（来自官方讲评 PPT）
当用户提供官方讲评截图时，必须额外按以下四类问题做专项筛查，并在输出中单列其证据链与修正动作：

1. 数据分析基础能力不足：
   - 典型表现：数据整合薄弱、异常值处理缺失、可视化仅展示不解释。
   - 审查动作：检查是否明确写出数据口径统一、异常处理规则、图表结论对应文字。

2. 统计方法“机械使用”：
   - 典型表现：只套用统计方法，不解释原理、适用条件与失效边界。
   - 审查动作：检查每个统计方法是否写明“为何可用、何时失效、参数如何设定”。

3. 脱离问题背景与数理逻辑：
   - 典型表现：只做预测/拟合/回归，不回答题目业务目标与约束关系。
   - 审查动作：检查“题意 -> 假设 -> 公式 -> 结论”是否闭环；若仅停留在拟合结果，至少判中风险，证据充分时可判高风险。

4. 优化建模与求解脱节：
   - 典型表现：模型写了一套，算法实现另一套；或算法描述过少，无法复核。
   - 审查动作：强制核对“目标函数/约束/变量”与代码实现或结果表字段的一致性，并检查算法参数、终止条件、可行性校验是否完整披露。

## 通用高分经验（所有数模题默认检查）
本节为默认检查项，不依赖是否提供图片，适用于问题一/二/三及其他数模题。

### 1. 口径与结论
1. 先锁主提交口径，再讲机制与算法；若有对比方案，主方案必须唯一。
2. 结论必须分情形写，禁止笼统写“整体最优”“整体稳健”。
3. 相关与因果必须分开；相关结论不得直接写成因果结论。
4. 计算口径与展示口径要分离，避免符号和指标误读。
5. 结论要答辩友好，最好按“证据 -> 推理 -> 结论 -> 风险/收益”表达。

### 2. 建模与题意闭环
1. 题意链条必须完整：`题意 -> 假设 -> 变量 -> 目标 -> 约束 -> 求解 -> 结果 -> 结论` 不能断。
2. 递进题必须写清“沿用什么、只新增什么”，并做同口径对比。
3. 关键机制必须入模，不能只停留在文字描述或场景分析。
4. 关键不确定性要公式化，不能只写概念说明。
5. 先给集合、索引、维度总表，再写公式，降低阅读门槛。
6. 新增机制最好同时给“三件套”证据：公式定义 + 输出字段/代码开关 + 结果对比。

### 3. 求解与方法选择
1. 方法选择要可辩护：说明为何不用精确法/解析法，并给替代基线或小规模对照。
2. 建议采用“基线 + 改进”结构，结果按同口径比较。
3. 至少说明复杂度来源，如变量规模、约束规模或非线性来源。
4. 文中写过的回退、阈值、后处理规则，必须能在输出文件中核查到。

### 4. 结果、稳健性与复现
1. 结果核查至少做四件套：口径一致、数值自洽、结论匹配证据、异常波动解释。
2. 同一结论至少给“数据表 + 图形”两类证据，且数值一致。
3. 可行性必须可复核，至少给 `violations_count`、`feasible_ratio` 或同级统计。
4. 稳健性至少分两层检查：算法随机性（多种子）和参数/业务扰动稳健性。
5. 关键参数、随机种子、文件路径要落盘，保证他人可复算。
6. 预处理规则必须明文化，写清保留、截尾、剔除规则及前后对比。
7. 复现交付优先 `.py` 主链，`.ipynb` 主要用于展示。
8. 正文结论要能映射到提交表字段，保证提交链路可追溯。

### 5. 图表与表达
1. 图表不能只报结果，还要解释结构、机制和可执行性。
2. 每问至少应有一张“解释型图表”，正文结论能回指到图表证据。
3. 论文最低配四图：整题流程图、资源/载荷分布图、频率/热度图、执行/调度图。
4. 若只有结果图、路径图、收敛图，没有解释型图表，默认至少判中风险。
5. 除结果图外，建议至少补一张机制传导图或执行示意图。

### 6. 题型专项项（按需检查）
1. 涉及时间序列或周期问题时，时间结构必须显式入模，并给时间分解图或周期指标表。
2. 涉及预测时，必须给 `R2/MAE/RMSE` 或同级质量指标表。
3. 涉及候选集筛选时，必须写清“原始候选 -> 筛选规则 -> 最终候选”的链路，并说明对目标值的影响。

## 输出风格要求
- 全中文。
- 面向小白解释：每条关键结论都回答三件事：
  - 为什么这是问题/亮点。
  - 你应如何修改/保留。
  - 不改会造成什么后果。
- 禁止仅给“主观判断句”，必须附证据链。

## 提交前格式自检（强制）
1. 四个主段是否齐全：`高风险扣分点`、`中风险扣分点`、`做得好的点`、`结果核查`。
2. 每个主段的编号是否都从 `1` 开始。
3. 是否出现跨段连续编号（若出现，必须重写后再输出）。
4. 每条风险项是否完整包含：`依据来源 -> 对应问题 -> 风险级别 -> 影响 -> 修正建议`。

## Common Mistakes
- 把评委审查看成建模求解，直接去给新模型或新代码。
- 只评方法，不查结果。
- 只给主观评价，不给证据链。
- 审查图片时只看一部分，没有逐张建立证据。
- 高风险和中风险混写，没有固定输出结构。
- 只说“这里不好”，但不给最小修正动作。
- 明明是审查任务，却不先调用 `math-modeling-brainstorm` 做边界对齐。
