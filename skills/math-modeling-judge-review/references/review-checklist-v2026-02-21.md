# 评委审核执行清单（v2026-02-21）

## 0. 审核前动作（强制）
1. 调用 `math-modeling-brainstorm` 对齐本轮目标。
2. 确认输入材料完整度：方法、结果表、结论文本是否齐全。
3. 载入 `cumcm-judging-baseline.md` 并锁定评审口径。

## 1. 高风险快速筛查（优先）
- [ ] 是否存在匿名泄露。
- [ ] 是否存在高相似风险而无合规处理。
- [ ] 是否存在 AI 披露不完整。
- [ ] 是否出现“结果与表格/图形冲突”。
- [ ] 是否出现“关键结论无法被证据复核”。

若任一项为“是”，直接进入 `高风险扣分点（优先）`。

## 2. 中风险筛查
- [ ] 假设是否有依据且与数据匹配。
- [ ] 参数设定是否解释充分。
- [ ] 方法链是否完整（建模-求解-验证）。
- [ ] 图表是否清晰且和正文一致。
- [ ] 鲁棒性/敏感性是否有最小验证。

## 3. 做得好的点采集
- [ ] 创新点是否真实可复核（非口号化）。
- [ ] 结果呈现是否清晰、结构化、可对比。
- [ ] 结论是否紧扣题意并可落地。
- [ ] 代码/流程是否可复现（至少给出关键参数与路径）。

## 4. 结果核查专用清单（强制单列）
### 4.1 口径一致性
- [ ] 单位一致
- [ ] 时间粒度一致
- [ ] 统计口径一致（含退货/折扣等）

### 4.2 数值逻辑一致性
- [ ] 指标计算可复核
- [ ] 跨天变化可解释
- [ ] 异常值有说明或处理

### 4.3 结论匹配
- [ ] 每条核心结论都有结果支撑
- [ ] 结果与结论不存在冲突

### 4.4 证据完整性
- [ ] 关键表格/图形引用位置明确
- [ ] 关键结论可追溯到具体证据

## 6. 结论风格要求
- 面向小白，结论必须解释：为什么、怎么改、不改后果。
- 禁止空泛评价，禁止无证据判断。
- 默认不打分；仅当用户明确要求时附加评分。
