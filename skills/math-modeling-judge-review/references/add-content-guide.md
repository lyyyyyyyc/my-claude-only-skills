# 为 `math-modeling-judge-review` 新增内容的维护指南

## 用途
这份文档是给 Codex 在后续继续扩展 `math-modeling-judge-review` 时使用的维护规程。以后如果需要继续往这个 skill 里新增审查规则、补触发词、扩展风险判定、补结果核查要求或修正常见跑偏行为，优先先读这份文档，再决定改哪里、怎么改。

## 什么时候应该新增内容
以下情况适合继续新增到这个 skill：
- 出现新的高频评委审查口语触发词，导致当前 `description` 或 `when_to_use` 覆盖不足。
- 出现新的审查维度，且适用于多类数模材料，而不是某一个具体题目。
- 需要补新的高风险规则、中风险规则或结果核查要求。
- 需要补新的合规检查要求、证据链要求或截图审查要求。
- 发现新的常见跑偏错误，值得加入 `Common Mistakes`。

以下情况通常不应该直接加到这个 skill：
- 某个题目的临时要求。
- 某个模型的具体求解细节、参数技巧或代码实现。
- 只适用于单次会话的修订意见。
- 更适合放进 `math-modeling-brainstorm` 或其他专门数模 skill 的内容。

## 新内容应该加到哪里
新增内容时，先判断它属于哪一类，再放到对应区块：

| 新增内容类型 | 应放位置 |
|---|---|
| 触发词、用户口语表达、何时应该调用本 skill | frontmatter 的 `description` / `when_to_use` |
| 审查第一步该做什么 | `什么时候优先用本 skill` / `第一优先动作` |
| 材料完整度、审查步骤变化 | `输入要求` / `审核流程` |
| 官方标准、讲评口径、经验扩展 | `官方评审主标准` / `官方讲评补充扣分画像` / `通用高分经验` |
| 输出结构、编号规则、核查字段 | `固定输出模板` / `提交前格式自检` |
| 结果复核类新增要求 | `结果核查专章` |
| 常见跑偏与误用 | `Common Mistakes` |
| 低频、长篇、维护导向说明 | `references/` |

## 新增内容的判断流程
以后新增内容时，按下面顺序判断：

1. 先判断这是“触发优化”还是“审查知识扩展”。
2. 再判断它是“通用规则”还是“某类任务专用”。
3. 如果是通用规则，优先考虑放入主 `SKILL.md` 的现有区块。
4. 如果只是低频、长说明或维护说明，优先放进 `references/`，主文只留入口。
5. 如果这条内容会改变触发边界，必须同步检查 `description` 和 `when_to_use`。
6. 如果它更适合其他数模 skill，就不要硬塞进 `math-modeling-judge-review`。

## 写法规范
根据 `skill-creator` 和 `writing-skills`，新增内容时遵守以下写法：
- 解释“为什么”，不要只堆“必须”。
- 新规则尽量短，优先补到已有区块，不轻易新开大区块。
- 对高风险规则要写清适用条件，不要扩大到所有任务。
- 不写叙事式历史，不写一次性案例总结。
- 能归入已有结构就不要重复写一遍。
- 新增内容要优先减少跑偏，而不是单纯增加篇幅。
- 如果内容很长、很低频、很维护导向，优先放 `references/`，不要把主 `SKILL.md` 的前半段写重。

## 修改前检查清单
新增前先检查：
- 这条内容是否真的是高频、可复用规则。
- 是否和已有区块重复。
- 是否本来属于别的数模 skill。
- 是否会改变触发边界。
- 是否需要补 `Common Mistakes` 或 `触发示例`。

## 修改后检查清单
新增后再检查：
- 主 skill 的结构顺序是否仍然稳定，前半段是否仍然以“进入审查模式”为主。
- frontmatter 是否需要同步更新。
- 新内容是否放在了正确层级。
- 是否引入了新的重复表述。
- 是否需要补 2–3 条回归测试提示词，验证新增内容真的有用。

## 常见错误
- 把评委审查 skill 写成建模求解 skill。
- 把具体模型知识直接塞进审查 skill。
- 把低频超长规则放进主文前半段。
- 只加硬规则，不写触发条件和适用范围。
- 增加内容后不检查 `description` / `when_to_use`。
- 把一次性任务要求写成永久规则。

## 维护时的默认原则
- 能少改就少改，优先最小改动。
- 先补触发与行为入口，再补审查细则。
- 先减少跑偏，再增加覆盖面。
- 如果新增内容会让主文变重，优先把长说明放进 `references/`。
