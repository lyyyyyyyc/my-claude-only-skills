# 数学建模：数据预处理与评审复核

## 概述
- 第一动作是形成或复用本任务的目标、范围和约束摘要；用户或上游已提供的澄清结果可直接复用，不得仅为满足顺序而重复转交。
- 本技能用于数据预处理主流程，并在流程内嵌评委关注维度做质量复核。
- 本技能同时负责探索性统计与建模前特征工程，但不负责选图、配色、字体、版式或完整绘图代码。
- 当统计结论需要图形证据时，本技能只生成结构化绘图请求并接收可得的图形证据；不直接调用或保证任何绘图 skill 能消费该请求。实际绘图由用户或已确认的编排器另行交接。
- 目标不是把数据“洗得最干净”，而是在题目范围和时间预算内交付足以支持模型与结论的可信数据版本；基础质量、防泄漏和证据链不可省略，低收益的可选比较按需进行。
- 原始数据、处理后数据与建模输入必须可区分。不得覆盖唯一原始副本；数据问题与转换过程引入的问题必须分别记录。
- 目标是让预处理结果不仅可运行，还能经得住“变量语义、样本层级、方法条件、统计意义、证据链完整性”的审查。
- 默认输出面向小白：每一步都说明为什么做、怎么做、做错会导致什么问题。

## 什么时候优先用本 skill
- 用户已经明确处在数模数据处理阶段，先要把原始数据整理干净，再进入建模。
- 用户在问“异常值怎么处理”“缺失值怎么补”“口径怎么统一”“时间效应怎么处理”“相关分析前提是否满足”等问题。
- 用户在问“外部数据能不能用”“日期混着格式怎么转”“列名有空格”“重复记录怎么合并”“merge 后行数翻倍”“数据是否泄漏”等问题。
- 用户不只是要一个处理建议，而是要一套能复核、能解释、能交付的预处理结果。
- 用户希望预处理结束后，顺带按评委会关心的统计意义和证据链完整性做质量复核。

## 第一优先动作
当本 skill 被触发时，先形成 `task_manifest`；已有题面、数据字典、上游技能结果或用户说明应优先复用，不重复提问。

1. 判断当前问题是“概念建议”“执行预处理”“原始数据质量审计”还是“复核已有预处理结果”；概念建议进入 `advice_only`，不读取或写入文件、不补造日志，只说明适用条件、风险和真正执行所需的数据。若预处理决策需要依赖模型分数、验证指标、模型性能/校准阈值、超参数选择或未见表现声明，建立 `model_contract`；业务阈值、IQR 或 3σ 等预处理筛查阈值不因此要求 `model_contract`。否则标记为 `not_required`。只有目标、关键口径、输入可访问性或不可逆处置无法安全判断时，补问一个关键问题。
2. 明确或暂定数据范围、时间范围、分析单位、关键字段、目标变量、泛化对象、信息可用时点和约束来源，并标注为“已确认 / 合理假设 / 待核验”。
3. 发现输入：登记可访问文件或数据表、格式、工作表/页码/表头、编码或分隔符、读取限制、敏感字段和原始副本位置；用户请求实际执行而未提供原始数据时，先只追问一个已确认的 `input_root` 或权威文件/表清单。若用户明确表示输入不可得、不可访问或只提供现有产物，则有产物时切换到 `review_only`；没有可复核产物时交付 `advice_only` 的输入阻塞说明，不重复追问同一信息。
4. 判断题目附件是否足够；需要外部材料时，明确其是模型输入、参数/阈值依据、假设论证、独立验证还是结果讨论。
5. 对 `advice_only`、`raw_audit`、`review_only` 可约定仅交付内联报告；实际改变数据的 `preprocessing`、`predictive_modeling`、`optimization` 必须在输入确认后约定可写的输出根目录。原始副本只读保留，输出路径、版本和可复现输入必须登记。
6. 列出必做项、条件触发项、可延后项与最低可用交付，再进入主流程。完整字段和目录约定见 `references/execution-contract-and-applicability.md`。

## 强制依赖与硬规则
1. 必须先形成或复用 `task_manifest`，对齐问题目标、范围、输入、输出和约束边界。若当前会话已有可用的上游澄清结果，直接复用；本 skill 不在执行过程中转交 `math-modeling-brainstorm`，避免其交互流程阻塞当前预处理。
2. 任何不确定信息都必须显式标注为“已确认 / 合理假设 / 待核验”；只有缺少该信息会阻止安全处理时，才补问一个关键问题，不得把推测写成事实。
3. 采用一步一问节奏：每次只问一个关键问题；需要并列收集信息时，可用一份结构化 intake 表作为同一个问题，并允许用户对未知项标为“待核验”，不得把它拆成无止境追问。多选题优先使用数字选项（1/2/3）。用户已提供的信息不得重复询问。
4. 流程固定为“先做输入安全检查与语义核验，再执行预处理，最后做评委质量维度检查”；不要求必须量化打分。字段语义、样本层级、结构、时间可用性、来源权限和不可逆动作边界必须在相应转换前核验。
5. 输出必须包含证据链：`数据来源 -> 处理规则 -> 验证结果 -> 结论 -> 风险与改进`。
6. 当后续分析或建模要使用“对数正态分布”假设时，必须先确认 `distribution_test_contract`，再执行“对数正态适配检查 + KS 检验表”；不允许只凭 QQ 图下结论。
7. 异常值处理必须闭环：IQR/3σ/业务阈值仅用于“筛查”，必须追加“处置规则（保留/截尾/剔除/标记）+ 处理前后对比表”；禁止只报“筛出异常”而不给处理策略与影响评估。
8. 缺失值处理必须闭环：先识别 `null/空白/异常编码`，再判断“删字段、删样本、简单补值、插值补齐”哪种最合适；禁止不区分字段类型和缺失比例就直接统一补齐。
9. 当任务需要估计对未见实体、未来时段或独立样本的表现时，数据划分必须先于任何依赖样本统计量的建模操作。纯描述统计、数据核对、复核已有产物或不作外部性能声明的任务可标记“数据划分不适用”，不得凭空创建测试集；需要外部性能评估时，测试集只能在全部规则、参数和算法超参数确定后用于最终评估，禁止用测试集调参。
10. 数值变量只在 `model_contract`、明确下游方法或数值稳定性风险触发时比较与变量分布、单位和评价目标相关的变换或缩放候选；没有下游模型、可比较指标或变换需求时，标记为“不适用及原因”。不得固定要求比较 Min-Max、Z-Score、Robust Scaler、`log1p`、Box-Cox 和 Yeo-Johnson 的全套方法，也不得把标准化当作所有模型的必需步骤；`model_contract` 未确认时不得以验证分数宣布某种变换更优。
11. 类别变量必须根据有序性、基数和模型类型选择编码；Target Encoding 只能使用训练集内的交叉折叠/OOF 统计与平滑规则，禁止直接用全体样本目标均值编码。
12. 缺失机制必须区分 MCAR、MAR、MNAR，并明确说明：仅凭观测数据通常不能证明缺失属于哪一种机制；高级填补须根据变量类型、缺失比例、时间结构和模型目标选择，并保留不确定性与敏感性分析。
13. 当数据为数值型、样本量与维度允许可靠估计且确有联合结构风险时，多变量异常检测不能只依赖单变量 IQR/3σ：可按数据维度、分布和时间/分组结构补充 MAD/稳健 z 分数、Hampel、稳健 Mahalanobis、Isolation Forest 或 LOF 等方法。非数值、小样本、高维病态或没有合理距离定义时标记“不适用及原因”；任何检测结果都只是筛查证据，不得自动等同于删除依据。
14. 直接可观察到原始数据或本轮处理输入时，数据盘点后必须形成探索性统计基线：数值变量至少记录样本量、缺失率、分位数、均值、中位数、离散程度、偏度和峰度，类别变量至少记录频数、频率、类别数和稀有类别；全量审计结果不得直接用于拟合建模规则。`review_only` 只能描述已提供产物的可观察状态，明确原始基线不可观察，不得重建或臆测。
15. 需要图形证据时，必须形成包含数据家族、变量数量、有序性、观察目的、统计口径和数据范围的 `plot_request`。请求单由用户或已确认的编排器决定是否交给兼容绘图能力；若无已验证接口，则交付请求单和统计证据，并说明图形实现未交接。预处理 SKILL 不得重复维护图型排序、配色、字体、版式或绘图代码。
16. 特征构造必须保留公式、单位、来源字段、缺失/无穷值处理和泄漏检查；分箱边界、滚动窗口参数和其他数据依赖参数只能在训练集或训练折内确定。仅当已确认的 `model_contract` 要求模型验证时才记录验证指标；否则以语义、量纲、边界和信息可用时点验收，并标注“模型验证不适用”。
17. 需要基于目标或模型表现进行特征选择时，必须先确认 `model_contract`，并在训练集或训练折内完成；应根据变量类型选择过滤法、包裹法或嵌入法，同时记录效应量、稳定性、业务含义和合同定义的验证表现，不能只按 p 值或全量相关性排序。没有 `model_contract` 时可登记候选和冗余风险，但不得用未定义的模型分数强行排序或宣称最优特征集。
18. 类别不均衡处理只在已确认的分类 `model_contract`、少数类样本量足以支持方法且训练范围可隔离时执行；类别权重、欠采样、过采样、SMOTE 或 SMOTENC 只能在训练集或训练折内使用。验证集和测试集保持真实分布，并仅按合同报告 PR-AUC、类别级指标、校准和阈值依据；无分类合同的标签质量审计只报告分布与风险，不做重采样或性能评价。
19. 多重共线性与降维在模型合同或明确的分析设计需要时才诊断和拟合；涉及模型验证时必须在训练集或训练折内执行。VIF、条件数、矩阵秩、PCA 或 TruncatedSVD 的阈值和参数都要记录，不能把经验阈值当成绝对规则；未确认模型合同时可报告结构诊断，但不得用下游性能声明某方案最优。
20. 正态性判断必须说明检验对象是原始变量、误差还是残差，并结合 Q-Q/P-P 图请求、统计检验、样本量和业务影响解释；不得因偏度阈值、p 值或大样本就机械宣布“正态”或强制变换。
21. 每份外部数据或参数都必须登记发布者、标题/编号、获取日期、覆盖期、版本、用途、可引用位置与使用限制。搜索结果、AI 推荐和无法打开的链接只算候选，不算已核验来源。
22. 原始数据体检与处理后统计基线必须分开保存。原始体检可用全量数据发现质量问题；任何依赖样本统计量的建模规则仍只能在训练范围拟合。
23. 列名规范化、类型转换、编码转换和语义解析必须保留原值或映射，并审计行数、列数、独立实体数、字段变化与逐值新增缺失；`errors='coerce'` 只能将失败值送入待核验清单，不能掩盖它们。
24. 在删除、填补或纠正前，先确认字段语义和样本层级。空白、不适用、未记录、未检测、未知、阴性/正常不是同义词；单次“不显著”检验不能证明两组等同，也不能证明缺失机制或字段语义。
25. 重复记录必须区分完全重复、技术重复和纵向重复测量。技术重复的聚合方法按字段含义指定，并保留原始行映射、重复次数和组内冲突；不得用按列取首个非缺失值的方式静默拼接不同原始行。
26. 任何纵向拼接、横向连接、宽长表转换或时间对齐都必须声明输入与输出粒度、键关系、空键策略、预期行数、未匹配比例和新增结构性缺失。允许的一对多关系不能被强行改成一对一。
27. 当任务依赖时间特征或外部数据对齐时，必须说明事件时间、信息可用时间、实体键、方向和最大允许间隔。预测时点不得使用未来记录、当前未知目标或包含该目标的全轨迹汇总；无可信时间字段或时间不影响任务时，标记“不适用及原因”。
28. 用于模型的填补、缩放、编码、筛选、异常阈值、PCA/降维和重采样都应封装为训练范围内拟合的处理流程。若存在内外层验证，两层均须遵守相同的分组/时间隔离原则。
29. 当 `model_contract` 已定义可比较的验证设计和指标时，特征选择、共线性处理和降维比较应在一致的数据划分、指标和计算预算下报告性能、稳定性、可解释性与资源代价；无模型合同的比较只能报告结构、语义与资源证据，不得以单一案例、固定阈值或筛除比例宣称某方法普遍最优。
30. 每个实际执行的重要处理步骤必须留下运行生成的变更日志和验收结果；复核模式若未提供原始数据、代码或历史日志，只能记录可观察产物、缺失证据和复核结论，不得补造变更日志、前后统计或实测数字。

## 任务模式与适用性

先为每个模块标记 `执行 / 仅复核 / 不适用`，并写明理由；“不适用”是允许且必须留痕的结果，不是跳过说明。

| 任务模式 | 数据划分与测试集 | 重点模块 | 不能做的事 |
|---|---|---|---|
| 概念建议 | 不适用 | 方法条件、可执行步骤、需要补充的数据 | 假装已读取数据、输出实测日志或给出具体阈值结论 |
| 原始数据审计或描述统计 | 通常不适用 | 读入、语义、质量、分布与证据链 | 用全量审计统计拟合预测规则 |
| 预测/分类/估计未见表现 | 必须按泛化目标划分 | 训练范围处理、防泄漏、验证 | 用验证集/测试集拟合处理器或调参 |
| 优化/仿真 | 取决于参数是否由数据校准及是否声明外部表现 | 参数来源、约束口径、情景与稳健性 | 没有未见表现声明却伪造测试集，或用测试集选参数 |
| 复核已有产物 | 原始输入缺失时不适用 | 可观察结构、证据缺口、回读与风险 | 补造原始日志、清洗前后数字或未提供的字段语义 |
| 小样本、单一类别、非数值或无时间字段 | 按任务可标记不适用 | 语义、质量、可用的稳健描述 | 强行执行分层划分、SMOTE、协方差异常检测、时间特征或分布检验 |

只有任务需要以模型指标选择预处理方案、评估未见表现或校准阈值时，才建立并确认 `model_contract`；其余任务将模型验证相关模块标为“不适用及原因”。各任务模式应交付的产物与豁免项见 `references/execution-contract-and-applicability.md`。

## 工作流程（一步一问）

### 步骤1：目标澄清
- 目标：明确本次预处理服务哪一类建模任务（描述统计、预测、优化、关联分析等）。
- 优先提取：分析对象、时间范围、粒度、目标变量、泛化对象、信息可用时点和约束来源；仅对缺少且会阻止安全处理的项目补问一个关键问题。
- 必做：
  - 完成或更新 `task_manifest`，写明输入来源、可访问性、任务模式、输出位置、当前事实状态和不可逆操作边界。
  - 区分“原始数据质量审计”“为建模拟合处理器”“复核已有处理结果”三种工作，不把三者混为一个数据版本。
  - 将任务分为必做项、条件触发项与可延后项，约定最低可用数据集、最晚进入建模的条件和允许回头处理的范围。
  - 判断是否需要外部数据；需要时标注它的用途，不因“资料看起来权威”就直接并入模型。
- 产出：预处理任务清单（优先级、停止条件、数据版本和外部数据需求）及 `task_manifest`。

### 步骤2：数据盘点
- 目标：搞清楚“有哪些表、字段、时间字段、主键、关联键”。
- 必做：
  - 只读保存原始文件标识、读取配置、工作表/页码、行数、列数、关键字段、单位、时间格式和原始列名。
  - 检查列名首尾空白、不可见字符、空表头、规范化后重名、跨表同名异义/同义异名；保留“原始列名 -> 规范列名”映射。
  - 对日期、数值候选和 `object` 列，记录实际值类型频数、非空样例、异常编码和解析候选，不只看表层 `dtype`；只检查 `task_manifest.input_sources` 中明确列出的权威输入，不默认递归扫描工作区。
  - 为每张表定义“实体、事件/样本、测量记录”层级，检查候选主键、完全重复候选、技术重复候选、纵向重复分布、跨表键覆盖率和空键。
  - 识别高风险字段：目标/标签、标识符、价格/成本/物理量、时间戳、外部参数和可能由目标派生的字段。
- 产出：原始数据质量报告、字段映射、样本层级说明和数据字典。详见 `references/parsing-and-schema-validation.md` 与 `references/duplicates-and-longitudinal-data.md`。

### 步骤2A：原始统计快照与处理后基线规划
- 目标：在直接可读取原始数据或本轮处理输入时形成原始数据体检统计快照，并预先定义处理后基线的比较口径；实际处理后的统计基线在步骤8生成，明确“数据原来是什么样、处理后变成什么样”，但不把描述性结果误当成建模规则。`review_only` 只登记现有产物可观察的统计，不将其冒充为原始或处理前快照。
- 数据范围：
  - 全量审计范围可用于检查字段类型、单位、重复、明显不可能值和整体质量，但必须标记为“审计结果”，不能直接用来拟合变换、筛选或模型参数。
  - 建模分析范围中，训练集用于拟合数据依赖的处理器和候选模型；验证集可用于模型选择、阈值选择与概率校准；测试集只在规则、特征集合和超参数锁定后用于最终独立估计。
- 在直接可读取原始数据或本轮处理输入时：
  - 数值变量记录 `n`、缺失率、唯一值数、均值、中位数、标准差、IQR、P1/P5/P25/P50/P75/P95/P99、最小值、最大值、偏度和峰度。
  - 类别变量记录类别数、各类别频数、频率、稀有类别比例和未知类别比例；小样本同时报告频数和百分比。
  - 按关键地区、设备、用户、目标类别和时间窗口进行分组统计，检查总体统计量是否掩盖群体差异。全量审计中按目标类别的结果只用于标签质量和数据描述；不得据此选择填补、异常阈值、分箱、特征、降维或模型规则。若该观察会影响建模决策，必须在训练范围内重新计算。
  - 明确峰度采用 Fisher 还是 Pearson 口径；均值和标准差必须与中位数和 IQR 对照解释。
- 产出：实际执行时输出原始质量摘要、处理后基线字段清单与比较口径；实际处理后，再由步骤8产出处理后探索性统计基线表及关键变化表（字段、数据类型、范围、样本量、实体数、缺失、分位数、集中趋势、离散程度、分布形态、分组差异和初步风险）。仅复核时输出可观察产物统计、证据缺口和限制。

### 步骤2B：外部数据与来源核验（按需）
- 目标：判断外部数据、参数、阈值或文献依据能否支撑当前任务，并确保论文与模型可追溯。
- 必做：
  - 对每项候选材料检查发布者、原始页面或文献、覆盖对象/地区/时间、粒度、字段、统计口径、版本、使用限制和可引用位置。
  - 标注用途：模型输入、参数估计、阈值/约束依据、假设论证、独立验证或结果讨论。用途不同，所需时间可用性和质量要求不同。
  - 记录获取、分析、共享与上传外部服务的限制；无法确认时不得假定允许。
  - 无法获得实测参数时，区分文献值、待校准参数、情景区间和仿真设定，并说明其不能替代实测验证。
- 产出：数据来源登记表、可用性判定表、外部参数与假设表。详见 `references/data-sources-and-provenance.md`。

### 与 `math-modeling-plotting` 的联动边界
- 触发时机：只有当统计结论需要图形证据，或用户明确要求绘图时，才提交绘图请求；不因为完成统计基线就自动生成一整套图。
- 预处理 SKILL 负责：提出要验证的分析问题，确定数据范围、分组方式、聚合方式、单位和统计口径，说明图形证据会支持哪条结论。
- `plot_request` 是用户或已确认编排器可使用的显式交接产物，不是 `math-modeling-plotting` 的既定可调用接口；本 skill 不等待隐式返回，也不承诺任何特定绘图 skill 能消费该请求。
- 若获得下游结果，按 `plot_evidence` 记录交接状态、返回图形方案/路径、统计口径、解释风险和支持的结论；未交接或下游不可用时，记录状态和原因，不阻塞预处理。
- 两个 SKILL 联动时传递已经确认的上下文，不能重复询问相同问题；缺失信息只补问一个关键问题。
- 预处理 SKILL 不维护图型排序，不决定色板、字体、图例、版式、DPI，也不直接生成完整绘图代码。
- 绘图请求至少包含：

```text
plot_request:
  objective: 分布 / 比较 / 关系 / 构成 / 趋势 / 异常
  data_family: 数值型 / 类别型 / 混合型 / 时间序列
  variable_count: 单变量 / 双变量 / 多变量
  ordered: 是 / 否
  variables: 字段名称
  group_by: 分组字段
  time_field: 时间字段
  data_artifact: 处理后数据或只读审计数据的路径/标识
  table_or_sheet: 表、工作表或查询标识
  data_version_or_hash: 数据版本、校验值或稳定标识
  output_root: 图形可写入的已确认目录
  handoff_actor: 负责调用绘图能力的编排器/调用方
  upstream_context_status: 已确认 / 部分缺失 / 不可得，以及缺失字段
  aggregation: 均值 / 中位数 / 频数 / 频率 / 原始点
  unit: 字段单位
  sample_scope: 全量审计 / 训练集 / 验证集 / 测试集
  question: 这张图需要验证什么问题
  constraints: 样本量、类别数、缺失情况、异常值情况
```

- 接收结果时记录：交接状态、交接方、首选图、备选图、选图理由、所需聚合方式、图形解释风险、图形文件或路径、实际观察到的证据以及是否需要下游绘图技能。
- 若用户还需要实际成图，完成统计诊断后说明需要由用户或已确认编排器把请求单交给兼容绘图能力；用户未授权、不需要图形或无兼容接口时，保留绘图请求单即可。

### 数据集划分与防数据泄漏
- 目标：确保验证结果反映模型对未见数据的真实表现，而不是预处理过程提前看到了验证集或测试集。
- 必做：
  - 先根据任务模式与泛化声明选择数据角色：监督学习且需要调参、模型比较、阈值选择或概率校准时采用训练集/验证集/测试集；参数和策略已预先确定、且需要检验未见数据表现的简单模型或优化任务，可采用训练集/测试集二分。纯描述统计、数据核对和仅复核已有产物可标记“数据划分不适用”；只有声明最终独立泛化评估时才需要独立测试集。
  - 先写清泛化目标：预测未见实体、已知实体的未来、未来时间段、未见地区/设备，还是仅描述当前样本。再选择分层、分组、时间或组合划分；“存在重复测量”不自动等于只能使用某一种交叉验证。
  - 在计算任何依赖样本统计量的规则前，先完成上述数据划分；预测任务可按比例划分，分类任务在类别允许时采用分层划分。分组或时间结构会改变样本量与类别平衡时，报告实际折分结果而不是只报告计划比例。
  - 对需要声明未见表现的优化任务，明确数据角色：训练集用于估计目标函数系数、约束参数、惩罚系数或校准算法参数；独立测试集用于检验目标值、约束违反情况、鲁棒性和对未见数据的表现。若粒子群、遗传算法等算法的超参数、特征规则或停止条件需要根据数据表现选择，则应增加验证集，或只在训练集内部使用交叉验证；不作外部表现声明时，记录“独立测试不适用”及其限制。
  - 时间序列按信息可用时间先后划分，禁止用未来数据预测过去；同一用户、设备、地点或其他实体是否隔离由泛化目标决定，并记录防实体泄漏或防时间泄漏的依据。
  - 只用训练集估计均值、中位数、众数、分位数、IQR、MAD、标准差、变换参数、缩放参数、类别映射、频数和目标编码统计；异常阈值也属于只能在训练集拟合的规则。
  - 将训练集拟合出的处理器、阈值和映射原样应用到验证集/测试集（若设置验证集）；对训练阶段未见的类别按“未知类”或预先约定的回退规则处理，并记录其数量。
  - 特征构造必须额外检查来源字段的可用时点：当前未知目标、含当前目标的差分、使用全轨迹计算的目标均值以及未来窗口统计不能无条件进入当前预测模型。
  - 当已确认的 `model_contract` 需要在内层选择特征数、阈值、缩放、填补、降维维数或超参数时，内层折也必须使用符合任务的分组/时间限制；外层评估只用于最终泛化估计。
  - 对粒子群、遗传算法等随机优化方法记录随机种子、群体规模、迭代次数、交叉/变异率、惯性权重等参数，并在训练集内通过多次运行评估稳定性；不得依据测试集结果挑选最优超参数或随机种子。
  - 检查重复样本、同一实体和由未来字段派生的变量是否跨集合泄漏，并记录划分随机种子、时间边界、分层字段、分组字段和各集合规模。
- 产出：数据划分清单与防泄漏记录（任务类型、泛化目标、数据角色、划分方式、是否设置验证集及理由、时间/分组边界、随机种子、集合规模、训练集拟合的处理对象、验证集/测试集应用规则、当前目标和未来信息泄漏检查结果）。

### 步骤3：口径统一
- 目标：把字段语义、业务口径和格式转换变成可执行规则，避免后续混口径或静默丢值。
- 对应评委关注维度：样本定义、异常/退货/打折/无销售口径、单位与时间口径。
- 必做：
  - 明确退货、打折、无销售、停机、未检测、无事件或其他领域等价记录是否纳入分析，给出统一规则。
  - 统一单位、量纲、时间时区、日期边界、编码格式和缺失编码；对于大面积违反直觉的值，先核验字段定义、校正方式和单位，不能直接删除或重新命名。
  - 将原始日期、数值、复合单位文本、有序分档、边界值和类别映射分开处理。解析规则必须列出允许格式、歧义处理、非法值去向和预期范围。
  - 转换后检查行数、列数、独立实体数、值域、原生缺失、新增缺失、解析失败和未知类别；原值、转换值、失败原因或映射必须可追溯。
  - 对标签或二元派生字段，明确未知、空白与否定类别的处理。不得将“不是某类别”自动命名或解释成另一个更窄的类别。
- 产出：口径规则表、字段映射与解析失败表、转换前后审计表。详见 `references/parsing-and-schema-validation.md`。

### 步骤3A：样本层级、重复与结构转换
- 目标：避免把同一实体的多次观测、同一样本的技术复测和多表关系混为“重复数据”。
- 必做：
  - 先定义一行代表实体、事件、样本还是测量，再分别统计完全重复行、技术重复组和纵向重复观测；报告记录数、涉及实体数、重复组数和多余记录数。
  - 技术重复只有在样本或事件标识、采样时间、批次等证据支持时才合并。按字段含义定义均值、加权汇总、求和、保留代表行或冲突处理，保存原始行映射和组内差异。
  - 纵向重复测量通常保留，并向下游交接实体数、每实体记录数分布、时间结构和可能的相关性处理需求；是否摘要到实体级取决于题目与信息损失，不设绝对禁令。
  - 进行 `concat`、`merge`、`pivot`、`melt` 或分组聚合前，声明输入/输出粒度、键关系、空键策略、聚合规则和预期行数；完成后审计匹配覆盖率、行数变化、冲突和新增结构性缺失。
- 产出：样本层级表、重复处置日志、连接审计表和结构转换报告。详见 `references/duplicates-and-longitudinal-data.md` 与 `references/joins-and-time-alignment.md`。

### 步骤4：异常处理
- 目标：识别并处理不合理值，防止模型被脏数据误导。
- 必做：
  - 先做“显然异常”排查：例如身高出现 `3.2m`、价格为负、成本远大于售价、时间戳超出题目时间范围。若大量记录违反常识，先核验变量定义、单位、校正或标准化方式，不把猜测当结论。
  - 对具有可解释数值尺度或已核验业务阈值、且非空、非恒定并具备足以支持所选统计量的样本量的字段，至少执行一种可复核筛查（IQR、3σ、业务阈值三选一或组合），并记录阈值与触发样本数。空列、常量列或样本量不足以稳定估计分位数/标准差时，标记“统计异常筛查不适用”，改做字段完整性、业务阈值（如有）和记录范围审计。纯类别字段若没有可解释数值尺度和业务阈值，标记“数值异常检测不适用”，改做类别合法性、编码映射、未知率和频数审计。
  - 若使用 3σ，必须先说明数据为何可近似看作正态分布；写清 `μ`、`σ` 和判定区间 `(μ-3σ, μ+3σ)`，并提示其更适合测量误差、考试成绩、加工质量等近似正态型数据。
  - 若数据分布未知、偏态明显、零膨胀或不满足正态，优先使用箱型图 / IQR 规则；写清 `Q1`、`Q3`、`IQR=Q3-Q1` 以及判定区间 `[Q1-1.5IQR, Q3+1.5IQR]`。
  - 对外部规范、文献或经验阈值，记录来源、对象、单位、测量方法、版本和用途；应用后检查总体及关键群体的触发率。触发比例只是复核信号，不能单独证明阈值正确或错误。
  - 检查异常价格、异常成本、异常销量、异常时间点和跨字段逻辑矛盾。
  - 对异常样本采取“保留、修正、截尾、剔除、标记”之一，并说明依据。
  - 若异常点被判定为录入错误，可按“修正、插值、邻近值替换、转缺失后再补齐”的思路处理，但必须保留原始值、修正值、修正依据和涉及记录，说明为什么这样改不会篡改业务含义。
  - 区分“真实极端值”和“录入错误”。
  - 对不确定异常，优先标记并按需比较“保留、稳健处理、合理排除”对结论的影响；检测分数只表示“值得复核”，不能自动成为删除依据。
  - 输出“异常处理前后对比”：至少包含样本量、实体数、均值、中位数、P95/P99（或业务关键分位数）、极值变化和受影响群体。
- 产出：
  - 异常处理日志（字段、样本数、处理动作、理由、规则阈值）。
  - 异常处理前后对比表（字段级）。

### 多变量与稳健异常检测
- 目标：识别单个字段看似正常、但多个字段组合或局部时间窗口不合理的样本，避免把相关结构误判为正常或异常。
- 必做：
  - 先确认存在数值变量、可解释的距离或局部邻域、足够样本量和可处理的维度结构；任一前提不满足时，记录“不适用”、保留单变量/领域规则检查并说明限制。
  - 对偏态、重尾或含极端值的单变量，可补充 MAD 与稳健 z 分数；对有序时间序列或局部窗口，可使用 Hampel filter。记录中心位置、尺度估计、窗口和阈值。
  - 对需要考察变量联合距离的数据，可使用稳健 Mahalanobis 距离；先说明协方差估计方法、变量缩放、维度与样本量关系，并处理强共线性或高维不稳定问题。
  - 对复杂非线性或高维数据，可使用 Isolation Forest；对局部密度异常，可使用 LOF。记录随机种子、邻居数/子样本数、污染率或阈值来源，并说明参数敏感性。
  - 对不同地区、设备、个体或时间阶段分布明显不同的数据，优先在合理分组或时间窗口内检测，再与全局结果比较，避免把群体差异误当异常。
  - 将多变量检测结果与业务规则、单变量筛查和可视化交叉核验；无监督检测的证据可包括业务规则一致性、重采样后的异常集合/排序稳定性，或仅在存在可信标签时使用标签验证。不得把未定义的“交叉验证”写成无监督异常检测已经得到的真实性证明；检测分数只表示“值得复核”，不能自动作为删除依据。
- 产出：多变量异常检测表（样本/实体、方法、分组或窗口、参数与阈值、异常分数、交叉核验或稳定性证据、最终处置和影响评估）。

### 步骤5：缺失处理与补齐
- 目标：在不扭曲业务含义的前提下处理缺失。
- 必做：
  - 先识别缺失表现形式：`null`、空字符串、空白单元格、约定俗成缺失编码（如 `-1`、`9999`、异常日期）等。
  - 区分结构性缺失（本来不存在）、未记录、未检测、未知和应有但缺失；先查数据字典、采集流程、题目说明与相关字段，再用分组比较或统计检验提供辅助证据。
  - 若字段存在经确认的确定性关系，先在非缺失记录上核验公式、单位和时点，再考虑用可靠输入重建；重建值必须单独标记，不能无痕覆盖原值。
  - 对每个关键字段记录缺失率与缺失范围；若缺失比例过高或已明显破坏指标代表性，必须显式评估“删字段 / 限制分析范围 / 保留缺失指示 / 强行补齐”的取舍，不能依赖固定比例自动决策。
  - 整行删除只针对本次分析真正必要的字段；记录删除理由、删除前后记录数、实体数和关键群体分布，不能对整表裸用 `dropna()`。
  - 给出补齐策略（补零、前向填充、分组中位数、插值等）及适用条件。
  - 对简单补值，必须区分字段类型：
    - 定量字段可将“均值 / 中位数补齐”作为低门槛方案，但要说明是否会压缩波动、削弱极值。
    - 定性字段优先考虑“众数补齐”或单独设“未知类”，不得用数值均值硬补类别变量。
  - 若采用插值，必须说明为什么要用该插值方法：
    - Newton 插值：适合追求函数值逼近、点位较少且对边界震荡不敏感的场景；必须提示其可能出现边界震荡，不适合对导数或光滑性要求高的问题。
    - 样条插值：适合水流、轨迹、温度、加工曲线等“变化应平滑、不能突变”的数据；必须说明其隐含“局部平滑”假设。
  - 对“总体统计型数据、对个体精度要求不高”的字段，允许采用更简单的均值 / 众数补齐；但对高精度控制、轨迹、图像基线等问题，优先考虑插值或保留缺失并单独建模。
  - 对关键字段记录“补前缺失率、补后缺失率、补值占比、重建值占比、原生缺失与转换失败的区别”。
- 产出：
  - 缺失处理报告（字段、缺失率、是否删字段、补齐策略、适用理由、风险）。
  - 补齐后数据快照与字段级对比表。

#### 缺失机制与高级填补
- 先判断缺失机制：MCAR 指缺失与已观测和未观测变量都无关，MAR 指在给定已观测变量后可解释，MNAR 指仍依赖未观测值或缺失本身；应结合缺失模式、分组比较和领域机制提出证据与假设，但不能仅凭观测数据把三者之一当作已被证明的事实。
- 对关键字段增加缺失指示变量（如 `is_missing_x`），尤其当“是否缺失”本身可能携带业务信息时；同时说明该指示变量是否进入后续模型，避免把结构性缺失误当成普通随机缺失。
- 当简单补值会明显低估不确定性或多字段相互影响时，可按条件选择：
  - MICE（多重插补）：通过多轮条件模型生成多个完整数据集，适合需要反映填补不确定性的分析；须汇总多个数据集的估计结果，不应只保留一次插补结果。
  - Iterative Imputer：逐变量迭代预测缺失值，适合变量间存在可解释关系的定量数据；需防止高维、强共线或样本量不足造成不稳定，并限制迭代次数和验证误差。
  - KNN 填补：用相似样本的邻域值补齐，适合样本间距离有意义且特征已合理缩放的场景；高维、类别混杂、样本稀疏或分布不均时可能失真。
  - 随机森林填补：利用非线性和交互关系，适合变量关系复杂且样本量足够的场景；计算成本较高，仍需检查变量重要性、过拟合和对极端值的影响。
- 当 `model_contract` 需要估计未见表现时，任一高级填补方法都必须只在训练集拟合；在验证集/测试集上只能调用训练阶段确定的填补模型或规则。未声明泛化表现的 `raw_audit` 或 `preprocessing` 任务，可在已声明的分析数据集内拟合，但必须记录拟合范围、不得将遮盖验证或敏感性分析冒充为外部性能结论。用缺失位置模拟遮盖并与真实值比较时，报告 MAE/RMSE 或分类准确率，并说明该验证的样本范围和限制。

### 数据标准化与数值变换（按条件）
- 目标：改善变量尺度、偏态或重尾对距离计算、正则化和数值优化的影响，同时保留可解释的单位与反变换信息。
- 先判断触发条件：下游方法是否对尺度敏感、变量是否有可解释的偏态/重尾或定义域问题、数值优化是否不稳定，以及 `model_contract` 是否定义了可比较指标。条件不成立时保留原单位，记录“不变换及原因”。
- 候选方法仅按适用条件选取：
  - Min-Max：仅在有明确范围或尺度敏感模型需要时，按训练集最小值和最大值映射到指定区间；对测试阶段超出训练范围的值说明裁剪或允许超界规则，且注意极端值影响。
  - Z-Score：仅在线性模型、正则化、聚类或梯度优化等需要尺度统一的场景，按训练集均值和标准差变换；偏态和极端值存在时说明稳健性风险。
  - Robust Scaler：仅对重尾或含异常值、且下游方法依赖尺度的变量，按训练集的中位数和 IQR 缩放；不能替代异常原因调查，也不能掩盖真实极端值。
  - `log1p`：仅对非负、右偏且含零的变量压缩长尾；检查 `x >= 0` 并保留反变换关系。Box-Cox 仅适合严格正值变量，Yeo-Johnson 可处理含零或负值变量；两者的参数只能由训练集估计。
- 树模型通常不依赖单调缩放，但偏态变换仍可能改善解释或异常影响；距离、核、线性正则化和神经网络模型通常更需要尺度统一。只有 `model_contract` 已确认验证设计与指标时，才比较变换前后的验证表现；否则只比较定义域、分布、数值稳定性和业务可解释性，不得默认“越标准化越好”。
- 产出：实际执行时输出数值变换与缩放表（字段、原始范围/偏态、方法、训练集参数、适用理由、合同定义的验证结果或“不适用”、反变换方式与风险）。

### 类别变量编码
- 目标：把类别信息转换成模型可使用的数值表示，同时避免伪造顺序关系和目标泄漏。
- 必做：
  - 有真实顺序的类别可采用 ordinal/label encoding，并明确顺序依据；无序类别通常采用 One-Hot Encoding。Label Encoding 不应直接用于无序类别的线性或距离模型，否则数值间隔会制造虚假的大小关系。
  - 高基数类别可考虑 Frequency/Count Encoding，记录频数或频率的统计口径；需要保留稀有类别分组规则，不能因为频数低就无依据删除样本。
  - Target Encoding 只能使用训练集目标统计，并在训练集内部采用 K 折 OOF 编码、平滑和先验回退，避免每行编码直接看到自身目标；验证集/测试集只能使用训练集拟合的映射。分类目标、回归目标和多分类目标要分别说明统计方式。
  - 对低频类别预先合并为“其他/稀有类”，对训练阶段未见类别设“未知类”或使用零/先验回退；记录各集合中的未知率和稀有类占比。
  - 编码映射、类别频数、目标均值、平滑参数和稀有阈值都只能在训练集拟合；高基数编码须检查过拟合、维度膨胀、稀有类别不稳定和验证集分布漂移。
- 产出：类别编码策略表（字段、有序性、基数、方法、稀有/未知处理、训练集映射或统计、OOF/平滑方案、验证集未知率与泄漏检查）。

### 步骤6：时间效应处理（按条件）
- 目标：让数据能够表达日内、周内、季节、节假日等时间结构。
- 对应评委关注维度：时间效应处理。
- 触发条件：存在可信时间字段，且任务目标、模型合同或外部数据对齐确实依赖时间。条件不成立时，标记“不适用及原因”，不构造时间特征、不做时间对齐或序列划分。
- 满足触发条件时：
  - 建立统一时间索引，区分事件发生时间、记录时间和信息可用时间，并检查时区、连续性、重复时间戳与断档。
  - 抽取时间特征（周几、月份、季度、节假日标记等）。
  - 多源时间对齐时，记录实体键、匹配方向、最大允许间隔、相同时间是否可用和未匹配比例；`nearest` 或后向填补只有在任务允许使用未来信息时才可采用。
  - 重采样或跨频率扩展时，说明原字段是流量、存量、比率还是测量值，并据此选择求和、均值、末值或其他聚合；不能把月度总量无说明地复制为日度总量。
  - 说明是否存在断档区间及对应处理策略；首次观测、零时间间隔、负时间间隔和不规则采样必须进入边界检查。
- 产出：实际执行时输出时间特征表、时间对齐配置、匹配差值报告和时间完整性检查结果。详见 `references/joins-and-time-alignment.md`。

### 步骤6A：特征构造与登记
- 目标：基于领域含义和时间结构构造有解释力的新变量，同时保证公式、单位、时间边界和缺失传播可复核。
- 可选方法：
  - 构造比值、差值、利润率、转化率、单位成本、增长率、同比和环比。
  - 构造星期、月份、季度、节假日、距事件时间和分组内变化等时间特征。
  - 对时间序列构造过去窗口的均值、最大值、最小值、标准差和趋势；预测时点 `t` 的窗口只能使用 `t` 之前实际可得到的数据。
  - 根据业务含义构造交互项、分箱变量和少量多项式项；构造后检查维度增长和可解释性。
- 必做：每个新特征记录名称、公式、来源字段、单位、业务含义、实体与时间粒度、缺失/无穷值处理、预期范围、可用时点和泄漏检查。仅当 `model_contract` 已确认并要求模型验证时记录训练集拟合参数和验证结果；否则以公式复算、单位、边界、样例和信息时点验收，并标注模型验证不适用。
- 注意：比值特征必须处理分母为零、接近零和负数；不能用没有业务依据的极小值掩盖问题。分箱边界和目标分箱规则只能在训练集或训练折内确定。派生变量与来源字段同时用于线性模型时，需在实际设计矩阵上检查线性依赖、秩和解释目标。
- 产出：特征构造登记表、时间可用性表与新旧字段对照表。

### 步骤6B：特征选择（按模型合同）
- 目标：在避免目标泄漏的前提下减少低信息、冗余或不稳定变量，并保留可能通过交互或非线性发挥作用的特征。
- 方法选择：
  - 过滤法：低方差、Pearson、Spearman、互信息、卡方检验、ANOVA/Welch ANOVA 或 Kruskal-Wallis；按特征和目标的数据类型选择方法。
  - 包裹法：RFE、Sequential Feature Selection 或训练集内部的交叉验证逐步选择。
  - 嵌入法：LASSO、Elastic Net、树模型重要性和训练集内部交叉验证折上的 permutation importance。
- 仅当 `model_contract` 已确认且确需削减特征、改善模型稳定性或比较预测表现时执行目标相关筛选。筛选必须在训练集或每个交叉验证折内完成；验证集上的 permutation importance 只能在特征集合和超参数锁定后用作诊断，不得再据此选择特征；大量单变量检验要考虑 FDR；同时报告效应量、选择稳定性、业务意义、保留/剔除理由和合同定义的验证表现。没有模型合同时，可登记候选、冗余风险与语义理由，但不产出伪造的最优排序或验证分数。
- 注意：低方差只在尺度、变量意义和阈值可比时才可作为筛选依据；经过单位方差缩放后，不能再以相同的非零方差阈值区分非恒定特征。相关性接近零只说明线性关系弱，不代表变量对非线性模型、交互项或分组模型无用；树模型的 impurity importance 可能偏向取值多或基数高的变量。
- 产出：执行模型筛选时输出特征选择日志（候选特征、方法、训练范围、阈值、结果、理由、稳定性、合同定义的验证表现和计算代价）。

### 步骤6C：多重共线性与降维
- 目标：识别特征间的冗余线性结构，降低线性模型系数不稳定、矩阵病态和高维过拟合风险。
- 必做：
  - 先检查 Pearson/Spearman 两两相关，再根据需要计算 VIF，记录 `VIF_j=1/(1-R_j^2)` 中的回归对象、设计矩阵、截距口径和特征集合。确定性但非线性的派生关系不自动等于当前设计矩阵存在精确线性共线。
  - 高维或严重共线时补充条件数、特征值、矩阵秩和 tolerance；One-Hot 后检查完整虚拟变量陷阱，交互项和多项式项要单独复核。
  - 若 `model_contract` 或明确分析设计需要 PCA，先完成训练集内的缺失处理和尺度变换，再只在训练集或训练折拟合均值、尺度和载荷；主成分数结合累计解释方差、稳定性、解释成本和资源代价确定。只有合同定义了验证设计与指标时，才把验证表现加入维数选择；否则不得把解释方差阈值写成预测表现最优的证据。
  - 稀疏 One-Hot 数据优先考虑 TruncatedSVD；t-SNE 只作为探索性可视化，不作为默认的生产特征。
- 注意：`VIF>5`、`VIF>10` 和累计解释方差 85%～95% 都是经验参考，不是绝对规则；删除变量、合并变量、PCA、Ridge 或 Elastic Net 的选择要结合业务含义和下游验证。不得由一次案例或仅凭“保留原变量”宣称某种方法普遍优于另一种。
- 产出：共线性诊断表；实际执行降维时补充降维报告（变量、相关结构、VIF/条件数、处理动作、主成分参数、解释方差、重构误差、稳定性、资源代价和合同定义的验证结果或“不适用”）。

### 步骤6D：类别不均衡处理（按分类合同）
- 目标：避免多数类基线掩盖少数类识别失败，并让训练、验证和测试评价符合真实业务代价。
- 仅当 `model_contract` 已确认是分类任务、少数类足以支持方法且训练范围可隔离时执行：
  - 记录各类别样本数、比例、少数类样本量、多数类基线和分层/分组划分方式。
  - 在训练集或训练折内比较类别权重、欠采样、随机过采样、SMOTE 或 SMOTENC；混合类别与数值变量时不得把类别标签的整数编码直接当连续值做普通 SMOTE。
  - SMOTE 近邻数必须小于可用少数类样本量；生成样本不得参与验证集或测试集近邻搜索。
  - 使用合同定义的 PR-AUC、召回率、精确率、F1、Balanced Accuracy、混淆矩阵和概率校准等指标；分类阈值只能在验证集确定，测试集用于最终一次评估。
- 注意：重采样可能复制噪声、生成越过类别边界的样本并改变类别先验；验证集和测试集必须保持真实分布，必要时重新校准预测概率。无分类合同的标签质量审计只输出类别分布、定义与采样风险，不执行重采样或性能指标比较。
- 产出：实际执行时输出类别不均衡处理报告（类别分布、方法、训练折范围、采样比例、合同定义的指标、阈值和风险）。

### 步骤7：相关性前提检查
- 目标：确保后续相关分析方法与数据分布匹配。
- 对应评委关注维度：相关分析前提与方法条件。
- 必做：
  - 先判断分布特征（偏态、重尾、离群点、零膨胀）。
  - 再选择方法（如 Pearson、Spearman 等）并说明使用条件。
  - 必要时提示不满足条件的风险，不得直接给出误导性相关结论。
- 对数正态与 KS（按需强制）：
  - 触发条件：你准备在后续模型中使用“对数正态”作为分布假设。
  - 先确认 `distribution_test_contract`：检验对象、零/负值处置（不得无依据平移）、样本筛选范围、是否检验 `log(x)`、参数拟合方法、p 值校准路径、随机种子、重复次数和结论规则；缺少会改变结论的字段时只补问一个关键问题。
  - 判定前提：样本应为正值为主，且应先处理主要时间效应（至少说明是否已去趋势/去季节）。零或负值不能直接进入对数正态拟合，必须按合同标为不适用、按业务语义分层或转用其他有依据的分布；不得为了通过检验无依据地整体平移。
  - 必做动作：按合同拟合 `log(x)` 的参数并输出 KS 检验表（至少含 `样本对象`、`样本量n`、`纳入/排除规则`、`参数拟合方法`、`参数μ/σ`、`KS统计量D`、`p值或N/A`、`校准方法`、`判定或无法判定`、`备注`）。
  - 结论规则：若证据不支持对数正态，必须重新评估其他有依据的分布、稳健/非参数口径或模型假设；不得把一次p值直接解释为“证明相同”或“证明完全不服从”。
#### 一般正态性与分布判定
- 先说明检验对象是原始变量、回归误差还是分组残差；原始特征、PCA 输入和许多机器学习模型不以正态性为必需前提。
- 结合偏度、峰度、Q-Q/P-P 图形证据和 Shapiro-Wilk、Anderson-Darling 等统计检验；需要图形证据时只提交绘图请求，不在本 skill 重复维护图型和样式规则。若图形请求无法交接或未返回，则仅输出统计性证据和“视觉证据不可得”的暂定结论，不得声称已经满足完整图形证据标准。
- 大样本下统计检验可能对很小偏离也显著，应同时报告实际影响、尾部风险、业务含义和模型方法条件；中心极限定理不等于原始数据自动正态。
- `|Skew|<0.5`、`|Kurt|<1` 等经验阈值只能辅助描述，不能单独作为“接受正态”的证明；多变量同时检验时说明多重检验处理。
  - 若 KS 的分布参数由同一批样本估计，不得直接报告标准 KS 的名义 p 值为最终结论。合同应明确使用经验证可用的 Lilliefors 类校正，或参数自助法；参数自助法必须记录重复次数和随机种子。两者都不能实际执行时，仅报告 D 和方法限制，不给“通过/不通过”的 p 值结论。
- 产出：方法选择说明与前提满足性结论。

### 步骤8：预处理产物核验
- 目标：保证“可复现、可追溯、可交付”。
- 对应评委关注维度：统计意义与结论可复核性。
- 必做：
  - 核对输出数据规模、独立实体数、字段完整性、口径一致性、来源版本和文件间引用关系。
  - 每个转换步骤至少核对行列数、独立实体数、字段映射、原生/新增缺失、值域、匹配覆盖率或聚合去向；对高风险转换再使用边界样例、行级追踪、守恒量或人工手算复核。
  - 对处理后数据执行回读验证：核对schema、日期/时区、类别、缺失、数值精度、关键阈值判断及与日志的一致性。机器中间格式与人工审阅格式可以不同，但都须写明用途。
  - 对数据量过大时区分存储压缩、特征压缩和样本压缩；分块处理先验证统计量可合并，不能把不同样本量的块均值直接平均。
  - 对实际完成处理的数据，按步骤2A约定口径生成处理后探索性统计基线，并与原始统计快照对照；原始审计或仅复核任务没有处理后版本时，明确标记“处理后基线不可观察/不适用”。
  - 给出可复现检查点（输入文件、来源登记、规则版本、随机种子、处理器参数、输出路径、运行时间戳）；所有表中数字标注为实际运行、外部文献、演示示例或待运行占位符之一。
- 产出：预处理验收清单、步骤变更日志、回读验证报告、数据版本清单。详见 `references/scalable-processing-and-storage.md` 与 `references/preprocessing-evidence-and-delivery.md`。

### 步骤9：评委关注维度检查（不强制打分）
- 目标：从竞赛评审口径审视预处理是否到位，但默认不做量化评分。
- 检查方式：四维检查清单逐条核对，输出“已满足/有风险/待补证据”。

| 维度 | 核心检查点 |
|---|---|
| 样本、质量与业务口径 | 是否显式定义并一致执行，是否有来源与证据链；销售题可检查退货、打折、无销售，其他题替换为对应领域记录 |
| 时间效应处理 | 是否考虑日/周/季节/节假日等时间结构 |
| 方法条件与信息可用性 | 分布、样本依赖、尺度、信息时点与方法适配，前置条件是否满足 |
| 统计意义与结论可复核性 | 是否超越描述统计、是否可复核 |

- 若用户明确要求量化评分，再基于上述四维给出分数与分级。
- 强制输出：整改优先级清单（高/中/低）。

### 步骤10：输出改进清单
- 目标：把维度检查结果转为可执行动作。
- 必做：
  - 给出“问题 -> 影响 -> 修复动作 -> 验证方式 -> 优先级”。
  - 明确短期修复项与长期优化项。
- 产出：下一轮迭代计划。

## 标准输出模板（按任务模式选用）
先按 `task_manifest.mode`、`output_mode` 与 `model_contract` 选择交付项；完整的必交付和豁免表见 `references/execution-contract-and-applicability.md`。未执行、不可观察或不适用的模块必须说明原因和可得证据，不能用空白表、虚构日志或未定义的验证指标充数。
1. 预处理执行记录  
   内容：数据版本、数据来源、样本层级、口径与解析规则、重复/连接处理、异常处理、缺失处理、时间处理、相关性前提检查摘要。
2. 证据链  
   内容：来源、原始发现、处理规则、验证结果、结论、剩余风险及数字性质（实测/外部/演示/待运行）。
3. 异常处理前后对比表（实际执行异常处置时强制）  
   内容：字段、筛查规则、阈值来源与适配性、异常样本数、处置动作、处理前后统计量变化（记录数/实体数/均值/中位数/P95/P99）。未执行处置或仅复核产物时，输出“不可观察/不适用”的原因和可得证据。
4. 缺失处理与补齐策略表（实际执行缺失处置时强制）  
   内容：字段、原生/转换后缺失率、缺失语义、是否删字段、重建或补齐方法、适用理由、补值占比、风险提示。未执行补齐或仅复核产物时，输出“不可观察/不适用”的原因和可得证据。
5. 分布拟合与 KS 检验表（按需）  
   内容：仅当后续使用分布假设时输出；至少包含对数正态参数、KS 统计量、校准方法和“判定/无法判定”。`D_only` 时只能写“当前合同下无法判定”，不得给出通过/不通过结论。
6. 质量维度检查结果  
   内容：四维检查项的满足状态、风险点与对应依据（默认不打分）。
7. 数据来源与版本登记表（外部材料或参数存在时强制）  
   内容：发布者、标题/编号、链接或文献位置、获取日期、覆盖期、版本、用途、使用限制、核验状态。
8. 结构转换与防泄漏记录（存在多表、重复测量或已确认模型合同时强制）  
   内容：分析单位、重复类型、连接或聚合规则、泛化目标、划分边界、训练范围拟合对象、时间/实体泄漏检查。
9. 步骤变更与验收日志  
   内容：实际执行时记录每步输入输出记录数/实体数/字段数、缺失迁移、匹配覆盖率、规则参数、回读验证和输出位置；仅复核时记录可观察产物、缺失证据、核验范围和未能复现的原因。
10. 问题清单  
    内容：未达标项、风险项、边界条件说明。
11. 下一步动作  
    内容：整改优先级、执行顺序、复核闭环要求。

## 输出风格要求
- 全中文输出，术语尽量通俗解释。
- 面向小白：每条关键结论必须回答三个问题：
  - 为什么这么做？
  - 具体怎么做？
  - 不这么做会有什么后果？
- 不允许只给“结论句”，必须附最低限度证据与验证建议。

## Common Mistakes
- 没先确认建模目标和关键字段，就直接开始预处理。
- 把全量描述性统计、相关性排序、分箱边界、特征选择、PCA 或重采样结果直接带入模型，造成隐性数据泄漏。
- 在预处理 SKILL 中重复维护图型选择、配色、字体、版式和绘图代码，导致它与 `math-modeling-plotting` 的职责重叠。
- 只筛出异常值，不给处置规则、前后对比和影响评估。
- 只看 QQ 图或主观印象，就断定数据服从对数正态。
- 把经验阈值（偏度、峰度、VIF、PCA 累计解释方差或 SMOTE 比例）当成所有数据集都适用的硬标准。
- 不区分结构性缺失和随机缺失，就统一补齐。
- 以一次p值不显著为由宣布“两组没有差别”、字段空白等于某种业务状态，或缺失机制已被证明。
- 未检查列名冲突、列内实际类型和原始/新增缺失，就直接标准化列名、转换日期或使用 `errors='coerce'`。
- 把同一实体同一时间自动当技术重复，或用逐列 `first` 聚合隐藏组内矛盾。
- 用 `drop_duplicates` 修复所有连接错误，或把合理的一对多连接强行改成一对一。
- 将最近时间匹配、后向填补、全轨迹均值或当前目标差分直接用于预测任务，导致未来信息或目标泄漏。
- 在全量数据上筛选特征、确定PCA维数或选择处理方案，再将同一数据用于交叉验证报告。
- 对不同样本量的分块均值再求平均，或把分块可运行误判为统计量可准确合并。
- 为节省内存无验证地降精度、字符串化标识符或声称某种文件格式能无损保留全部数据语义。
- 在时间序列滚动特征中使用未来数据，或在划分数据前执行 SMOTE/过采样。
- 把训练集/验证集/测试集三分法强行套用到不需要验证集的数学规划或简单优化任务，或反过来在需要调参时省略验证集并用测试集选参数。
- 只做描述性清洗，不输出可复核的处理日志和质量检查结果。

## 触发示例（用于稳定触发）
- 正例：
  - “帮我做数模数据预处理，先处理异常值和缺失值。”
  - “我需要统一退货和打折口径，再检查时间效应。”
  - “预处理做完后，请按评委关注点检查哪里还不够。”
  - “我后面要用对数正态，帮我判断是否成立并给 KS 表。”
  - “这个日期列一半是数字一半是日期，转换后 NaT 变多了，帮我查。”
  - “同一个用户有很多条记录，训练测试集应该怎么划分才不泄漏？”
  - “两张表 merge 后从几百行变成几千行，帮我检查连接键和粒度。”

  - “帮我写目标函数。”（优先触发目标函数相关技能）
  - “帮我整理约束条件。”（优先触发约束提取相关技能）
