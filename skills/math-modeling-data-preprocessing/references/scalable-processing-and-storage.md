# 大规模处理、存储与回读验证

仅在数据量、内存、文件格式、精度、分块处理或样本压缩成为约束时读取。优化目标不同，验收也不同：存储压缩、特征压缩和样本压缩不能混为同一件事。

## 1. 先区分优化目标

| 类型 | 目标 | 主要风险 |
|---|---|---|
| 存储压缩 | 减少磁盘空间或读写时间 | 类型、精度、时区、类别语义丢失 |
| 特征压缩 | 降维或减少字段 | 可解释性、泄漏、预测信息损失 |
| 样本压缩 | 抽样、聚合或保留代表记录 | 类别、实体、时间轨迹和罕见事件被破坏 |

不要因“文件更小”就称预处理成功；必须说明节省了什么资源、保留了什么语义、牺牲了什么信息。

## 2. 类型与精度

降级数值类型前记录原范围、精度需求、关键阈值和预期误差。验收不能只比较文件大小，还应检查：

- 极值、分位数、缺失数、类别数和日期范围。
- 关键公式、排序、连接键、阈值边界和模型输入是否改变。
- 整数是否可能溢出；浮点精度是否足以区分关键数值。
- 标识符是否应作为字符串保留前导零，而不是转为数值。

若 `float32` 改变关键阈值判断、排序或科学计算误差不可接受，应保留更高精度。字符串化、类别化也会改变缺失与比较语义，需回读检查。

## 3. 文件格式与双产物

区分机器中间格式和人工审阅格式：

- 机器中间格式：用于保存类型、批量读取和后续计算。
- 人工审阅格式：用于抽查、评委阅读或论文附录。

格式选择需按当前环境实际读写测试。任何格式都不能被预设为“无损保留所有 pandas 语义”。保存后回读，核对：

```text
schema | rows | columns | entity_count | missing | categories | datetime/timezone |
numeric_precision | key_uniqueness | critical_thresholds
```

若文件跨工具使用，还要检查工具之间的日期、时区、空值、分类和编码兼容性。

## 4. 分块计算

先判断操作是否可拆分：

| 操作类型 | 可分块的条件 |
|---|---|
| 计数、总和、最小/最大 | 可维护并合并部分统计量 |
| 均值、比例 | 合并分子与分母，不能直接平均块均值 |
| 方差、标准差、协方差 | 维护足够的计数、均值和二阶统计量，或使用稳定的可合并算法 |
| 全局排序、去重、连接、全局分位数 | 通常需要额外协调、外部排序或全量/近似算法 |
| 时间窗口、实体轨迹 | 分块边界需保留前后上下文和实体连续性 |

对每个分块流程保存总数、有效数、总和和必要的中间统计量。至少在可承受的子集上将分块结果与全量结果对照；对不同组大小、缺失率和边界分割专门测试。

## 5. 样本压缩

抽样或保留代表记录时记录：

```text
sampling_unit:
seed:
entity_coverage:
class_distribution_before_after:
time_coverage_before_after:
trajectory_completeness:
rare_event_retention:
intended_use:
```

按行随机抽样可能把同一实体拆散、破坏时间顺序或遗漏少数类。抽样单位应由泛化目标和分析单位决定；用于探索可与用于模型评估不同，但都不得偷偷改变验证集/测试集的真实分布。

## 6. 最小回读验收

1. 用目标环境重新读取输出文件。
2. 比较结构、模式、关键类型、缺失、值域、时间和连接键。
3. 运行关键阈值、公式和抽样分布断言。
4. 将回读结果与步骤变更日志关联，记录差异及处理结论。
5. 为每个输出标明用途、版本、生成时间和可复现输入。
