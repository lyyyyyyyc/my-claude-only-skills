# 为 `math-modeling-data-preprocessing` 新增内容的维护指南

## 用途
这份文档是给 Codex 在后续继续扩展 `math-modeling-data-preprocessing` 时使用的维护规程。以后如果需要继续往这个 skill 里新增预处理规则、补充触发词、扩展质量复核要求或调整插入位置，优先先读这份文档，再决定改哪里、怎么改。

本 skill 当前采用“两层结构”：`SKILL.md` 仅保留高频决策、硬规则和流程入口；低频或需要表格/示例的操作细节放入 `references/`。新增内容前先判断是否能在已有参考文件中扩展，避免把主文件膨胀成数据处理手册。

## 什么时候应该新增内容
以下情况适合继续新增到这个 skill：
- 出现新的高频预处理口语表达，导致当前 `description` 或 `when_to_use` 覆盖不足。
- 需要补新的预处理规则，例如新的缺失值处置、异常值处置、时间效应处理或分布检验要求。
- 需要补新的质量复核要求，使输出更容易被评委或后续建模步骤复核。
- 发现新的常见跑偏场景，值得加入 `Common Mistakes`。

以下情况通常不应该直接加到这个 skill：
- 只适用于某一种模型的细节。
- 某个题目的临时数据口径。
- 只适用于单次会话的处理偏好。
- 更适合放到 `math-modeling-constraints`、`math-modeling-objective-function-builder` 或其他专门数模 skill 的内容。

## 新内容应该加到哪里
新增内容时，先判断它属于哪一类，再放到对应区块：

| 新增内容类型 | 应放位置 |
|---|---|
| 触发词、用户口语表达、何时应该调用本 skill | frontmatter 的 `description` / `when_to_use` |
| 进入预处理前必须先确认什么 | `什么时候优先用本 skill` / `第一优先动作` |
| 通用预处理规则和质量要求 | `强制依赖与硬规则` 或 `工作流程（一步一问）` |
| 输出结构变化 | `标准输出模板（固定）` |
| 容易跑偏的问题 | `Common Mistakes` |
| 低频、长说明、维护导向规则 | `references/` |

## 参考文件边界

| 文件 | 何时读取 | 不应放入的内容 |
|---|---|---|
| `data-sources-and-provenance.md` | 外部数据、参数、阈值、许可、引用 | 某平台或赛事的临时结论 |
| `parsing-and-schema-validation.md` | 读入、列名、混合类型、日期、单位文本、编码 | 特定文件的固定列名和读入路径 |
| `duplicates-and-longitudinal-data.md` | 技术重复、纵向记录、分组聚合、重复测量 | 某个模型的完整推导 |
| `joins-and-time-alignment.md` | 多表连接、长宽转换、时间匹配、可用时点 | 某题的固定连接键或日期阈值 |
| `scalable-processing-and-storage.md` | 内存、分块、格式、精度、抽样 | 未经回读验证的格式承诺 |
| `preprocessing-evidence-and-delivery.md` | 日志、验收、论文交接、AI 协作、交付包 | 伪造的效果数字或一次案例结论 |
| `execution-contract-and-applicability.md` | 输入发现、任务模式、输出合同、降级路径、跨技能交接 | 固定项目路径、强制调用链或未经确认的自动写文件 |

## 新增内容的判断流程
以后新增内容时，按下面顺序判断：

1. 先判断这是“触发优化”还是“预处理规则扩展”。
2. 再判断它是“通用规则”还是“只适用于某类任务”。
3. 如果是通用规则，优先补到主 `SKILL.md` 的现有区块。
4. 如果只是低频长说明，优先放进 `references/`，主文只留入口。
5. 如果这条内容会改变触发边界，必须同步检查 `description` 和 `when_to_use`。
6. 如果更适合别的数模 skill，就不要硬塞进本 skill。
7. 若规则涉及统计推断、软件 API 或第三方格式行为，先以实际运行、官方文档或一手资料核验；无法核验时写明适用假设或待核验状态。
8. 若规则改变现有运行时承诺、输出合同或边界，先保留旧 bundle 的审计快照，修改后完成回归审计；不能用“精简”静默删除既有能力。

## 写法规范
- 解释“为什么”，不要只堆“必须”。
- 新规则尽量短，优先补进已有区块，不轻易新开大区块。
- 对统计或分布判断类规则，要写清适用条件，不要扩大到所有数据。
- 不写叙事式历史，不写一次性案例总结。
- 新增内容要优先减少跑偏，提升可复核性，而不是单纯增加篇幅。
- 经验阈值只能作为可配置参考，必须说明字段语义、尺度、样本结构和方法条件；不得从一次案例推导通用优劣或固定效果数字。
- 明确区分审计用途的全量统计与建模用途的训练范围拟合，避免把“查看数据”写成“用全量数据确定模型规则”。

## 修改前检查清单
- 这条内容是否真的是高频、可复用规则。
- 是否和已有区块重复。
- 是否本来属于别的数模 skill。
- 是否会改变触发边界。
- 是否需要同步补 `Common Mistakes`。

## 修改后检查清单
- frontmatter 是否需要同步更新。
- 新内容是否放在了正确区块。
- 主 `SKILL.md` 是否仍然保持“先确认任务，再进入流程”的顺序。
- 是否引入新的重复表述。
- 是否仍然保留现有预处理流程和标准输出模板的主体结构。
- 新增或更新的 `references/` 是否已从 `SKILL.md` 链接，且路径真实存在。
- 是否新增了会静默丢失原值、空键、重复记录、转换失败或未来信息的规则。
- 是否为高风险规则提供可观察的验收方式，而非“已确认”的自我声明。
- 任务是否允许“不适用”并说明理由，避免把预测任务的测试集、时间字段或高级统计方法强行套到审计和复核任务。

## 常见错误
- 不问建模目标和关键字段，就直接开始预处理。
- 只加新规则，不写适用条件和证据要求。
- 把某个具体题目的临时处理方式写成永久规则。
- 增加内容后不检查 `description` / `when_to_use`。
- 把低频长说明直接塞进主文前半段。
- 将 `p` 值不显著、筛除比例、模型分数或单个案例表现当作字段语义、阈值正确性或普遍方法优劣的证明。
- 将合理的一对多连接、纵向观测或技术复测一律压成一对一或 `drop_duplicates`。
- 将分块的均值再次简单平均，或未经回读就声明类型/格式转换无损。
- 要求调用另一个 skill 却不说明可用条件、交接输入、返回产物或不可用时的降级路径。

## 建议回归测试提示词
- “先把这份销量数据做缺失值和异常值处理，再给我说明为什么这么处理。”
- “我后面要做对数正态，先帮我检查预处理后能不能这么假设并给 KS 表。”
- “帮我统一退货和打折口径，再按评委关注点检查预处理还缺什么。”
- “两张表合并后行数暴涨，是否是一对多关系，空键怎么处理？”
- “日期混合了 Excel 序列、文本和空白，转换后新增了 NaT，帮我逐项审计。”
- “缺失字段能否由其他字段公式重建？不能时该如何记录假设和风险？”
- “我要把外部指标接入预测模型，先核验来源、预测时点和许可。”
