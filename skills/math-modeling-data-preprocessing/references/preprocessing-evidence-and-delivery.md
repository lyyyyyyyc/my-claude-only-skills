# 预处理证据、验收与交付

仅在需要交付数据、写论文、复核已有流程、使用 AI 辅助或报告预处理结论时读取。目标是让别人能够区分：发现了什么、依据是什么、做了什么、验证了什么、还留下什么风险。

## 1. 自动生成的步骤变更日志

每个实际执行的重要步骤应由运行产生记录，而不是手写“效果很好”的数字。最小字段：

```text
step_id:
operation_id:
input_version:
input_hash_or_identifier:
output_version:
output_hash_or_identifier:
rule_or_parameter:
stable_row_identifier_or_scope:
rows_before_after:
entities_before_after:
columns_before_after:
native_missing_before_after:
new_missing:
match_or_aggregation_metrics:
warnings_and_failures:
error_records_location:
validation_result:
acceptance_rule:
generated_at:
```

数字都需标记来源：`实际运行 / 外部文献 / 演示示例 / 待运行占位符`。`operation_id` 在本次运行内唯一；优先使用源表稳定行标识，若没有则记录行级追踪范围和生成方式。输入/输出可使用内容哈希、文件校验值或稳定版本标识。警告和失败不可用全局静默过滤代替处理；应记录、分类、修复、豁免或停止流程。

`acceptance_rule` 记录本步实际适用的结构断言、允许误差或人工复核条件；不设跨项目的万能数值阈值。`error_records_location` 记录解析失败、连接冲突或断言失败的可追溯位置；没有错误记录也要写明检查范围。

仅复核模式若没有原始输入、代码或历史日志，应输出“可观察产物 + 缺失证据 + 风险”而非变更日志；不能依据最终数据倒推并声称实际执行过的步骤。

## 2. 分层验收

将检查设计成可失败的观察，不写“已确认无误”一类自我判断。按风险使用：

| 层级 | 适用场景 | 可观察证据 |
|---|---|---|
| 结构断言 | 所有步骤 | 行列数、键唯一性、字段存在、模式 |
| 汇总对照 | 清洗/转换 | 缺失迁移、值域、频数、分位数、实体数 |
| 边界样例 | 解析/规则 | 空值、上/下界、异常编码、日期歧义、空键 |
| 行级追踪 | 高风险转换 | 原值、转换值、规则、失败原因、记录去向 |
| 守恒/手算 | 聚合/分块/连接 | 总量、有效分母、组计数、人工可复现小例 |
| 回读验证 | 文件交付 | 重新读取后的类型、精度、时区、类别和关键判断 |

检查必须覆盖规则的每个关键条件。若规则要求“原值保留、失败入表、回读一致”，就分别提供三类证据，不能只检查行数。

## 3. 最小交付包

按项目需要交付下列文件或等价结构：

```text
raw_manifest.md                 # 原始文件标识、只读位置和读取配置
data_sources.md                 # 外部来源、参数、权限与引用
data_dictionary.md              # 字段语义、单位、映射和样本层级
preprocessing_rules.md/json     # 规则、版本、参数和适用范围
change_log.csv/json             # 实际运行的步骤变化
processed_data.<format>         # 机器使用的数据版本
review_copy.<format>            # 人工抽查版本（按需）
validation_report.md            # 断言、回读和剩余风险
feature_registry.md             # 公式、可用时间、泄漏检查（按需）
```

不要求所有任务都使用固定文件名，但必须能够从最终结果反查原始输入、规则版本、处理器参数、随机种子和验证证据。

## 4. 论文/答辩交接模板

每个关键处理用以下五段表达：

1. **发现**：字段/样本/结构出现了什么问题。
2. **依据**：数据字典、原始来源、业务规则、统计证据或敏感性分析是什么。
3. **处理**：执行了什么规则，适用范围和例外是什么。
4. **验证**：前后对照、断言、回读或下游验证显示什么。
5. **剩余风险**：什么仍未确认，会如何影响解释或泛化。

避免把“p 值不显著”“筛掉比例不大”“模型分数变高”单独写成处理正确的证明。它们最多是需要结合语义和设计继续判断的证据。

## 5. AI 协作要求

向 AI 请求分析或生成代码时，提供真实字段名、数据字典摘要、样本粒度、目标变量、预测时点和已执行规则；不能只说“帮我洗数据”后接受猜测。

AI 产出的每项处理建议都要落实为：

```text
input_fields | assumed_semantics | proposed_rule | verification_code_or_check |
actual_result | evidence_location | unresolved_assumption
```

AI 给出的数据名称、论文、网页、统计数字、阈值和库行为均为候选，必须回到原始来源或实际运行验证。不可将 AI 生成的示例数字写入结果表或论文结论。

## 6. 故障与停止规则

出现下列情况时，停止自动推进并转入核验或向用户补问一个关键问题：

- 关键字段语义、单位、样本层级或目标时点未确认。
- 连接关系、空键、行数膨胀或重复定义无法解释。
- 转换新增缺失或类别未知率异常升高。
- 外部来源的可用性、许可或时间可得性无法确认。
- 关键验证断言失败，或回读与日志不一致。

非关键、低收益的比较可记录为“未执行及原因”，而不是为追求完整度强行执行。达到已约定的最低可用数据、关键风险已处置或显式披露、基线模型可运行且交付包可复核时，可进入建模。
