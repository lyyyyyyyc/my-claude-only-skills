# 连接、长宽转换与时间对齐

仅在存在 `concat`、`merge`、`pivot`、`melt`、跨频率数据或外部时间对齐时读取。先定义粒度与可用时间，再写代码；行数变化本身不是错误，也不是成功证明。

## 1. 连接前声明

每次结构转换前填写：

```text
left_grain:
right_grain:
output_grain:
keys:
relationship: one_to_one / one_to_many / many_to_one / many_to_many
null_key_policy:
expected_row_count_or_range:
expected_match_rate:
unmatched_policy:
```

字段同名不表示可以连接。先核对键的语义、类型、单位、编码、时间粒度和每侧键唯一性。

## 2. 连接验收

连接后至少检查：

- 左、右、输出的行数、独立实体数和键唯一性。
- 每种连接关系的实际基数是否符合声明。
- 匹配、仅左侧、仅右侧的记录数及关键群体差异。
- 新增列的缺失是结构性未匹配，还是原字段本来缺失。
- 多对多是否是任务允许的真实关系；它可以合法，但通常需要额外说明行数放大含义。

空键需先处理。某些数据工具会将两侧空键视为可以匹配，可能产生虚假的合并；除非任务明确要求，不应让未知实体/未知时间互相匹配。

不要用 `drop_duplicates` 掩盖连接问题，也不要将本来合理的一对多关系强行改成一对一。若输出行数膨胀，先解释它对应的输出粒度，而不是只追求行数不变。

## 3. 纵向拼接与横向连接

- 纵向拼接前对齐字段字典、单位、时间格式、类别代码和结构性缺失；记录来自哪张源表。
- 横向连接前确认每个输出行的分析单位，以及测量值属于哪个事件或时间。
- 同名字段含义不同应改名并保留来源；同义字段合并前需要一致性检查。

## 4. 长宽表转换

使用长转宽或宽转长前明确：

| 问题 | 必须说明 |
|---|---|
| 唯一性 | 哪些键组合应唯一，重复如何处置 |
| 聚合 | 若单元格有多值，使用什么聚合及其语义 |
| 缺失 | “没有这次观测”与“观测存在但值缺失”如何区分 |
| 字段命名 | 新列如何命名，是否与原列冲突 |

透视表常默认使用均值聚合；只有均值符合数据含义时才可接受。转换后检查行列数、唯一键数、填充单元格数、结构性缺失和关键变量守恒。

## 5. 时间对齐

每个外部或跨表时间匹配需记录：

```text
entity_key:
event_time:
record_time:
information_available_time:
reference_time:
direction: backward / forward / nearest / exact
tolerance:
same_time_availability:
unmatched_rate:
time_difference_summary:
```

预测时点的特征必须使用当时已知信息。`nearest` 可能选择未来记录；后向或前向填充同样需要符合业务信息流。若存在发布滞后、修订或数据回填，应使用“信息可用时间”而非仅使用事件发生时间。

对于滚动窗口、差分、增长率和时间间隔：

- 窗口在时点 `t` 只能使用 `t` 前可取得记录。
- 分母为零、接近零、首次观测、零间隔、负间隔和不规则采样需明确处置。
- 对流量、存量、比率和测量值分别决定重采样时用求和、末值、均值或其他规则。
- 月度总量不可无说明地复制成日度总量。

## 6. 防泄漏的快速检查

遇到以下任一情况，标为高风险并回到数据划分与特征登记：

- 当前目标值或当前标签直接进入特征。
- 使用包含当前目标的差分、比值或全轨迹汇总。
- 特征来自预测时点之后的记录、未来窗口或未来版本的外部数据。
- 以全量数据计算分组均值、目标编码、异常阈值、填补参数或分箱边界后再评估模型。

最终输出一份连接与时间对齐审计表，保存配置、匹配率、未匹配样本、行数变化、时间差和判定结果。
