# Annotation UTF-8 Guard

## 目标

在任何“写注释/改注释”的任务里，强制执行 UTF-8 安全流程，避免中文注释乱码，并在回复中附上可记录的步骤说明。

## 触发条件（必须执行）

- 用户提到“注释”两个字。
- 用户要求“写注释/改注释/添加注释/注释更详细/注释中文”等。

## 必须遵守的工作流（不可省略）

1) **只用 UTF-8 写入文件**
   - 读写时明确 `encoding="utf-8"`。
   - Python 写 JSON/Notebook 时用 `ensure_ascii=False`。

2) **禁止用 PowerShell 管道把中文喂给 Python**
   - 禁用 `@'...中文...' | python -` 这种方式。
   - 如需临时脚本，使用 `write_file`/编辑器保存为 UTF-8。

3) **Notebook 写注释的安全方式**
   - 读取 `.ipynb` 用 `json`。
   - 仅修改 `cells[].source`，写回时 `encoding="utf-8"`。
   - 若有空 code cell，逻辑必须容错，避免索引错位。
   - **IPYNB 注释范围确认（必须先问）**：
     - 是否需要**详细注释**（逐段/逐参数说明）？
     - 是否需要**新建 Markdown cell** 专门写文字说明？
     - 只在 code cell 内写注释，还是 code+Markdown 混合说明？
     - 是否需要新增 **Q&A（问答）** 注释环节？
     - **提问方式**：给出**数字选项**（如 1/2/3），让用户只需回数字选择，避免要求用户打字说明。
   - **深度学习任务判定与风格确认（必须先做）**：
     - 先判断用户任务是否为**深度学习相关**（如：模型训练/网络结构/损失函数/数据集/指标/调参等）。  
     - 若**不是**深度学习任务：**不触发此风格确认**。  
     - 若**是**深度学习任务：必须先给出**数字选项**的判断题，询问是否采用“**小白版、逐步解释 + 形状说明 + 原因解释 + Q&A + 改动点标注**”的注释风格。

4) **必须做乱码自检**
   - 查 `???` 或 `�`（替换字符）。
   - 如发现，重新以 UTF-8 重写。

5) **输出必须包含“可记录版（按关键步骤）”**
   - 每次完成注释后，回复里附上可记录的步骤清单。

## “可记录版（按关键步骤）”输出模板（必须带上）

- 问题根因：中文通过非 UTF‑8 途径写入导致乱码。
- 关键步骤：
  1. 统一以 UTF‑8 读写文件（`encoding="utf-8"`）。
  2. Notebook 用 `json` 读写，`ensure_ascii=False`。
  3. 禁止 PowerShell 管道喂中文给 Python。
  4. 处理空 code cell 的对齐问题。
  5. 自检 `???`/`�`，必要时重写。
- 关键代码点：`write_text(..., encoding="utf-8")` / `ensure_ascii=False`。

## 最小要点提示

- 如需运行脚本，确保环境变量 `PYTHONIOENCODING=utf-8` 可用（只在需要时提示）。
- 若用户要求“详细注释”，在注释中明确每个参数含义、单位、约束来源（题目/数据）。
