# 方法依据与适用范围

## 用户确认的制作目标

本技能提炼自一次完整支撑材料制作及用户的明确要求：根目录四项固定；整题预处理、各问求解、敏感性、稳健性和绘图都转成精简可运行 PY；论文图表与完整结果集中归档；题外数据单独分类；Readme 分成材料与运行说明两部分。

2026-09-09 用户进一步指定提交范围：Figures 只保留图片与答题结果两个目录，图片连续编号；结果仅按题号保留直接答案；不交付来源表、论文表格总表、日志、缓存或验证记录；Readme 的运行部分只写环境；所有交付文件脱敏并去除制作来源措辞。此要求替代旧版公开过程材料的做法，但内部全流程验证及完整计算代码继续保留。用户明确禁止本轮子代理，维护时采用串行检查和测试。

同日用户再次明确：结果表必须与程序输出一致，不接受二次改表或单元格配色；论文实际使用的全部表格也须交付。本版以这一最新要求为准，新增 paper_tables 目录，恢复论文表格覆盖；结果按文件原样复制并校验字节一致，不再合并或裁列。原有短 Readme、隐私保护和包外运行记录规则保留。

已完成项目提供了具体纠错经验：动态参数改名遗漏、隐藏 Notebook 状态、Windows 数值环境、绘图布局和字体上下文、原图与复算图分版、从空缓存实跑及按业务键比较。这些经验写成判断规则，不把某一道题的企业数量、模型参数、图表数量、盘符和人员路径写成通用标准。

## 公开规范

- Anthropic 官方 `anthropics/skills` 仓库中的 skill-creator：明确触发场景、从当前任务提炼、使用必要脚本和渐进式参考材料，并设计可观察的测试。2026-09-09 读取官方仓库文本；官方最佳实践页面当时跳转地区不可用页面，未声称读取了该页面正文。
- Jupyter 官方 `jupyter/nbformat` 的 `docs/format_description.rst`：Notebook 是结构化 JSON，代码单元与输出应区分；磁盘上的多行 source 可为字符串或字符串列表。2026-09-09 读取官方仓库文本，辅助盘点按这一结构处理，不做正则切割 JSON。
- 数学正确性和完整复现要求来自用户交付契约与实际结果核对，不把目录检查器包装成外部机构认证。

可复核的官方来源地址：

## 能力边界

本技能不是一键将任意语言、任意 Notebook 无损转换为 Python 的程序。通用脚本承担盘点和有限结构验收，模型改写和完整性判断由执行者阅读本项目资料后完成。未获得原始输入、论文入口、求解器或执行权限时，必须说明缺口，不补造数据或运行结论。

本地技能创建及夹具测试不等于已在其他比赛项目成功运行；每次实际制作都需要本项目的验证证据。技能默认只制作材料，不额外修改论文、打包发布、提交比赛或更改其他技能。
