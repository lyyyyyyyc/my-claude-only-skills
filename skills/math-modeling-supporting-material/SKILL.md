# 数学建模支撑材料制作

交付材料用于阅读和使用，制作记录用于内部验证，两者分开。说明文字只介绍文件内容，简短、自然，不写防御性解释或自证过程。

## 交付规则

1. 根目录只有 `Code/`、`Figures/`、`User_data/`、`Readme.txt`。默认放在项目允许的输出区域，如 `Solve/支撑材料/`，也可按用户指定位置制作。
2. Code 中交付全部相关 Python 源文件：预处理、特征处理、各问模型与求解、敏感性、稳健性、必要对照、后处理、绘图。可简化重复内容和封装，保留模型、参数、随机种子、约束与实验。依赖清单和必要配置可以保留。
3. Figures 下设置 `paper_figures/`、`paper_tables/` 和 `results/` 三个目录，分别保存论文图片、论文表格和程序结果。不放来源映射、总索引、验证报告或散文件，也不把这些过程文件移到别处混入交付包。
4. `paper_figures/` 保存选定论文版本使用的图片，按论文出现顺序命名 `01.png`、`02.png`、`03.png` 等，连续、不跳号、不带 DP/Q1 等来源前缀。多个格式的同一图共用编号。超过 99 张时统一扩展编号宽度。
5. `results/` 只含各问的 `problem_1_results/`、`problem_2_results/` 等目录，按文件选取直接回答题目的结果。程序输出什么文件就原样收录什么文件：直接复制，不合并工作簿、不删行列或工作表、不改表头、精度、排序和数值，也不添加单元格颜色、字体、边框、行高列宽、筛选或冻结等排版。用源输出与交付文件的 SHA256 一致性验收；不能只比较数值相同。
6. `paper_tables/` 收齐当前论文实际出现的全部表格，包括符号说明、数据统计、参数、模型比较、求解结果、敏感性稳健性及附录表。按论文顺序单独导出可编辑文件，保留表号、标题、单位和显示精度，默认不加颜色等装饰。论文表与完整程序结果分开，不能互相替代。
7. 不额外提交仅用于预处理审计、约束验收、参数扫描、候选组合等的独立过程文件，日志和缓存仍放包外。某张过程表若已出现在论文中，须收录其论文版本；答题工作簿若原本包含辅助工作表，保留整个工作簿，不为精简而拆改。全部计算及检验代码继续保留。
8. User_data 只放实际使用的题外数据；没有则留空，不放说明、占位文件、原赛题附件或自产缓存。
9. 所有交付文件均须检查个人姓名、用户名、个人路径、邮箱和作者身份信息，覆盖文本、表格内容、批注、链接及元数据。结果输出存在身份信息时，在生成端去除非业务身份字段并重新输出，再原样复制；不擅自修改计算结果或格式。`openpyxl` 等经核实的通用生成器标记不属于个人身份，赛题实体正常保留。
10. 提交材料中不出现 Notebook、IPYNB、Markdown、MD、LaTeX 等制作来源字眼或源文档路径。只介绍求解程序、图片和表格。论文附录若含原工作目录，将提交版文件说明映射到支撑材料实际路径，记录这一导航调整；不改变科研表格的数值或结论，也不修改论文。必要库接口不能为通过扫描而破坏。
11. 不修改原始附件和论文。内部验证仍做完整实跑与结果比较，证据保存在交付包以外。仅变更复制或发布逻辑时，可沿用未改动计算代码的完整运行证据，并单独重验发布步骤；明确增量范围。未完成的验证如实在对话说明，不编造成功记录，也不往简短 Readme 添加长篇声明。

按最新用户要求恢复全部论文表格，并强制程序结果原样复制；来源映射、公开日志和详细复现说明仍不交付。

## Readme 写法

仅有两个一级部分：

- `1. 材料说明`：各目录一句话，正常介绍代码、图片、结果表格和题外数据情况。
- `2. 代码运行说明`：仅简要写操作系统、Python/环境名称、主要依赖，必要时指向 Code 中的依赖清单。通常一至两句话即可。

不在 Readme 写安装命令、逐步运行教程、续跑方法、附件文件名清单、日志/缓存目录说明、日期和验证记录、哈希、容差、耗时或制作过程。程序参数可通过程序自身的帮助查看，内部运行方法写在包外工作记录。

不使用“不用复算图冒充原图”“不以简化代码为由删除约束”“原有某格式不交付”“不是外部数据”等防御性表达。对应的正确处理动作仍须执行，毋须在交付说明中宣告。

使用 [简短模板](assets/Readme-template.txt)，填写后删除占位符。

## 执行流程

先读 [制作细则](references/workflow.md)，验收时读 [验收说明](references/verification.md)。用户已经明确范围、命名和格式时直接执行，不重复询问。

### 1. 内部盘点

读取题面、输入、论文入口和全部计算程序，建立依赖及论文图表顺序。逐表登记表号、标题、位置与行列规模，不遗漏长表、续表和附录表。原文件到交付程序的映射只存包外。旧稿和废弃试验逐项判定，正式方案及论证所需的代码不遗漏。

```text
python "<本技能目录>/scripts/audit_package.py" inventory --project "<项目根目录>" --exclude "<支撑材料目录>"
```

盘点输出只是候选清单，需要人工确认。论文版本不一致时先确认实际交付版；未确认的差异留在内部记录，不向材料塞多版对照文件。

### 2. 代码整理

按真实依赖划分少量功能 PY，命名清楚，必要时使用公共函数和 `run_all.py`。提供 `requirements.txt`；保留主入口、输入参数和失败检查，不依赖旧内核、个人路径、私有技能或未交付数据。

用户本轮显式调用 `$math-modeling-code-simplifier` 时，可按其最新主文与必读参考协作，并遵守它的触发和命名协商要求；本技能的提及不构成用户调用。未调用时按本技能精简。协作时不将范围降为只有核心求解，绘图和全部必要实验仍保留。

运行时把日志、模型、中间表、诊断和补充图片写到包外工作目录。Figures 只发布论文图表及答题结果；答题结果使用文件复制，不经过二次 DataFrame 导出或样式加工。重跑同样遵守此规则。

### 3. 归集与脱敏

```text
支撑材料/
  Code/
    01_preprocess.py
    02_problem1.py
    ...
    run_all.py
    requirements.txt
  Figures/
    paper_figures/
      01.png
      02.png
      ...
    paper_tables/
      01_表格标题.xlsx
      02_表格标题.xlsx
      ...
    results/
      problem_1_results/
      problem_2_results/
      problem_3_results/
  User_data/
  Readme.txt
```

结果目录不分 reference/reproduced 或按过程再嵌套目录。结果保留程序原有工作表、字段和格式；新提取的论文表采用中文标题，保留原数学记号、单位和显示精度，不做额外美化。主图按正文顺序编号；图片脱敏检查像素，结果文件复制检查字节，两者不能混用。

### 4. 内部验证

从原始数据完整执行程序，含绘图和全部实验；检查语法、依赖、唯一键、记录数、离散决策、浮点容差、约束、实验覆盖、图像像素/DPI/字体与代表图。不得删断言或缩实验以制造成功。

使用 [内部清单示例](assets/manifest-example.json)，将清单、日志和验证证据放入独立审核目录，然后运行：

```text
python "<本技能目录>/scripts/audit_package.py" check --project "<原项目根目录>" --package "<支撑材料目录>" --audit-dir "<包外审核目录>"
```

审核工具不运行模型，也不独立证明论文覆盖和数学正确性；实际运行与人工核对仍必需。隐私扫描结合已知个人词和通用路径模式，图像可见文字与未支持的二进制元数据要另行检查。

### 5. 交付前确认

- 目录符合四项根目录、Figures 三目录和按题号结果目录要求。
- 图片从 01 连续编号，图面内容完整。
- 论文全部表格已按正文逐表核对，包括长表、续表和附录表。
- 结果文件直接回答赛题，与程序输出字节一致，未改内容、结构、样式；没有另加过程文件、来源表或总索引。
- 全部相关 PY 保留，重跑只发布规定产物。
- 文本和文件元数据完成脱敏，无原制作目录和来源字眼。
- Readme 只有简短目录介绍和运行环境。
- 实跑、数值和图形检查已在包外记录；用户禁止子代理时不调用子代理。

最终简短提供材料和技能的链接，说明实际变化及验证范围；不将内部记录混入交付文件，不自动发布或修改论文。
