# Math Modeling：模型与方法选择

## 概述
- 本 skill 用于数模题目的“模型和方法选择”，核心目标是先判断题型，再给出该题型下常见可选方法清单。
- 面对新题或尚未确定方法时，优先调用 `math-modeling-brainstorm`，先把题意、输入输出、目标和约束边界对齐。该调用的最少输入是题面、已有数据/变量、每个小问和已知限制；最少输出是每个小问的目标、输入、输出、约束、数据依赖结构和待确认项。若该 skill 不可用，当前代理必须在本轮直接完成同一份最少信息表，不能因此中断路由；模型已确定、用户只需要检验路由时，不重复启动题型头脑风暴。
- 本 skill 负责“题型/结构识别 + 候选方法路由 + 公式入口 + 初始参数建议 + 验证路线 + 模型检验路由”；具体代码、长教程和最终超参数由后续参考文档或专门代码 SKILL 承担。
- 对机理模型和智能优化必须区分三类参数：模型/决策参数、智能算法超参数、数值求解参数；推荐值不等于用户确认值，实际运行值必须单独记录。

## 章节正文与 PDF 截图的证据优先级

- 当章节正文的修正版、复算结果与 PDF 截图中的旧公式或旧数值冲突时，以当前正文和可复算结果为准。
- 截图只能作为结构和原始示例的辅助证据；不得直接复制与方程、参数、人数规模、坐标量级或下标不一致的旧截图结论。
- 发现冲突时，必须重新代入公式检查单位、边界条件、时间点和量级，并在输出中说明“截图旧示例已被正文/复算修正”。
- 结构风格对齐 `math-modeling-paper-writing`：采用一个主入口 `SKILL.md` + 多个分类参考文档的路由方式。

## 什么时候优先用本 skill
- 用户还没确定具体算法，只是在问“这题应该走哪类模型/方法”。
- 用户给出题面后，希望先判断题型，再查看该题型下常见候选方法。
- 用户已经知道自己在做评价、优化、预测、关联规则分析等题型，但想先缩小方法选择空间。
- 用户需要的是“方法地图”和“类别分界线”，而不是立刻写目标函数、代码或论文正文。
- 用户已经建立候选模型，想判断应做误差分析、残差诊断、交叉验证、灵敏度分析还是稳健性检验。

## 使用边界
- 适用场景：
  - 用户问“这题该选什么模型 / 方法？”
  - 用户给出题面后，希望先判断题型再看可选方法
  - 用户已经知道自己在做评价、优化、预测等题型，想快速浏览候选方法
  - 用户已经确定模型，但需要确定模型检验类别、证据要求或后续参考文档
- 不适用场景：
  - 已经明确某个具体方法，只需要建立目标函数或约束条件
  - 已经完成方法选择，只想写论文、写代码或做评委复核，且不需要设计或解释模型检验

## 模型检验路由

模型检验不是第十类题型，而是在模型或候选路线明确后，用来检查“结果是否可信、对什么因素敏感、在合理变化下结论是否保持”的跨题型环节。先说明待支持的主张、可用参照数据/基准、数据结构和可接受变化范围，再决定读哪个参考文档。

| 用户目标或问题结构 | 首选检验路线 | 参考文档 |
|---|---|---|
| 有观测值、预测值或拟合值，需要解释偏差和异常样本 | 误差分析与残差诊断 | [error-and-residual-diagnostics.md](references/validation/error-and-residual-diagnostics.md) |
| 需要估计新样本或未来数据上的表现，或比较复杂度 | 泛化评估、交叉验证、学习曲线 | [generalization-diagnostics.md](references/validation/generalization-diagnostics.md) |
| 需要判断输入、模型参数或数值配置对输出影响 | 局部或全局灵敏度分析 | [sensitivity-analysis.md](references/validation/sensitivity-analysis.md) |
| 需要检查结论是否依赖样本、变量定义、模型设定、噪声或处理方式 | 稳健性检验 | [robustness-checks.md](references/validation/robustness-checks.md) |
| 评价模型的权重、标准化、指标/对象增删、GRA/FCE 参数或排名是否稳定 | 通用稳健性规则 + 评价类专属检查 | [evaluation-robustness.md](references/01-evaluation/evaluation-robustness.md) |

### 模型检验的最少判断问题

- 要支持的主张是什么：预测误差、排名、推荐方案、参数方向、机理轨迹、可行性还是最优性？
- 是否有独立观测、基准模型、已知最优界或物理/逻辑约束可作为参照？
- 数据是否具有时间、群组、空间或重复测量结构？这些结构决定能否随机划分或逐行重抽样。
- 改变的是输入数据、模型参数、算法超参数、数值求解配置，还是模型假设/样本/变量定义？
- 输出观察量是什么：单点、全轨迹、峰值、累计量、误差、排名、目标值、可行率或结论方向？
- 扰动范围、方法替换和可接受变化的依据是什么？不得把 10%、20% 或单一误差阈值当作通用标准。

- 模型与题型：
- 参照数据/基准/约束：
- 数据依赖结构：
- 检验类别：
- 改变的对象及范围：
- 固定的条件：

不要强制所有模型同时进行误差、泛化、灵敏度和稳健性检验。预测模型通常需要样本外误差；纯确定性优化优先报告可行性、上下界或最优性 gap；机理模型还要报告量纲、守恒、非负性、边界和数值精度；分类与聚类使用各自专属指标。

## 优化类二级路由

仅当 `primary type=优化类` 时，先判断问题结构，再选择精确求解、动态规划、图算法或智能优化。不要因为题目出现“最优”就直接使用 GA、PSO、SA、DE 或 ACO。

```text
优化类
├── 连续 + 线性 → LP
├── 整数/0-1 + 线性 → IP / MILP / CP-SAT
├── 连续与整数混合 + 非线性 → MINLP（先判断凸性与可用求解器）
├── 多个冲突目标 → 加权和 / ε-约束 / Pareto 算法
├── 非线性目标或约束
│   ├── 凸 NLP → 凸求解器或满足条件的局部求解器
│   ├── 非凸 NLP → 多起点、全局求解器或混合方法
│   └── 黑箱连续优化 → PSO / DE / SA 等
├── 多阶段状态转移 → DP
├── 节点/边/路径/流量
│   ├── 只求静态最短路/最大流/匹配 → 路由至 references/07-graph-and-path/
│   └── 需要构造完整巡回/车辆路径/路径序列 → 先比较 MILP / CP-SAT / DP，再考虑 ACO
└── 离散组合/排列/复杂逻辑
    ├── 能建成 IP / MILP / CP-SAT / DP / 图算法 → 先比较精确方法
    ├── 路径构建型离散优化 → ACO / GA / SA
    └── 精确方法不可行、规模过大或目标为黑箱 → GA / SA；连续实值搜索 → PSO / DE
```

ACO 主要适合逐步构造路径、排列或组合解；连续 ACO 变体存在，因此不能把“ACO 不支持连续变量”写成绝对规则，但使用连续变体时必须明确其变体和概率模型。纯静态最短路不应为了使用 ACO 而替代 Dijkstra、Bellman-Ford、Floyd 或其他适用的图算法。

### 优化路由的最少判断问题

- 决策变量是连续、整数、0-1、排列，还是混合变量？边界和单位是什么？
- 目标是最大化还是最小化？是否有多个互相冲突的目标？
- 目标函数和约束是否线性？是否可导？是否可以判断凸性？
- 是否存在等式、容量、逻辑、时间窗、互斥或覆盖约束？
- 是否有明显的阶段、状态转移、节点、边、路径或流量结构？
- 若考虑 GA/PSO/SA，编码/适应度方向、速度与位置边界、拓扑、初温校准、链长、接受率和停滞终止如何定义？
- 若考虑 ACO，解是否能逐步构造成路径/排列/组合？图是有向还是无向？启发式信息、信息素更新和不可行路径修复如何定义？
- 是否要求精确最优，还是接受近似解？是否有运行时间限制？
- 结果必须具备什么证据：求解器最优状态、MIP gap、上下界、可行性残差，还是多随机种子稳定性？
- 目标函数参数来自固定规则，还是来自数据拟合、预测模型或情景数据？

### 优化类核心公式入口

主 SKILL 只保留公式入口，详细推导进入 `references/02-optimization/`：

```text
LP：min cᵀx，Ax≤b，A_eq x=b_eq，l≤x≤u
IP / MILP：LP + x_j∈Z 或 x_j∈{0,1}；混合整数变量允许连续变量与整数变量并存
MINLP：min f(x,z)，s.t. g(x,z)≤0，h(x,z)=0，x 连续，z 整数/0-1
MOP：min Σ w_j f̃_j(x)，或 min f_1(x) s.t. f_j(x)≤ε_j
NLP：min f(x) s.t. g_i(x)≤0，h_j(x)=0，l≤x≤u
DP：V_t(s)=min_a { c_t(s,a)+V_{t+1}(T(s,a)) }
GA：先统一最大化/最小化口径；轮盘赌只对非负适应度使用，最小化目标需先转换为适应度（如 `1/(g+ε)` 或排序适应度），不能直接用 `fᵢ/Σfⱼ`。
PSO：vᵢᵗ⁺¹=ωvᵢᵗ+c₁r₁(pBestᵢ-xᵢᵗ)+c₂r₂(gBest-xᵢᵗ)；再按 `vmax` 截断速度、按变量边界修复位置，并明确 gBest/lBest 拓扑和停滞检测。
SA：坏解接受概率 p=exp(-Δ/T)，最大化/最小化口径必须先统一；`T0` 应由目标接受率校准，`chain_length`、降温率、接受率和无改进终止条件必须记录。
DE：vᵢᵗ⁺¹=xᵣ₁ᵗ+F(xᵣ₂ᵗ-xᵣ₃ᵗ)，再以交叉规则生成试验向量并与 xᵢᵗ 比较保留
ACO：Pᵢⱼ⁽ᵏ⁾=τᵢⱼ^αηᵢⱼ^β / Σₗ∈Cᵢ⁽ᵏ⁾ τᵢₗ^αηᵢₗ^β；τᵢⱼ←(1−ρ)τᵢⱼ+Σₖ(Q/Lₖ)·1{(i,j)∈Pₖ}
```

### 优化类推荐工作流

1. 调用 `math-modeling-brainstorm`，抽取决策变量、目标、约束、数据来源和小问关系。
2. 先检查单位、变量域、目标方向、约束方向和可行性，不要先写算法。
3. 按 LP/IP/MILP/CP-SAT/MINLP/MOP/NLP/DP/图论/黑箱结构路由；若存在可行的精确方法，必须先比较其适用性、规模和最优性证据，再决定是否进入智能优化（包括 ACO）。
4. 建立 Baseline：LP 松弛、最近邻、贪心、单起点或随机可行解等。
5. 输出首选与备选方法、适用边界、推荐初始参数和风险，等待用户确认主路线。
6. 若进入智能优化，转交 `math-modeling-intelligent-optimization-coder`；本 SKILL 只交付模型结构和参数候选。若选择 ACO，还要交付图表示、路径构造、启发式信息和信息素更新口径。
7. 求解后必须复算目标值、约束违反量、变量域和求解状态。
8. 精确方法报告最优性证据；启发式方法报告多随机种子、收敛、可行率、运行时间和稳定性。

### 优化问题的数据划分规则

- 纯确定性 LP/IP/MOP/NLP/DP/图算法：模型参数固定时，不强行套训练集/验证集/测试集；应使用可行性、最优性和敏感性分析。
- 目标函数或约束参数来自数据拟合、预测模型或代理模型：按照数据驱动任务划分训练/验证/测试。
- 使用 PSO、GA、SA、DE、ACO 等搜索模型参数或超参数时，适应度只能使用训练内部验证信息；测试数据只能在参数锁定后最终使用一次。
- ODE/差分方程参数辨识属于数据驱动拟合时，按时间段、实验批次或其他独立组划分训练/验证/测试；纯确定性仿真且没有观测拟合时，不强行创建数据集划分。
- “多随机种子”是随机算法稳定性实验，不等同于验证集。

### 超参数与求解配置的用户确认协议

- SKILL 可以根据问题结构给出“推荐初始值/候选范围/调参顺序”，但不得把推荐值默认为用户最终方案。
- 任何进入代码或正式实验的 `population_size`、`max_iter`、`c1/c2`、`omega`、PSO 的 `vmax`/位置边界修复/拓扑/停滞阈值、`T0`、`cooling_rate`、`chain_length`/初始接受率目标、`mutation_rate`、DE 的 `strategy`/`popsize`/`mutation`/`recombination`/`tol`、ACO 的 `alpha`/`beta`/`rho`/`Q`/`ant_count`/`tau0`/`candidate_list`/`q0`/`tau_min`/`tau_max`/信息素更新策略、`penalty_weight`、`MIPGap`、`TimeLimit` 等参数，都必须标记为“推荐值”或“用户确认值”。
- ODE/参数辨识还必须分别记录模型参数初值与上下界、损失函数权重，以及数值求解器 `method`、`rtol`、`atol`、`max_step`/步长和事件处理设置；这些不能被算法超参数表掩盖。
- 若用户未确认，先展示参数表和影响说明；只有用户确认后，才进入代码、实验或论文结果。
- 若用户要求自动调参，必须先确认搜索范围、预算、评价指标、随机种子和早停规则；自动搜索结果仍需回报给用户确认。

## 机理分析类二级路由

仅当 `primary type=机理分析类` 时，先判断时间、空间和状态结构，再决定使用 ODE、差分方程、PDE、DAE 或守恒/动力学模型。不要因为题目出现“变化规律”就直接套微分方程，也不要把数值求解器参数误写成模型机理参数。

```text
机理分析类
├── 连续时间、有限维状态演化 → ODE
├── 离散时刻逐期演化 → 差分方程
├── 时间 + 空间连续变化 → PDE
├── 微分关系 + 代数约束 → DAE
├── 质量/能量/流量守恒 → 守恒关系模型
├── 已知方程结构但参数未知 → 参数辨识 / 数据校准
└── 方程已知、只需运行情景 → 路由至仿真模拟类
```

### 机理分析触发后的最少判断问题

- 因变量是连续时间、离散时间，还是同时包含空间变量？
- 状态变量、控制变量、参数和观测量分别是什么？单位是否一致？
- 方程来自守恒律、经验关系、动力学假设还是数据拟合？
- 初始条件、边界条件、事件条件和参数范围是什么？
- 参数是已知常数，还是需要由观测数据辨识？观测误差如何处理？
- 数值问题是否可能刚性？需要显式方法、自适应步长还是隐式方法？
- 是否保留独立时间段、实验批次或情景用于验证？

### 机理分析核心公式入口

详细推导和操作步骤进入 `references/05-mechanism-analysis/`：

```text

Euler：yₙ₊₁ = yₙ + h f(tₙ, yₙ, θ)
参数辨识：θ^ = argmin_θ Σᵢ wᵢ ||y(tᵢ;θ) - yᵢ_obs||²
```

### 机理分析推荐工作流

1. 调用 `math-modeling-brainstorm`，明确状态、输入、输出、单位和小问关系。
2. 写出可检验的基本假设，检查守恒关系、量纲和符号方向。
3. 建立微分/差分/偏微分或代数约束方程，并明确初始/边界条件。

### 经验阈值的使用规则

- `T<20`、`T=50~500`、`T>200`、`n=4~20`、`|a|<0.3` 等只能作为候选模型的经验起点，不能作为自动淘汰模型的绝对边界。

- 小样本可以优先尝试 GM(1,1)，但必须用留出点、滚动验证或敏感性分析检查其预测稳定性。

- 固定方法、没有模型比较或调参时，训练集+测试集可以满足一次最终评估；不要为了形式强行增加验证集。

- 无监督执行流程：读取 `references/04-classification-and-recognition/unsupervised-clustering-workflow.md`。
- 评价、稳定性和报告：读取 `references/04-classification-and-recognition/classification-clustering-validation.md`。
- 具体模型：再进入 `有监督分类/` 或现有目录名为 `无监督分类/` 的聚类参考目录下对应的 md；不要为了一个问题一次性展开所有方法。

## 评价类二级路由
仅当 `primary type=评价类` 时，继续判断 `method subtype`，不要把赋权、排序、分级、接近度和稳健性验证当成同一层的单层竞争方法。

- 如果目标是确定指标重要性：
  - 有专家判断或主观偏好：AHP。
  - 纯数据驱动：熵权法、CRITIC、变异系数法。
- 如果目标是给多个方案排序：
  - 指标清晰、需要数值排名：TOPSIS。
  - 样本较少、强调与参考序列接近：灰色关联分析（GRA）。
- 如果目标是输出“优 / 良 / 中 / 差”等等级：
  - 评价边界模糊：模糊综合评价（FCE）。
- 如果已经得到候选结果、需要检查结论是否稳定：
  - method subtype：稳健性验证；先读取通用模型检验索引，再读取评价稳健性专属文档。
- 如果需要同时考虑主观和客观：
  - 可采用 AHP + 熵权法或 AHP + CRITIC 形成组合权重。
  - 再根据输出目标接 TOPSIS、FCE 或 GRA。

评价类方法的层级关系为：

```text
评价指标体系
    ↓
赋权层：AHP / 熵权法 / CRITIC / 变异系数法
    ↓
综合评价层：TOPSIS / 模糊综合评价 / GRA
    ↓
稳健性验证：权重敏感性 / 参数敏感性 / 方法对照 / 排名稳定性
```

## 使用规则
- 若题型明确，只读取对应分类的一个 `index.md`，不要把 9 类全部展开。
- 若题型不明确，先要求用户澄清属于哪类问题，或先根据题面做分类判断，再让用户确认。
- 先给“候选方法清单 + 适用边界”，不要在信息不足时断言“唯一最优方法”。用户明确要求深入执行时，再读取对应工作流、验证和具体方法参考文档。
- 若多个类别都可能适用，优先说明这些类别的分界线，而不是直接跳到具体算法。
- 具体公式、超参数、验证方案和常见错误必须以对应参考文档为准，不要在根 SKILL 中重复维护长公式。
- 若用户后续希望补某个具体方法的详细文档，可在对应分类文件夹下继续新增方法 md 文档，并在相应 `index.md` 与本入口中建立可达链接。

## 用户路线确认
当输出多个候选主模型后，如果下一步将进入代码、实验或论文写作，必须让用户确认主路线。

用户只需要明确选择主模型或路线编号，不需要说明为什么不用备选方案。

备选方案的不选理由由本 skill 在候选比较阶段给出。

## 推荐工作流程
1. 先调用 `math-modeling-brainstorm`，抽取题目的目标、输入、输出、约束和小问关系。
2. 识别题型；若不确定，先与用户确认类别。
3. 读取对应分类 `index.md`。
4. 若属于分类识别类，继续读取分类/聚类方法选择参考，并确定 `method subtype`。
5. 若属于预测类，继续读取预测选择参考，确定预测对象、预测步长、时间验证方案和 `method subtype`。
6. 若属于优化类，继续执行优化二级路由，区分精确方法、图算法、动态规划和智能优化，并输出可行性/最优性验证要求。
7. 若属于机理分析类，继续执行 ODE/差分方程/PDE/DAE/参数辨识二级路由，并输出方程、条件、参数类别和数值验证要求。
8. 模型已经确定且用户需要检验时，读取 `references/validation/index.md`，再按误差与残差、泛化、灵敏度或稳健性进入对应参考文档；评价类还需进入 `references/01-evaluation/evaluation-robustness.md`。若用户要求实际运行检验，当前执行代理负责在可用的数据和代码环境中执行所选实验、复算结果并回传证据；不能把执行任务交给一个未声明的“模型检验 skill”。
9. 输出该分类下的候选方法清单、适用边界和易混点；若用户要求可执行方案，再读取对应工作流和验证参考文档。
10. 只有在用户确认主路线后，才进入具体模型参考文档、代码、实验或论文写作。

## 与其他 SKILL 的职责边界

本 skill 负责“题型识别、方法选择、方法适用边界、公式入口、初始超参数和验证路线”。它可以把下一步交给其他 SKILL，但不重复承担其他 SKILL 的完整工作流：

```text
数据预处理 SKILL
→ 缺失值、异常值、编码、标准化、数据划分和防数据泄漏

模型与方法选择 SKILL（本 skill）
→ 预测/分类/聚类类型判断、候选方法、公式入口、适用范围、初始超参数、验证方案和模型检验路由

超参数调优 SKILL
→ 网格搜索、随机搜索、贝叶斯优化、实验记录、早停和参数对比

数学建模智能优化算法 SKILL
→ GA/PSO/SA/DE/ACO 的代码生成、算法专属提问、参数候选范围、用户确认和实现验证

机理模型参考文档 / 数值求解代码
→ ODE、差分方程、参数辨识的方程细节、求解器选择、误差诊断和独立验证；若使用智能算法标定参数，再交给智能优化 SKILL

模型检验参考文档
→ 误差与残差诊断、泛化评估、局部/全局灵敏度和跨题型稳健性设计；用户要求实际检验时，由当前执行代理在可用代码环境中运行实验、复算指标并交付证据，不替代分类、聚类、优化或机理模型的专属验证证据

画图 SKILL
→ 混淆矩阵、ROC/PR 曲线、特征重要性、肘部图、轮廓图、树状图、时序图、ACF/PACF、残差图和预测区间图

论文写作 SKILL
→ 模型假设、公式排版、结果解释、方法对比和论文段落组织
```

如果分类/聚类参考文档中出现“标准化、编码、划分或作图”，只说明该步骤的接口和风险，并把具体执行交给对应 SKILL，避免重复维护同一套规则。

## 常见错误
- 还没判断题型，就直接套具体算法。
- 把“评价类”与“统计分析类”混为一谈。
- 把“优化类”与“预测类”混为一谈，只因为两者都能输出数值。
- 看到“最优”就直接使用 GA、PSO、SA、DE 或 ACO，不先检查 LP/IP/MILP/CP-SAT/MINLP/DP/图算法等精确方法是否适用。
- 把 LP 松弛解四舍五入当作整数规划解，或只看目标值而不检查约束违反量。
- 把推荐超参数当成用户已经确认的最终参数，或用测试数据自动选择优化参数。
- 把启发式算法的收敛曲线当成全局最优证明，不报告随机种子、可行率、上下界或最优性 gap。
- 把 ACO 的信息素浓度当成最优性证明，不报告路径可行率、重复蒸发风险、候选集/修复规则和多随机种子稳定性。
- 把纯静态最短路直接交给 ACO，或把 ACO 只能用于离散问题写成无条件规则；应先区分图算法、路径构建优化和连续 ACO 变体。
- 把 ODE 的模型参数、智能算法超参数和数值求解器参数混在一张表中，导致拟合结果无法复现。
- 把 Euler 的教学演示、旧截图中的曲线或单次拟合误差当成独立验证；必须检查步长稳定性、单位、初边界条件和独立数据。
- 把横截面回归和时间序列预测混为一谈；有时间顺序的数据不能直接使用随机划分。
- 把预测步长、外生变量未来可得性和季节周期留空，却直接选择 ARIMA、LSTM 或回归模型。
- 用测试集选择模型、调参或早停，或者把未来外生变量真实值带入预测。
- 把训练集拟合优度、单次 AIC/BIC 或单次留出误差当成最终预测能力证明。
- 把训练残差与独立预测误差混为一谈，或用一次测试集结果反复选择模型、阈值、变量和超参数。
- 把单因素参数扰动直接称为结构性稳健性，或用局部灵敏度排名宣布参数在所有情景下最重要。
- 用百分比扰动处理零值附近、摄氏温度、循环时段或类别变量，却不说明变量尺度和情景含义。
- 把模型输入扰动、重新训练后的流程稳定性与现实因果影响混为一谈。
- 只写“结果稳定”，却不报告改变对象、变化范围、固定条件、评价指标和可接受变化的依据。
- 看到路径 / 网络 / 调度词汇就直接上图论，不先判断目标是否其实是优化。
- 看到数据就直接回归，不先判断题目是否其实要求评价、分类或机理解释。
- 看到购物篮数据、共现数据或事务型数据，却直接套聚类或回归，不先判断是否其实是关联规则分析。
