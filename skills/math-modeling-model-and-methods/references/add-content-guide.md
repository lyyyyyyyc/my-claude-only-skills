# 为 `math-modeling-model-and-methods` 新增内容的维护指南

## 用途
这份文档是给 Codex 在后续继续扩展 `math-modeling-model-and-methods` 时使用的操作规程。以后如果需要继续往这个 skill 里新增触发词、补充题型分类、扩展路由规则、追加某类方法说明或修正常见误用，优先先读这份文档，再决定改哪里、怎么改。

## 什么时候应该新增内容
以下情况适合继续新增到这个 skill：
- 出现新的高频用户表达，导致当前 `description` 或 `when_to_use` 覆盖不足。
- 需要补新的题型边界说明，例如两个类别之间的分界线更清晰了。
- 需要新增某一类方法的路由入口，或补充现有分类的索引说明。
- 需要补新的“常见混淆点”或“候选方法缩小策略”。

以下情况通常不应该直接加到这个 skill：
- 某一个具体方法的详细做法、公式、参数技巧。
- 某一次会话的临时分类口径。
- 已经明确属于其他数模 skill 的内容，例如目标函数、约束、代码或论文写作细节。
- 低频、一次性、过长的说明性内容，尤其是不影响主触发逻辑的材料。

## 新内容应该加到哪里
新增内容时，先判断它属于哪一类，再放到对应区块：

| 新增内容类型 | 应放位置 |
|---|---|
| 触发相关话术、何时应该调用本 skill | frontmatter 的 `description` / `when_to_use` |
| 适用场景和边界 | `什么时候优先用本 skill` / `使用边界` |
| 题型总分类本身 | `分类体系` |
| 各类 references 索引入口 | `路由表` |
| 跨题型的模型检验入口 | 主 `SKILL.md` 的 `模型检验路由` 和 `references/validation/` |
| 如何使用候选清单、不该直接跳算法 | `使用规则` / `推荐工作流程` |
| 常见误用、类别混淆 | `常见错误` |
| 低频、长说明、维护导向内容 | `references/` |

## 新增内容的判断流程
以后新增内容时，按下面顺序判断：

1. 先判断这是“触发优化”还是“题型/路由扩展”。
2. 再判断它是“通用规则”还是“某个具体方法的细节”。
3. 如果是通用规则，优先补进主 `SKILL.md` 的已有区块。
4. 如果只是某个方法的详细说明，优先新增到对应分类目录下的 `references/*.md`，不要塞回主 `SKILL.md`。
5. 如果内容是跨题型的误差、泛化、灵敏度或稳健性规则，优先新增到 `references/validation/`；评价权重、排序、GRA/FCE 等专属规则仍保留在 `references/01-evaluation/evaluation-robustness.md`。
6. 如果会改变触发边界，必须同步检查 `description` 和 `when_to_use`。
7. 如果只是低频长说明，优先放进 `references/`，主文只留短入口。

## 截图补充内容的处理规则
- 如果新增内容来自用户截图，只采纳能够明确辨认的文字、标题、表格字段、公式结构和层级关系。
- 任何模糊、遮挡、截断、分辨率不足或存在歧义的内容，都必须先标成“待用户确认”，不能靠上下文自行补全。
- 如果同一张截图里一部分清楚、一部分不清楚，先拆成“可确认内容”和“待确认内容”，不要把两者混写。
- 未经用户确认，不把不确定内容写入正式文档，包括 `SKILL.md` 和 `references/` 下的任何 md 文件。
- 如果截图来自拍照、手写笔记、PPT 局部截取或压缩图片，默认采用更保守的处理口径：宁可少写，也不臆造。

## 写法规范
- 保持本 skill 的定位是“先判断题型，再给候选方法清单”，不要写成完整方法教程。
- 解释“为什么这样分流”，不要只堆“必须”。
- 新规则尽量短，优先归入现有区块，不轻易新开大区块。
- 不写一次性案例总结，不写叙事式历史。
- 如果某个说明很长，优先新增到对应分类 `references/` 下，而不是压重主文。

## 修改前检查清单
- 这条内容是否真的是高频、可复用规则。
- 是否会影响当前 skill 的触发边界。
- 是否和已有区块重复。
- 是否本来应该属于某个具体分类 references 文档。
- 是否需要同步更新 `description` 或 `when_to_use`。
- 如果内容来自截图，是否已经把所有看不清或不确定的地方单独标出。

## 修改后检查清单
- 主 `SKILL.md` 是否仍然保持“主入口 + 分类 references 路由”的结构。
- frontmatter 是否已同步更新。
- 新内容是否放在了正确层级。
- 是否引入新的重复表述。
- 是否仍然坚持“只给候选方法清单，不直接展开完整教程”的定位。
- 是否把未经确认的截图内容误写进正式文档。

## 常见错误
- 还没判断题型，就把具体算法直接塞进主 skill。
- 把某一个方法的详细教程写回主 `SKILL.md`。
- 为了增加覆盖面，把所有分类一股脑展开，导致主文过重。
- 增加内容后不检查 `description` / `when_to_use`。
- 把一次性任务要求写成永久分类规则。

## 建议回归测试提示词
- “这题该选什么模型，你先判断属于评价还是优化。”
- “我不知道这道题该走哪类方法，先给我候选方法路线。”
- “先别上具体算法，先帮我判断题型和方法地图。”
