# 重复值处理

> 用途：当用户已经进入“数据预处理”阶段，并且想进一步判断“重复记录怎么处理”“整行重复和字段冲突该怎么区分”“删掉重复值后如何衔接后续处理”时，读取本文件。
>
> 说明：本文件重点整理重复值识别、删重规则，以及与缺失值处理的衔接方式。

## 这份文档适合什么时候看

- 你发现数据表中有重复记录、重复样本或重复编号。
- 你需要决定哪些重复是完全重复，哪些重复是冲突记录。
- 你想把“删重”和“缺失值处理”纳入同一个预处理流程。

## 一句话先判断处理思路

- **如果是完全重复的记录，优先直接删重。**
- **如果是同一对象的多条记录但字段冲突，先删去冲突重复值，再把空出来的位置当作缺失值继续处理。**

## 1. 先把重复值想成什么

重复值通常分两类：

1. **完全重复**：一整行内容都相同。
2. **部分重复 / 冲突重复**：主键相同，但部分字段不同。

前者更像是数据拷贝或录入重复；  
后者更像是多次记录、冲突记录或信息覆盖不一致。

## 2. 默认处理口径

你这次给出的要求是：

- **直接删掉，然后再当作缺失值去处理。**

把它整理成可执行流程后，可以写成：

1. 先识别重复记录；
2. 对完全重复记录直接保留一条、删除其余条；
3. 对部分重复或冲突重复，删除冲突项后把无法确定的字段位置记为缺失；
4. 再转入 `missing-value-handling.md` 继续处理。

因此，这里的重点不是“重复值处理独立完成”，而是：

- **重复值先清，再和缺失值处理流程衔接。**

## 3. 什么时候直接删重

- 记录完全一致；
- 删除不会损失额外信息；
- 重复只是简单冗余。

## 4. 什么时候要转成缺失再处理

- 主键相同但字段不一致；
- 无法判断哪条记录是真值；
- 保留冲突字段会让模型误读。

此时更稳妥的做法是：

- 删除冲突重复值；
- 把无法确认的字段留空；
- 再按缺失值处理流程继续补全或筛选。

## 5. 一个论文里可直接使用的表述

> 针对原始数据中的重复记录，本文先按主键与字段内容进行一致性核查。对于完全重复记录，直接删除冗余项，仅保留一条有效记录；对于主键相同但字段值不一致的冲突重复记录，则先删除不可靠重复值，并将无法确认真值的字段记为缺失项，随后统一并入缺失值处理流程，以保证后续建模样本的一致性与可复核性。

## 小结

重复值处理可以概括成一句话：

- **先删重，再把删重后无法确定的冲突位置视作缺失，继续交给缺失值处理模块。**
