# 评价类方法选择总结

## 这份文档是干什么的
- 这不是某一个具体方法的教程，而是评价类问题里常见方法的“选型对比表”和总结。
- 适合在你已经知道题目属于评价类之后，进一步判断应该优先考虑哪种方法。
- 重点不是把所有方法都用一遍，而是根据题目数据类型、数据量、是否需要主观判断、是否需要排序或权重，先缩小方法选择范围。

## 评价类问题的共性
1. 评价只能在已有对象中寻找最优，不能凭空创造新对象。
2. 指标不能太多，指标一多，每个指标的分辨力和权重区分度就会下降；必要时可先分层再评价。
3. 主观性太高不易服人，过于客观又可能忽略指标本身的重要程度。
4. 评价类问题通常对数据分布没有特别严格的假设，更关注数据的相对关系、差异性和变异性。

## 评价类方法适用对比

### 层次分析法 AHP
- 优点：
  - 简洁实用，能把定性与定量方法结合起来。
  - 所需的定量数据信息相对较少。
  - 适合处理多目标、多准则决策中的主观赋权问题。
- 缺点：
  - 主观性较高，不易令人信服。
  - 不适用于大量指标的情况。
  - 当客观数据已经较充分时，不容易给出强数据驱动的说明。
- 适用情况：
  - 定性 + 定量指标并存。
  - 数据量较小。
  - 决策变量较少、层次分明的多指标决策问题。
  - 适合影响因素不太多的主观场景，例如政策评估、项目选择、景点选择、商品选购等。

### TOPSIS
- 优点：
  - 大样本和小样本都适用。
  - 相比纯主观判断，能避免较多主观性和复杂的人为打分过程。
  - 能直接基于已有客观数据判断各方案优劣，计算流程相对简洁。
- 缺点：
  - 需要每个指标都有数据，且部分指标的量化和最优值选取有一定难度。
  - 受极端值影响较大，较依赖归一化处理。
  - 对新出现的外部情况适应性一般，且经典模型不显式处理指标交互作用。
- 适用情况：
  - 定量指标问题。
  - 数据量大小都可接受。
  - 指标清晰、数据精度较高的排序决策问题。
  - 例如供应商选择、绩效评估等。

### 熵权法
- 优点：
  - 完全客观，不受人为影响。
  - 主要用于确定多指标在综合评价中的权重。
- 缺点：
  - 忽略专家主观判断，容易忽略指标本身的重要程度。
  - 易受数据波动性不平衡影响。
  - 对数据误差和异常值较敏感。
- 适用情况：
  - 定量指标问题。
  - 数据量较大，部分经验做法会把 `m ≥ 5` 作为初筛参考，但不能视为硬性条件。
- 无法通过认知、文献或专家判断去确定因素重要程度时，可优先考虑。

### CRITIC
- 优点：
  - 同时考虑指标自身的对比强度和指标之间的冲突性。
  - 适合作为纯数据驱动的客观赋权方法。
- 缺点：
  - 依赖标准差和相关系数，容易受到异常值、样本量和高度相关指标影响。
  - 指标冲突性较强不一定代表指标在实际决策中更重要。
- 适用情况：
  - 希望客观赋权，同时避免只依据单个指标离散程度。
  - 指标之间存在一定差异和信息冲突，且能够进行可靠相关性计算。

### 变异系数法
- 优点：
  - 计算简单，能依据指标的相对离散程度进行客观赋权。
  - 适合正值、比率尺度且均值具有明确意义的指标。
- 缺点：
  - 均值接近 0 时结果会非常不稳定。
  - 均值为负或指标不满足比率尺度时，直接使用变异系数缺乏合理解释。
- 适用情况：
  - 希望用“相对波动程度”区分指标权重，而不引入专家判断。
  - 指标已完成方向统一，并且能够合理解释均值与标准差的比值。

### 模糊综合评价
- 优点：
  - 能通过精确的数字手段处理模糊的评价对象。
  - 能较好吸收模糊和不确定信息，使结果更平滑。
- 缺点：
  - 指定隶属函数时主观性较强，计算相对复杂。
  - 当指标过多时，容易出现区分度不足的问题。
- 适用情况：
  - 定性 + 定量指标并存。
  - 数据量较小。
  - 评价因素不确定，或天然具有模糊描述。
  - 常见于指标关系模糊、权重不易直接确定的场景。
  - 例如社会评价、风险分析等。

### 灰色关联分析
- 优点：
  - 对数据分布没有太高要求。
  - 不需要大量数据，结果通常较直观。
- 缺点：
  - 需要对各项指标的最优值进行先验确定，主观性过强时会影响结果。
  - 对指标绝对大小不够敏感，更强调相对接近性。
  - 更适合做关联接近度比较，不宜直接解释因果关系。
- 适用情况：
  - 定量指标问题。
  - 数据量较小。
  - 更适合相对变化比较、趋势分析类场景。
  - 也适合分析某一核心指标与多个因素之间的关联强弱并排序。
  - 例如经济指标关联分析等。

## 快速选型矩阵

### 按任务模块看
- 评价决策：
  - 可用：AHP、TOPSIS、模糊综合评价、灰色关联分析
  - 不优先：熵权法单独作为最终评价方法
- 权重计算：
  - 可用：AHP、熵权法、CRITIC、变异系数法
  - 一般不用：TOPSIS、模糊综合评价、灰色关联分析单独求权

### 按数据类型看
- 定性 + 定量：
  - 优先考虑：AHP、模糊综合评价
- 纯定量：
  - 优先考虑：TOPSIS、熵权法、灰色关联分析

### 按数据量看
- 数据量小：
  - 常见可用：AHP、模糊综合评价、灰色关联分析
- 数据量多：
  - 常见可用：TOPSIS、熵权法

这里的“数据量小 / 大”只用于方法初筛；`m ≥ 5`、`m ≥ 10` 等数字只能作为经验参考，不能写成适用于所有题目的绝对样本量标准。

### 按数据要求看
- 大多数评价类方法不依赖于大样本，但至少需要每个方案在每个指标上有完整数据，且各方案之间要有一定差异。

## 标准化方法怎么选
- 如果只是想消除量纲，让数据变成“均值为 0、标准差为 1”，可用 `Z-score` 标准化。
  - 更常见于机器学习前处理，不是评价模型本体。
- 如果既要统一量纲，又想把值压到 `0-1` 区间，常用极差标准化。
  - 常见于 TOPSIS、熵权法。
- 如果需要保留数据占比结构，使每一列和为 `1`，可用比例归一化。
  - 常见于层次分析法、熵权法的某些处理中。
- 如果更关注方向而不是绝对大小，可用向量归一化。
  - 常见于 TOPSIS、熵权法中计算欧氏距离或方向比较时。

## 方法选择建议
1. 先判断你的问题是“排序决策”还是“权重确定”。
2. 再看数据是“定量为主”还是“定性 + 定量混合”。
3. 再看数据量是偏小还是偏大。
4. 最后再决定是否需要主观判断：
   - 需要主观判断：优先看 AHP、模糊综合评价。
   - 希望客观赋权：根据数据特征比较熵权法、CRITIC 和变异系数法。
   - 重点是排序：优先看 TOPSIS、灰色关联分析。

## 方法分层与组合建议
评价方法不宜简单视为同一层的“五选一”，更合理的流程是：

```text
评价指标体系
    ↓
赋权层：AHP / 熵权法 / CRITIC / 变异系数法
    ↓
综合评价层：TOPSIS / 模糊综合评价 / GRA
    ↓
稳健性验证：权重敏感性 / 参数敏感性 / 方法对照 / 排名稳定性
```

常见组合包括：

- AHP + 熵权法或 AHP + CRITIC：同时保留主观判断和客观数据的信息。
- AHP + TOPSIS、熵权法 + TOPSIS 或 CRITIC + TOPSIS：先赋权，再进行数值排序。
- AHP + GRA、熵权法 + GRA：先赋权，再比较与参考序列的接近程度。
- AHP + 模糊综合评价或熵权法 + 模糊综合评价：先赋权，再输出模糊等级。
- 已有任一主路线后，先读取 [../validation/index.md](../validation/index.md)，再读取 [evaluation-robustness.md](evaluation-robustness.md) 做评价专属的敏感性和排名稳定性检查。

## 常见误区
- 评价类问题不是“方法越多越好”，而是“方法越贴题越好”。
- 不能把熵权法直接当成完整的评价决策方法，它更常承担“客观赋权”的角色。
- 不能把 AHP 当成万能方法；指标一多、主观性一强，可信度会下降。
- 不能把灰色关联分析当成纯综合评分法，它更强调和参考序列的接近程度。
- 不能把模糊综合评价用于完全清晰、完全可量化且边界明确的问题，否则会引入不必要的复杂度。
- 不能把 CRITIC 或变异系数法单独当作最终排序方法；它们首先是赋权方法。
- “客观赋权”只说明权重来自数据计算，不等于指标在现实决策中的实际重要性。
