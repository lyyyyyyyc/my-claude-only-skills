## 这份文档适合什么时候看

- 你已经判断题目和“节点、边、容量、输送、分配、通路、网络瓶颈”这些词强相关。
- 你怀疑题目本质是“在容量约束下，让总流量尽量大”。
- 你需要的不只是概念说明，而是想判断“最大流模型到底适不适合这题”。
- 你后面准备把最大流写进论文、写成代码，想先把基本结构和几种常见求解思路理顺。

## 一句话先判断它适不适合这题

- **如果题目核心是在一个有向容量网络里，让源点到汇点的总通过量尽量大，最大流通常就是第一候选。**
- **如果题目更像最短路、最低成本、路径最短、巡回访问，那通常不该优先套最大流。**
- **如果题目除了容量约束，还有复杂时序、调度、车辆路径或综合收益目标，往往要把图论和优化模型结合起来，而不是只用最大流。**

## 1. 先把最大流想成什么

最大流问题的核心不是“找一条最好走的路”，而是“在整个网络里安排流量，让源点到汇点的总输送量最大”。  
所以它处理的不是单条路径优劣，而是**整张网络的容量分配问题**。

更直白一点：

- 最短路关心“怎么走一条最便宜的路”；
- 最大流关心“整个网络总共能送多少”；
- 最小割则关心“卡住整个网络吞吐量的最小瓶颈边集是什么”。

因此，最大流模型特别适合下面这种叙事：

- 每条边都有容量上限；
- 流量从源点出发流向汇点；
- 中间点不凭空创造也不凭空消失流量；
- 目标是让总通过量最大。

## 2. 基本概念：流量图、发点、收点、中间点（对应前两张图）

图片里先给了一个有向图：

```text
D = (V, A, C)
```

其中：

- `V`：点集；
- `A`：弧集；
- `C`：容量集合。

对任意弧 `(V_i, V_j)`：

- `C_ij >= 0` 表示该弧容量；
- `x_ij` 表示通过该弧的实际流量。

这就构成了最大流里最重要的两个量：

1. **容量**：这条边最多能过多少；
2. **流量**：这条边当前实际过了多少。

图片里还把点分成三类：

- **发点**：只有出弧的点，也就是源点；
- **收点**：只有入弧的点，也就是汇点；
- **中间点**：除发点和收点之外的点。

这三类点的区分非常重要，因为最大流模型的约束恰恰就是围绕它们展开的。

## 3. 可行流：不是随便给每条边分配数字都叫流（对应第二张图）

图片里把“可行流”定义成满足两类条件的流。

### 3.1 容量条件

```text
0 <= x_ij <= C_ij
```

含义很直接：

- 每条边上的流量不能是负数；
- 也不能超过这条边的容量上限。

这保证了网络里的每条边都不会“超载”。

### 3.2 平衡条件

对中间点来说：

- 输入量 = 输出量

也就是说，中间点不制造流量，也不吞掉流量，它只是中转。  
从建模角度看，这一点就是流量守恒。

因此，可行流的本质就是：

- 边不超载；
- 中间点守恒；
- 源点负责送出；
- 汇点负责接收。

如果这两条都不满足，那还谈不上“最大流”，因为你连一个合法的流都没有构出来。

## 4. 增广链：最大流为什么还能继续变大（对应第三、第四张图）

图片在“增广链的求解”里强调了一个核心判断：

> 如果还能找到一条增广链，就说明当前解还有继续优化的空间。

这句话是理解 Ford-Fulkerson 的关键。

### 4.1 什么是增广链

可以把增广链理解成：

- 一条从源点到汇点的“可继续调整流量的通路”。

沿着这条链，如果某些边还能继续加流量，或者某些边当前已有流量可以回退，那么整个网络的总流量就还有增加空间。

### 4.2 前向弧和后向弧

图片里把弧分成两类：

- **前向弧**：还能继续增加流量的弧；
- **后向弧**：可以减少已有流量、从而腾出调整空间的弧。

这其实就是残量网络思想的直观版本：

- 前向弧代表“还有剩余容量”；
- 后向弧代表“已有流量可以回退一部分”。

所以，增广链不是简单找一条“没走过的路”，而是找一条**还能继续推进总流量的调整通路**。

### 4.3 没有增广链意味着什么

第四张图的结论非常重要：

> 若不存在从 `V_s` 到 `V_t` 的关于流 `x` 的一条增广链，则当前可行流就是最大流。

这句话基本就是 Ford-Fulkerson 的终止判据：

- 找得到增广链 -> 还能增大总流量；
- 找不到增广链 -> 当前流已经到头了。

## 5. Ford-Fulkerson：先标号，再调整（对应后四张图）

图片里对 Ford-Fulkerson 的讲法很有特点，不是直接上残量网络伪代码，而是分成：

1. **标号过程**
2. **调整过程**

这种写法其实很适合数模 skill 调用，因为它很清晰。

## 6. 标号过程：怎么找到一条能增广的链（对应第五、六张图）

### 6.1 给源点打起始标号

图片里第一步是：

```text
给发点 V_s 标号 (0, +∞)
```

这表示：

- 源点没有前驱；
- 从源点开始，理论上先不受增量上界限制。

这是整个搜索的起点。

### 6.2 从已标号点往外扩展

图片里第二步的逻辑是：

取一个已标号点 `V_i`，对它一切未标号的邻接点 `V_j` 按规则处理。

分两种情况：

#### 情况 1：前向弧

如果存在弧 `(V_i, V_j)`，且还可以继续加流量，那么给 `V_j` 标号：

```text
(+V_i, Δ_j)
```

其中新增量：

```text
Δ_j = min{C_ij - x_ij, Δ_i}
```

含义是：

- 这条前向弧最多还能加 `C_ij - x_ij`
- 但整条链真正能加多少，还要受前面已经形成的链增量限制
- 所以最终取两者的较小值

#### 情况 2：后向弧

如果存在弧 `(V_j, V_i)`，且当前该弧上已有流量可以回退，那么给 `V_j` 标号：

```text
(-V_i, Δ_j)
```

其中：

```text
Δ_j = min{x_ji, Δ_i}
```

含义是：

- 后向弧最多能回退的量，就是它当前已有流量；
- 但整条链的调整量同样要受前面链路限制；
- 所以还是取较小值

### 6.3 标号过程什么时候结束

图片里说得很明确：

- 重复上述步骤，直到 `V_t` 被标号；
- 或者再也没法继续标号。

于是会出现两种结果：

1. `V_t` 被标号：说明找到一条增广链；
2. `V_t` 未被标号且过程停住：说明已经找不到增广链，当前流就是最大流。

## 7. 调整过程：找到链之后怎么真正把流量加上去（对应第七张图）

图片把调整过程拆得非常清楚。

先定义：

- `Δ1`：链上所有前向弧还能增加的最大共同余量；
- `Δ2`：链上所有后向弧还能回退的最大共同余量；
- 最终增广量：

```text
Δ = min{Δ1, Δ2}
```

更直观地说，整条增广链最后能调整多少，不是某一条边说了算，而是链上最“卡脖子”的那一条说了算。

### 7.1 调整规则

图片里的规则是：

- 对链 `u` 上的前向弧：`x_ij + Δ`
- 对链 `u` 上的后向弧：`x_ij - Δ`
- 不在链上的弧：流量不变

这一步特别重要，因为它说明：

- 增广不是“所有边都加”；
- 而是前向边加、后向边减；
- 本质上是在整条链上做一次协调调整。

### 7.2 调整后做什么

图片最后一步是：

- 去掉所有标号；
- 回到第一步；
- 对新的可行流重新标号。

这意味着 Ford-Fulkerson 不是一次找到一条增广链就结束，而是：

`找链 -> 调整 -> 清空标号 -> 再找链 -> 再调整`

直到再也找不到增广链。

## 8. Ford-Fulkerson 的完整流程，适合 skill 调用时怎么说

如果后续 skill 需要快速调这个方法，可以直接按下面这个流程调用：

1. 先构造一个满足容量与守恒约束的可行流（通常从零流开始）。
2. 从源点开始做标号。
3. 沿前向弧和后向弧扩展标号，寻找汇点是否可达。
4. 若汇点可达，则得到一条增广链。
5. 计算这条链的最大可增广量 `Δ`。
6. 沿增广链对前向弧加流、后向弧减流。
7. 清空标号并重复。
8. 若汇点始终不可达，则当前流为最大流。

这套表达比单纯写“用 Ford-Fulkerson 求解”更适合 skill 调用，因为它把“什么时候停、怎么调、为什么能调”都说清了。

## 8.1 两个常见实现补充：Edmonds-Karp 与 Dinic

### Edmonds-Karp

- `Edmonds-Karp` 是一种 `BFS`（广度优先搜索）算法。
- 这类做法会出现重复处理问题。

### Dinic

- `Dinic` 引入了分层图的概念。
- 它在上述算法的 `BFS` 之后，又加入了 `DFS`（深度优先搜索），从而加快了算法运行速度。

## 9. 什么时候优先考虑最大流

下面这些情况，最大流通常值得优先进入候选：

- 两点之间有多种传输方式，但各个传输方式都有不同的流量限制，希望整体运输流量效果更好；
- 题目明确有源点、汇点、容量上限；
- 目标是让总输送量、总通过量、总配送量、总吞吐量最大；
- 中间节点满足守恒逻辑；
- 重点在网络传输能力，而不是路线最短或总成本最小。

常见题型包括：

- 水、油、气、电、信息流传输网络；
- 产线 / 管道 / 通讯链路吞吐量；
- 分层输送和容量受限分配问题；
- 某些资源调配网络的瓶颈分析。

## 10. 什么时候不要直接套最大流

以下情况不建议一看到网络就直接套最大流：

- 题目真正目标是“最短”“最低成本”“最少时间”，而不是总流量最大；
- 边上没有明确容量含义；
- 存在复杂时序、调度、收益目标，单纯容量守恒不够表达问题本质；
- 题目更像车辆路径、巡回访问、运输调度，而不是网络流量输送。

也就是说，出现“网络”“路径”“配送”这些词，并不自动等于最大流。

## 11. 和最短路、TSP/VRP、综合优化怎么分

- **和最短路比**：最短路找一条最便宜的路；最大流看整个网络总共能过多少。
- **和 TSP/VRP 比**：TSP/VRP 更关心访问顺序和巡回路径；最大流更关心容量约束下的总输送能力。
- **和综合优化比**：如果除了流量最大，还要同时考虑收益、时间窗、调度顺序、成本等，往往需要把最大流和优化模型结合，而不是只靠最大流。

## 12. 为什么文件名里会带“最小割”

虽然你这次给的图片主要在讲最大流和 Ford-Fulkerson，但在数模里“最大流 / 最小割”通常是成对出现的，因为：

- 最大流告诉你网络最多能送多少；
- 最小割告诉你卡住这个上限的瓶颈边集在哪里。

所以这个文档当前重点写最大流与几种常见求解思路，是为了先把最常用的求解主线讲清。  
如果后续要继续扩充，可以在同一文件里补“最大流最小割定理”和最小割的判定逻辑。

## 13. 可直接写进论文的表述

如果题目适合用最大流，可以直接这样写：

> 由于该问题本质上是在容量受限网络中提升源点到汇点的总输送能力，且网络中间节点满足流量守恒关系，本文将其建模为网络最大流问题。在构造满足容量约束与平衡约束的可行流基础上，采用 Ford-Fulkerson 算法通过反复寻找增广链并调整流量，逐步提高网络总流量，直至不存在新的增广链，从而获得最大流结果。

如果题目并不适合只用最大流，也可以这样写：

> 虽然该问题具有网络结构，但其核心目标并非单纯提升源汇之间的总流量，而是同时受成本 / 调度 / 时序 / 路径结构等因素影响，因此本文不直接采用纯最大流模型，而是将网络流思想作为局部约束结构，进一步结合其他优化方法进行建模。

## 14. 使用前最低检查清单

如果以后准备在 skill 里调用最大流，至少先问清这些问题：

1. 是否存在明确的源点与汇点？
2. 每条边是否有清晰的容量上限？
3. 中间节点是否满足守恒关系？
4. 目标究竟是总流量最大，还是最短路 / 最低成本 / 最优调度？
5. 当前问题里的“流量”具体代表什么？
6. 若采用 Ford-Fulkerson，增广链搜索方式准备如何实现？
7. 是否需要同时解释网络瓶颈或最小割含义？
8. 是否存在附加约束，已经超出纯最大流模型表达能力？

## 常见误用

- 只要题目里出现“路径”就直接套最大流。
- 把“边有权重”误当成“边有容量”，不区分成本和容量。
- 忽略中间节点流量守恒，只顾着算源点送出量。
- 把 Ford-Fulkerson 当成“找一条路然后一路加满”，而不理解前向弧 / 后向弧调整。
- 明明题目是最短路、VRP 或综合调度，却因为网络结构明显就强行写成最大流。
