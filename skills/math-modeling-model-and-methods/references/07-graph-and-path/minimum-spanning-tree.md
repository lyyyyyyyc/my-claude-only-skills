# 最小生成树（当前重点：Prim 与 Kruskal）

> 用途：当用户已经确定题目属于图论路径类，并且进一步想判断“这题是不是最小生成树问题”“该用 Prim 还是 Kruskal”“网络搭建成本最小该怎么写”时，读取本文件。
>
> 说明：本文件根据用户提供的“最小生成树”截图整理，当前重点放在 `Prim` 与 `Kruskal` 两种经典算法的适用题型和分流边界，不展开成完整图论教材。

## 这份文档适合什么时候看

- 题目围绕城市、站点、节点之间的连通与搭建展开。
- 每条边有距离、长度、造价等权重，目标是让总连接成本最小。
- 题目要求在保证整体连通的前提下，只保留必要连接，而不是形成回路网络。
- 你需要进一步判断到底该优先用 `Prim` 还是 `Kruskal`。

## 一句话先判断它适不适合这题

- **如果题目要在保证所有节点连通的前提下，让总连接代价最小，而且最终只需要 `n-1` 条边，最小生成树通常就是第一候选。**
- **如果图更稠密，优先考虑 `Prim`；如果图更稀疏，优先考虑 `Kruskal`。**
- **如果题目除了建网成本，还包含容量、时序、流量或多阶段调度约束，就不该只靠最小生成树。**

## 1. 先把最小生成树想成什么

- 在给定一张无向图时，如果它的一个子图满足任意两个顶点都互相连通，并且整体是树结构，那么这类树叫做生成树。
- 当连接顶点之间的图带有权重时，权重之和最小的树结构就是最小生成树。
- 一个直观例子是：在若干城市之间铺设电缆，只需要 `n-1` 条线路，同时希望铺设线路总长度最短。

## 2. Prim 算法

### 2.1 核心思路

- `Prim` 从任意一个顶点开始，每次选择一个与当前顶点集最近的顶点，并把两顶点之间的边加入到树中。

### 2.2 适用题型

- 适用于稠密图。
- 边越多，图越稠密，`Prim` 往往越值得优先考虑。

## 3. Kruskal 算法

### 3.1 核心思路

- `Kruskal` 从最小边权的边开始，按边权从小到大依次加入。
- 如果某次加入的边产生了环，就丢掉这条边。
- 当已经加入了 `n-1` 条边时，就形成了一棵树。

### 3.2 适用题型

- 适用于稀疏图。

## 4. Prim 和 Kruskal 怎么分

| 方法 | 核心做法 | 更适合的图 |
|---|---|---|
| `Prim` | 从一个起点出发，不断向当前顶点集外扩 | 稠密图 |
| `Kruskal` | 直接按边权从小到大选边，遇环舍弃 | 稀疏图 |

## 5. 常见适用场景

- 城市间铺设电缆、光纤、管线
- 多站点之间的最低连接成本搭建
- 需要保证整体连通、但不要求形成回路的网络建设问题

## 6. 不适用边界

- 题目不仅要求连通，还同时要求容量分配、流量约束或运输吞吐量。
- 题目包含显式时序、时间窗或多阶段调度约束。
- 题目本质是最短路径、最大流或车辆路径，而不是连通网络的最低搭建成本。

## 7. 可直接写进论文的表述

如果采用最小生成树，可以写：

> 由于题目要求在保证各节点连通的前提下，使网络搭建总成本最小，且最终仅需形成包含 `n-1` 条边的树结构，因此本文将其建模为最小生成树问题。进一步根据图的稠密程度，在 `Prim` 与 `Kruskal` 算法之间进行选择，以获得最低连接代价的网络结构。

## 小结

- **最小生成树解决的是“连通 + 总权重最小”，不是“路径最短”或“流量最大”。**
- **稠密图优先考虑 `Prim`，稀疏图优先考虑 `Kruskal`。**
