# 最小费用最大流（当前重点：最短路增广思路）

> 用途：当用户已经确定题目属于图论路径类，并且进一步想判断“这题是不是最小费用最大流”“在容量约束下既要送得多又要送得省该怎么建模”“最小费用最大流的求解主线该怎么理解”时，读取本文件。
>
> 说明：本文件根据用户提供的“最小费用最大流问题”教学图整理而成，重点不是逐页复述课件，而是把这些图转成一个**可被 skill 调用的参考模块**。当前重点放在：基本概念、费用定义、最短路增广思路、反向弧处理，以及“什么时候该用 / 不该用最小费用最大流”。

## 这份文档适合什么时候看

- 你已经判断题目是网络流问题，但现在不只是要“流量最大”，还要“总费用尽量小”。
- 题目里每条边除了容量之外，还有单位运输成本、体力消耗、费用、代价之类的量。
- 你怀疑题目本质是“在满足最大输送量的前提下，再把总成本压到最低”。
- 你后面准备把这个方法写进论文、代码或 skill 里的路由判断，想先把求解主线理顺。

## 一句话先判断它适不适合这题

- **如果题目是在容量受限网络中，既要求总输送量尽量大，又要求总代价尽量小，最小费用最大流通常就是第一候选。**
- **如果题目只关心“总流量最大”，不关心每条边的费用，那通常最大流就够了。**
- **如果题目更像最短路、最短时间或单条路径最优，而不是整个网络的流量分配，那通常不该优先套最小费用最大流。**

## 1. 先把最小费用最大流想成什么

最小费用最大流不是“最短路”和“最大流”的简单拼接，而是一个两层目标：

1. 先尽量把网络总流量做大；
2. 在所有最大流里，再选总费用最小的那个流。

因此，它处理的是“**量**”和“**代价**”同时存在的网络问题。

更直白一点：

- 最大流只问：最多能送多少？
- 最短路只问：走哪条路最便宜？
- 最小费用最大流问的是：  
  **在整个网络里尽可能多地送，并且总费用尽可能低。**

所以它不是只找一条最便宜的路，而是在整个网络里安排流量去走一批边，使得：

- 总流量最大；
- 总费用最小。

## 2. 基本概念：可行流、单位费用、总费用（对应前两张图）

图片里先约定了两个对象：

- `x = (x_ij)`：一个可行流；
- `w = (w_ij)`：单位流量通过弧 `(i,j)` 的费用。

于是总费用写成：

```text
∑ w_ij * x_ij
```

也就是说：

- `x_ij` 决定有多少流量通过这条弧；
- `w_ij` 决定每经过 1 单位流量要付出多少代价；
- 两者乘起来，就是这条弧贡献的总费用；
- 把所有弧的费用加起来，就是整个流的总费用。

这说明最小费用最大流的关键并不只是“流量怎么走”，还包括“流量走这条边值不值得”。

## 3. 它和普通最大流到底差在哪

普通最大流只看容量和守恒，不区分“这条边贵不贵”。  
最小费用最大流则多了一层成本判断：

- 边不只是有容量上限；
- 每单位流量走过去还会产生成本。

所以，在两个都能把流送到汇点的方案之间，最小费用最大流不会只看谁送到了，而会继续比较：

- 谁的总成本更低；
- 哪条边虽然能走，但不值得多走。

这也是为什么它的求解思路会引入“费用意义上的最短路”。

## 4. 求解主线：为什么它会变成“最短路 + 增广链”的过程（对应第三、第四张图）

图片给出的求解思想可以概括成一句话：

> 用费用作为评价标准去找最短路，再在这条路上做增广。

这里最容易误解的地方是：  
“找最短路”不是说题目本身变成最短路问题了，而是说：

- 在当前残量网络里，
- 你优先选择那条**增广代价最低**的路径，
- 然后沿着它增加流量。

所以这套方法本质上是：

1. 从零流开始；
2. 在当前网络状态下找一条费用最优的可增广路径；
3. 沿这条路径增加流量；
4. 更新网络；
5. 继续重复，直到流量已经不能再增加。

因为你每次都优先沿“当前最省钱”的增广路径扩充，所以最终在达到最大流时，也尽量把总费用压低了。

## 5. 为什么图片里强调“从零流开始”

图片里明确说：

> 题目中并没有给出初始可行流，所以我们需要从零流开始构建，这样可以保证所求的是人数的最大流。

这句话的意义很重要：

- 如果你从一个任意可行流开始，后面确实也能继续调；
- 但在教学和数模实现里，从零流开始最干净，也最容易控制逻辑；
- 它保证你是在“逐步把流做大”，而不是在一个来历不明的流上做修修补补。

对 skill 调用来说，这一点可以直接抽象成默认规则：

- **如果题目没有给定起始可行流，默认从零流开始建。**

## 6. 这套方法具体在做什么（按图片里的三步来理解）

图片里把主过程拆成三步，这种拆法很适合后续 skill 调用。

### 6.1 第一步：找出最短路径

这里的“最短”不是距离最短，而是**费用最小**。

也就是说，在当前可用网络中，你先找一条从源点到汇点的最低费用路径，把它当成当前最值得扩充的方向。

这一步在解题中解决的是：

- 不是先问“能不能增流”，而是先问“往哪里增流最划算”。

### 6.2 第二步：找出最短路径上的增广链

图片里强调：

- 对没有记录的弧从零流开始；
- 有记录的弧则在原来的流量基础上计算；
- 根据流量有向图看是否还有增广链。

这一步的本质是：

- 最短路只是候选方向；
- 还要进一步检查这条路上到底还能不能真正增加流量。

也就是说，最短路要同时满足：

- 成本意义上值得走；
- 容量意义上还能走。

### 6.3 第三步：检查是否有反向弧

这是图片里最关键、也是最容易被忽略的一步。

图里给了三种情况：

1. `0 < x_ij < C_ij`
   - 说明这条弧还可以增加，也可以减少；
   - 于是保留原弧，同时加入一条反向弧；
   - 反向弧权值设为原弧权值的相反数。

2. `x_ij = 0`
   - 说明当前还没有流量走这条弧；
   - 它现在只能增加，不能减少；
   - 所以没有必要额外给它一个可回退的流量通道。

3. `x_ij = C_ij`
   - 说明这条弧已经满流；
   - 它不能再增加，只可能减少；
   - 所以删去原来的可增广方向，保留反向调整可能。

这一整套逻辑本质上是在维护一个带费用信息的**残量网络**。  
如果没有这一步，你就无法表达“某些边上的流量其实是可以回退和重新分配的”，也就很难做到全局费用最优。

## 7. 反向弧为什么这么重要

反向弧不是技巧细节，而是最小费用最大流真正能“修正旧决策”的关键。

如果只有前向弧，那么算法只能不断往前加流量，没法撤销之前走得太贵的路径。  
而一旦加入反向弧，算法才有机会：

- 把已经送出去的一部分流量退回来；
- 改走更便宜的路径；
- 在保证总流量不减的前提下，继续压低总费用。

所以最小费用最大流并不是机械加流，而是在做“**增流 + 重分配 + 纠偏**”。

## 8. 适合 skill 调用的完整求解流程

如果后续 skill 需要快速调用这个方法，可以直接按下面这套主线：

1. 先确认题目是否同时存在：
   - 容量约束；
   - 源点 / 汇点；
   - 单位费用或单位代价。
2. 若未给初始可行流，默认从零流开始。
3. 在当前残量网络中，以费用为权重寻找从源点到汇点的最短路径。
4. 检查这条路径上是否存在可增广链。
5. 根据当前流量状态维护前向弧与反向弧。
6. 沿增广链增加可行流量。
7. 更新流量图与费用结构。
8. 重复上述过程，直到不存在新的增广路径。
9. 输出：
   - 最大总流量；
   - 对应总费用；
   - 必要时给出各边流量分配方案。

这套表达比单纯写“用最小费用最大流算法求解”更适合 skill，因为它把“什么时候找路、什么时候看增广、什么时候处理反向弧”都明确了。

## 9. 什么时候优先考虑最小费用最大流

下面这些情况，最小费用最大流通常值得优先进入候选：

- 题目明确有源点、汇点、容量限制；
- 每条边同时带有单位费用、单位成本、体力消耗、代价等；
- 目标是“尽可能多输送”，同时“总代价尽可能低”；
- 需要输出的是网络级流量分配，而不是单条路径。

常见场景包括：

- 运输网络中的最大输送与最小成本；
- 人流 / 物流 / 物资调配网络；
- 管道、通信、能源网络中的容量与费用平衡；
- 需要在网络中找最省成本的大规模输送方案的问题。

## 10. 什么时候不要直接套它

以下情况不适合一看到“费用”就直接上最小费用最大流：

- 题目目标是单条路最短，而不是整网输送量最大；
- 没有容量约束，只有距离或时间；
- 没有明确源点和汇点；
- 费用不是沿弧按单位流量累积，而是更复杂的全局收益 / 时序 / 调度目标；
- 实际更像路径规划、车辆调度、收益最大化综合优化，而不是标准网络流。

也就是说，“有费用”不等于“最小费用最大流”，还必须同时有网络流结构。

## 11. 和最大流、最短路、综合优化怎么分

- **和最大流比**：最大流只看“送得最多”；最小费用最大流在“送得最多”的基础上继续追求“送得最省”。
- **和最短路比**：最短路找的是一条路径；最小费用最大流处理的是整个网络的流量安排。
- **和综合优化比**：如果题目还有时序、收益、调度、车辆路径、资源配置等复杂条件，往往要把网络流模型和优化模型结合起来，而不是只用最小费用最大流。

## 12. 可直接写进论文的表述

如果题目适合这个方法，可以直接这样写：

> 由于该问题本质上是在容量受限网络中实现源点到汇点的最大输送，同时要求总运输代价最小，本文将其建模为最小费用最大流问题。设 `x_ij` 为弧 `(i,j)` 上的流量，`w_ij` 为单位流量通过该弧的费用，则总费用可表示为 `∑ w_ij x_ij`。在满足容量约束与流量守恒约束的前提下，本文从零流出发，采用基于最短费用增广路径的求解思路，不断在残量网络中寻找最小费用增广链并调整流量，直至达到最大流，从而得到费用最小的最大流方案。

如果题目不适合只用它，也可以这样写：

> 虽然该问题具有网络结构且涉及费用因素，但其核心目标并非单纯在容量约束下实现最大输送并最小化总费用，而是同时包含更复杂的调度 / 时序 / 收益优化要求。因此本文不直接采用标准最小费用最大流模型，而是将网络流思想作为局部结构，进一步结合其他优化方法进行建模。

## 13. 使用前最低检查清单

如果以后准备在 skill 里调用最小费用最大流，至少先问清这些问题：

1. 是否存在明确的源点、汇点？
2. 每条边是否有容量上限？
3. 每条边是否有清晰的单位费用 / 代价定义？
4. 题目要的是“最大流 + 最小费用”，还是单纯最短路、最大流、最低成本？
5. 中间节点是否满足流量守恒？
6. 当前问题中的费用是否能按 `∑ w_ij x_ij` 这种弧费用累加方式表达？
7. 是否需要构造反向弧来做残量调整？
8. 输出最终需要的是总流量、总费用，还是每条边的具体流量分配？

## 常见误用

- 一看到“费用”就直接把题目写成最小费用最大流。
- 把“最短路”误当成“最小费用最大流”的等价问题。
- 只关注费用，不检查是否真的存在容量约束和流量守恒。
- 只会沿当前最短路加流，却不理解反向弧和残量调整的意义。
- 题目本质是综合调度优化，却因为有网络结构就强行套最小费用最大流。
