# 未覆盖方法的受控兜底

## 何时使用

当问题被识别为因果推断、博弈、专门几何/运动学、正式实验设计，或某个分类索引列出的具体方法尚无专属参考文档时，使用本流程。它的作用是避免把不相容的问题硬套到已有方法中。

不要把以下情况转入关联规则分析：

- 需要处理效应、反事实、混杂控制或因果方向的因果问题；
- 普通相关分析、回归解释或显著性检验；
- 博弈策略、几何证明、实验设计或生态食物网。

关联规则分析只处理事务/购物篮/共现型数据中的频繁项集和规则强度。

## 最少信息表

优先调用 `math-modeling-brainstorm`；其不可用时，当前代理直接收集：

```text
问题主张与最终决策
研究对象、时间/空间范围和单位
输入、输出、已知约束和可用数据
需要解释、预测、比较、优化还是识别因果
关键假设、潜在混杂因素、干预或策略主体
所需证据：误差、显著性、均衡、几何可行性、实验功效或其他
可使用的软件、运行预算和可接受限制
```

## 执行规则

1. 先判断是否能无损分流到已有路线：因果问题中的描述相关可进入统计分析；单主体决策可进入优化；运动方程可进入机理；网络路径可进入图论。
2. 若仍需要专属方法，当前代理只交付“方法需求规格”，不得凭名称宣称该方法适用或已验证。
3. 方法需求规格必须写明：问题类型、候选理论框架、识别/适用前提、数据结构、至少一个基准或反例检查、执行与验证所需输出。
4. 将规格交给 `math-modeling-brainstorm` 重新进行方法设计；如果仍没有可用专属参考或执行环境，明确标注“当前 skill 未覆盖，不能给出可执行推荐”，再由用户决定是否新增该方法参考。

## 常见错误

- 因为数据里有多个变量，就把因果识别改写成关联规则。
- 因为存在多个参与方，就把博弈问题简化成单主体优化而不说明这一假设。
- 因为路线图中有“仿真”，就把缺失机制的复杂问题直接交给 Monte Carlo。
- 在没有方法参考、数据条件或识别前提时，输出看似完整但无法复核的结论。
