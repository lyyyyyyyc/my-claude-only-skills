# DBSCAN（基于密度的聚类）

> 用途：当用户已经判断问题属于“分类识别 / 聚类发现”方向，并且想进一步理解“什么时候适合用 DBSCAN”“DBSCAN 为什么能识别噪声点”“它和 K-means、层次聚类有什么本质区别”时，读取本文件。
>
> 说明：本文件不是把教材原句照搬，而是把 DBSCAN 整理成“数模里能选方法、写论文、解释结果”的参考模块。重点放在密度思想、参数含义、优缺点边界和论文表达。

## 这份文档适合什么时候看

- 你面对的是“没有现成标签，但希望根据样本局部密度自动分组”的问题。
- 你怀疑数据中存在离群点、噪声点，不想让这些点强行被分进某个簇。
- 你觉得真实簇形状可能很复杂，不像 K-means 那样接近球形或圆形。
- 你想比较 DBSCAN 与 K-means、层次聚类的适用边界，判断谁更适合这题。

## 一句话先判断它适不适合这题

- **如果你更关心“哪些点在局部上足够密集，能自然形成簇”，而且希望把噪声点单独识别出来，DBSCAN 往往值得优先进入候选。**
- **如果你不想预先指定簇数，并且数据簇形状可能比较复杂，DBSCAN 通常比 K-means 更自然。**
- **如果不同区域的簇密度差异很大，DBSCAN 往往会比较吃力，这时要谨慎。**

## 1. 先把 DBSCAN 想成什么

DBSCAN（Density-Based Spatial Clustering of Applications with Noise）可以理解成一种“看周围够不够挤，再决定要不要成团”的聚类方法。

按截图中的原始概括，它也可以表述为：

- 基于一组邻域参数来判断某处样本是否是紧密。

它和 K-means 最大的不同，不是先找中心，而是先看：

- 某个点周围是不是足够密集；
- 如果足够密集，它是不是可以带出一片簇；
- 如果不够密集，它是边缘点，还是干脆就是噪声点。

因此，DBSCAN 的核心不是“把点分给最近中心”，而是：

- 先识别高密度区域；
- 再让这些高密度区域向外扩展形成簇；
- 最后把密度太低、无法归入任何簇的点识别为噪声。

所以你可以把 DBSCAN 想成：

- **不是按中心分组，而是按“局部够不够密”来成团。**

## 2. DBSCAN 的三类点

DBSCAN 会把样本点分成三种角色：

### 2.1 核心点（Core Point）

如果一个点在其 `ε` 邻域内包含至少 `MinPts` 个点（通常把它自己也算进去），那么它就是核心点。

核心点可以理解为：

- 这个点周围已经足够“挤”；
- 它所在位置是一个局部高密度区域；
- 它能够成为簇扩展的起点。

### 2.2 边界点（Border Point）

如果一个点自己达不到核心点条件，但它落在某个核心点的邻域之内，那么它是边界点。

边界点可以理解为：

- 它属于某个簇；
- 但它自己周围不够密，不能单独继续向外扩展。

### 2.3 噪声点（Noise Point）

如果一个点既不是核心点，也不落在任何核心点邻域中，那么它就是噪声点。

噪声点可以理解为：

- 它没有加入任何高密度团块；
- 它不属于任何簇；
- 它处于当前参数和距离定义下的局部稀疏区域。它可能是异常值，也可能只是正常但稀疏的样本，不能仅凭 DBSCAN 标签断言其为异常。

## 3. DBSCAN 的两个关键参数

### 3.1 `ε`（epsilon，邻域半径）

`ε` 决定“看多大范围算邻居”。

也就是说，对某个样本点而言，距离它不超过 `ε` 的点，都算它的邻域点。

如果 `ε` 太小：

- 大家彼此都看不到足够多邻居；
- 很多点会被误判成噪声；
- 簇会被切得很碎。

如果 `ε` 太大：

- 原本不同的簇可能被连成一大团；
- 聚类结构会被过度合并；
- 噪声识别能力会下降。

### 3.2 `MinPts`

`MinPts` 决定“周围至少要有多少点，才算局部够密”。

如果 `MinPts` 太小：

- 很多稀疏区域也会被当成簇；
- 噪声点容易被误吸纳。

如果 `MinPts` 太大：

- 即使本来是正常簇，也可能因为密度标准太高而无法成簇；
- 结果会出现过多噪声点。

## 4. DBSCAN 到底怎么工作

DBSCAN 的标准流程可以整理成下面这条线：

1. 从一个尚未处理的点开始。
2. 查看它的 `ε` 邻域。
3. 如果它是核心点，就以它为起点扩展一个新簇。
4. 把邻域中的点加入当前簇，并继续检查这些点中哪些还是核心点。
5. 对新发现的核心点重复扩展，直到这个簇无法继续长大。
6. 再去找下一个尚未处理的点。
7. 如果某个点既不能成为核心点，也无法归入已有簇，就把它标记为噪声。

这里最关键的不是“逐点检查”，而是：

- **只有核心点能真正把簇往外扩展；**
- **边界点只能被带进簇，但不能继续扩展；**
- **噪声点会被单独留下。**

## 5. 一个通俗的二维例子

假设我们有以下 6 个二维数据点：

```text
(1, 2), (2, 3), (3, 3), (8, 7), (8, 8), (25, 80)
```

并且设定：

- `ε = 1.5`
- `MinPts = 2`

### 第一步：看每个点的邻域

先按欧几里得距离判断每个点周围是否有足够邻居。

例如：

- `(1, 2)` 与 `(2, 3)` 的距离约为 `1.41`，在邻域内；
- `(2, 3)` 与 `(3, 3)` 的距离为 `1`，在邻域内；
- `(8, 7)` 与 `(8, 8)` 的距离为 `1`，在邻域内；
- `(25, 80)` 与其他点都非常远，邻域几乎为空。

### 第二步：找出核心点

由于 `MinPts = 2`，并且通常把点自身也算进邻域，因此：

- `(1, 2)` 的邻域中至少有自己和 `(2, 3)`，是核心点；
- `(2, 3)` 的邻域中至少有自己、`(1, 2)`、`(3, 3)`，是核心点；
- `(3, 3)` 的邻域中至少有自己和 `(2, 3)`，是核心点；
- `(8, 7)` 的邻域中有自己和 `(8, 8)`，也是核心点；
- `(8, 8)` 的邻域中有自己和 `(8, 7)`，也是核心点；
- `(25, 80)` 邻域中只有自己，不满足条件，因此不是核心点。

这里要特别注意：

- 按这个参数设定，`(8, 7)` 和 `(8, 8)` 并不是边界点，而是核心点。

### 第三步：扩展簇

于是会得到两个密度簇：

- 簇 1：`{(1,2), (2,3), (3,3)}`
- 簇 2：`{(8,7), (8,8)}`

而：

- 噪声点：`{(25,80)}`

### 这个例子真正想说明什么

重点不在于坐标本身，而在于：

- DBSCAN 会自动把紧密靠近的点连成一簇；
- 不需要你提前指定“必须分成 2 类”；
- 孤立很远的点会自然被标成噪声，而不是被强行分配进去。

## 6. DBSCAN 在优化什么

严格来说，DBSCAN 和 K-means 不一样，它并不是通过某个显式“最小化簇内平方和”的目标函数来做迭代优化。

它更像一种“基于规则的密度扩展过程”：

- 规则 1：达到密度阈值的点是核心点；
- 规则 2：核心点能扩展簇；
- 规则 3：无法归入任何密度簇的点就是噪声。

所以，DBSCAN 的强项不在于“优化一个中心”，而在于：

- **通过密度规则自动发现簇与噪声。**

## 7. DBSCAN 的优点

### 7.1 不需要预先指定簇数

它不会像 K-means 那样要求你先给 `K`，而是根据局部密度自动发现簇。

### 7.2 能发现复杂形状的簇

只要同一簇内部局部密度连续，哪怕形状弯曲、拉长或不规则，DBSCAN 仍可能把它识别出来。

### 7.3 能识别噪声点

这点非常重要。很多聚类方法会把每个点都硬塞进某一类，而 DBSCAN 允许噪声单独存在，这对异常值很多的问题很有价值。

### 7.4 不依赖随机初始中心，但仍有实现边界

DBSCAN 不像 K-means 那样依赖随机初始中心来启动聚类；但边界点在多个簇都可达、或实现处理顺序不同的情况下，归属仍可能存在差异。因此仍需做参数和稳定性检查。

## 8. DBSCAN 的缺点与边界

### 8.1 对参数敏感

`ε` 和 `MinPts` 选得不合适，结果可能完全不同。

### 8.2 不擅长处理密度差异很大的簇

如果一个簇特别稠、另一个簇特别稀，那么同一组参数很难同时兼顾二者。

### 8.3 对距离度量和特征尺度敏感

如果特征没有标准化，某些量纲大的变量会主导邻域判断，导致聚类结果失真。

### 8.4 高维数据计算复杂

当特征维度升高时，邻域搜索与距离计算的负担会明显上升，因此 DBSCAN 在高维数据上的实现和调参通常更吃力。

## 9. DBSCAN 和 K-means 的区别

### 9.1 是否需要预先指定簇数

- K-means：通常需要先给 `K`。
- DBSCAN：不需要先给定簇数。

### 9.2 对噪声的处理

- K-means：会把所有点都分进某个簇。
- DBSCAN：允许噪声点不属于任何簇。

### 9.3 对簇形状的偏好

- K-means：更偏好圆形、紧凑簇。
- DBSCAN：更适合复杂形状簇。

因此：

- 如果你更在意固定分组、速度和质心解释，优先考虑 K-means；
- 如果你更在意复杂形状簇与噪声识别，优先考虑 DBSCAN。

## 10. DBSCAN 和层次聚类的区别

- 层次聚类强调层次结构和树状图表达。
- DBSCAN 强调密度连通和噪声识别。
- 层次聚类适合先探索“样本关系树”；DBSCAN 更适合直接找“高密度团块”。

因此：

- 如果你要的是树状图和层次解释，优先考虑层次聚类；
- 如果你要的是基于密度自动分簇并识别异常点，优先考虑 DBSCAN。

## 11. 数模里怎么把它写进论文

如果最终采用 DBSCAN，论文里一般要交代四件事：

1. 为什么该问题适合看局部密度而不是固定中心。
2. 为什么不能直接用 K-means。
3. `ε` 和 `MinPts` 是如何设定的。
4. 聚类结果如何解释，噪声点如何处理。

一个比较自然的论文表述可以写成：

> 由于题目样本未提供现成类别标签，且数据中可能同时存在局部高密度群体与少量离群样本，因此本文采用基于密度的聚类方法 DBSCAN 对样本进行分群。该方法通过在给定邻域半径 `ε` 与最小邻域点数 `MinPts` 的条件下识别核心点、边界点与噪声点，从而自动发现密度连通簇。与需要预先指定簇数且对离群点较敏感的 K-means 相比，DBSCAN 更适合处理含噪声、簇形状较复杂的数据结构。

## 12. 核心定义与关键超参数

给定距离 `d` 和邻域半径 `\varepsilon`，点 `x_i` 的邻域为：

\[
N_{\varepsilon}(x_i)=\{x_j:d(x_i,x_j)\le\varepsilon\}
\]

若邻域中点数达到最小阈值，则点为核心点：

\[
|N_{\varepsilon}(x_i)|\ge\operatorname{MinPts}
\]

边界点位于核心点的邻域中但自身不满足核心点条件；既不是核心点也不能归入任何核心点邻域的点可标为噪声。是否计入点自身必须与具体实现保持一致并在文档中说明。

若存在点序列 `x_1,\ldots,x_m`，使得相邻点满足“在核心点 `\varepsilon` 邻域内”，则可称 `x_m` 从 `x_1` 密度可达；若两个点都能从某个核心点通过这样的链到达，则称它们密度相连。DBSCAN 的簇由密度相连的点组成，而不是由一个显式质心或平方损失最小化得到。

| 参数 | 作用 | 建议起点 |
|---|---|---|
| `eps` | 邻域半径 | 通过 k-distance 曲线找拐点候选，再做敏感性检查 |
| `min_samples` | 最小邻域点数 | 可从 `p+1` 附近起步，但仅是经验起点 |
| `metric` | 距离度量 | 由特征语义和尺度决定 |
| `algorithm` | 邻域搜索算法 | `auto` 或按数据结构选择 |
| `leaf_size` | 树搜索叶节点大小 | 主要影响速度和内存 |

表中的 `eps`、`min_samples` 和 `p+1` 仅是经验起点；必须结合 k-distance、噪声比例、簇结构和稳定性验证，不能作为绝对阈值。

### 参数操作建议

1. 先完成尺度处理并固定距离度量。
2. 计算每个点的第 `k` 近邻距离，观察 k-distance 曲线的拐点。
3. 用若干 `eps` 与 `min_samples` 组合运行，记录簇数、噪声比例和极小簇数量。
4. 用内部指标和稳定性检查筛选参数；不能只选择轮廓系数最高的一组。
5. 报告 `eps`、`min_samples`、距离度量、噪声比例和参数敏感性。

## 13. 常见误判风险

- 只说“用了 DBSCAN”，却不交代 `ε` 与 `MinPts` 的设定依据。
- 数据尺度差异很大，却没有做标准化。
- 误把边界点和核心点混为一谈。
- 参数不合适导致大量噪声，却没有讨论原因。
- 把 DBSCAN 的聚类结果直接当成最终真实类别，而没有结合业务含义解释。

## 14. 什么时候建议优先看别的方法

- 如果你已经明确知道大概要分成几类，且数据结构比较规整，优先看 `k-means.md`。
- 如果你更关心样本的层次结构和树状图解释，优先看 `hierarchical-clustering.md`。
- 如果任务其实是有标签后的监督识别问题，应转向逻辑回归、决策树、SVM 等监督分类方法。

## 小结

DBSCAN 可以概括成一句话：

- **它不是先找中心，而是先找“局部足够密”的区域，再让这些区域自动长成簇，并把无法归入任何密度簇的点识别为噪声。**

它最大的优点是不必预先给簇数、能识别噪声、能处理复杂形状簇；最大的限制是对 `ε` 与 `MinPts` 比较敏感，而且不擅长处理密度差异很大的簇。

如果你的题目重点在“密度结构发现 + 异常点识别”，DBSCAN 往往比 K-means 更值得优先考虑。
