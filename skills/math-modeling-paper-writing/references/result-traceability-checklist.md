# 摘要结果溯源与交付清单

## 用途
- 本清单用于把摘要中的每个数字、结论、方法和验证结果追溯到题目、代码、结果文件或正文。
- 它是论文写作 SKILL 的质量控制参考，不替代模型求解、数据预处理、超参数调优或评委复核。

## 摘要写作规则
- 每个小问必须以“针对问题 X”定位，随后直接写已执行的处理、方法、求解动作和结果。
- 不使用“本问是[问题类型]问题，需[题目要求]”作为固定模板。
- 摘要已覆盖任务、方法和结果三个核心要素；只有存在真实的新框架、组合方法或对比证据时才写创新点。
- 可选总体段已直接交代核心场景、矛盾和总体任务；中间段已按“小问定位 -> 研究对象/任务 -> 方法及职责 -> 必要操作、阈值或选择理由 -> 关键结果 -> 验证、稳定性或实际含义”展开；只有需要统一验证、创新或推广结论时才设置收束段。
- 每个中间段的动词都对应真实执行步骤，关键方法参数或检验结果没有被空泛方法名替代。
- 没有来源的数字使用 `[待核验]`，不能由 AI 根据上下文猜测。
- 每个数字都要核对对象、指标名称、单位、方向、样本范围、小数位和计算时间点。
- 摘要中的方法名、参数、验证方式和结果必须能在正文中找到支撑。
- 摘要不放公式、图表、完整超参数搜索过程或算法伪代码。
- 可以用一句话报告真实的验证结果，但不能用“模型有效”“结果可靠”等无证据评价替代结果。
- 每个需要定量回答的小问优先选择 `1` 至 `3` 组高信息密度数字或对比证据，全文不设数字总量硬上限。
- 结果较多时已在摘要中直接给出代表性结论，没有用“具体数据见附录”或“详见正文 / 附录”替代核心答案。

## 常用后台核验

基线差值：

\[
\Delta=y_{\mathrm{model}}-y_{\mathrm{baseline}}.
\]

相对变化率：

\[
r=\frac{y_{\mathrm{model}}-y_{\mathrm{baseline}}}
{|y_{\mathrm{baseline}}|}.
\]

评价排序第一名与第二名的差距：

\[
\Delta C=C_{(1)}-C_{(2)}.
\]

使用相对变化率前，应确认分母不接近 0，并明确“指标越大越好”还是“指标越小越好”。

## 交付前检查
- [ ] 每个小问都被摘要覆盖。
- [ ] 如设置总体段，背景能够直接引出研究对象、核心矛盾和总体任务，没有无关的宏观铺垫。
- [ ] 每个中间段都以“针对问题 X”开头，并写出任务、方法职责、必要操作或理由、关键结果，以及适用时的验证或实际含义。
- [ ] 如设置收束段，其中的模型特色、创新或验证结论均有依据；不需要收束段时已直接由最后一问进入关键词。
- [ ] 关键词数量和分隔符符合赛题或模板要求；没有明确要求时为 `4` 到 `5` 个，且每个关键词都能在正文找到支撑。
- [ ] 每个关键数字都有来源。
- [ ] 数字、单位、对象和小数位已核对。
- [ ] 没有把不同小问的结果混用。
- [ ] 没有把拟合结果写成泛化结果。
- [ ] 没有把推荐超参数写成用户已确认的最终配置。
- [ ] “稳健、可靠、有效、提升”等评价都有对应证据。
- [ ] 摘要、正文、表格和附录的口径一致。
