# 为 `math-modeling-paper-writing` 新增内容的维护指南

## 用途
这份文档是给 Codex 在后续继续扩展 `math-modeling-paper-writing` 时使用的维护规程。以后如果需要继续往这个 skill 里新增写作规则、补充触发词、扩展论文结构说明或增加排版图表规范，优先先读这份文档，再决定改哪里、怎么改。

## 什么时候应该新增内容
以下情况适合继续新增到这个 skill：
- 出现新的高频数模论文写作口语表达，导致当前 `description` 或 `when_to_use` 覆盖不足。
- 需要补新的写作规则、部分衔接规则或章节边界说明。
- 需要补新的排版、标题、图表、附录规范。
- 发现新的常见写作跑偏场景，值得加入 `常见错误` 或写作流程中。

以下情况通常不应该直接加到这个 skill：
- 某一个具体模型的方法细节或求解过程本身。
- 某一个单题目的临时写法要求。
- 只适用于单次会话的修改意见。
- 更适合放到 `math-modeling-brainstorm`、`math-modeling-model-and-methods` 或其他专门数模 skill 的内容。

## 新内容应该加到哪里
新增内容时，先判断它属于哪一类，再放到对应区块：

| 新增内容类型 | 应放位置 |
|---|---|
| 触发词、用户口语表达、何时应该调用本 skill | frontmatter 的 `description` / `when_to_use` |
| 用户应先判断整篇还是单部分 | `什么时候优先用本 skill` / `第一优先动作` |
| 正式部分与扩展部分定义 | `摘要与固定的 12 个正式正文部分` / `额外扩展部分` |
| 标题编号、章节层级规则 | `标题与编号默认规则` |
| 章节映射与读取关系 | `路由表` |
| 写作执行方式与调用逻辑 | `使用规则` / `写作流程` |
| 常见写作错误与误用 | `常见错误` |
| 低频、长说明、维护导向内容 | `references/` |

## 新增内容的判断流程
以后新增内容时，按下面顺序判断：

1. 先判断这是“触发优化”还是“写作规则扩展”。
2. 再判断它是“通用规则”还是“只适用于某一部分/某类论文”。
3. 如果是通用规则，优先补入主 `SKILL.md` 的已有区块。
4. 如果只是低频长说明，优先放进 `references/`，主文只留入口。
5. 如果这条内容会改变触发边界，必须同步检查 `description` 和 `when_to_use`。
6. 如果它本质上属于建模、求解、评审，而不是写作，就不要硬塞进本 skill。

## 写法规范
- 解释“为什么这样写”，不要只堆“必须”。
- 新规则尽量短，优先补入已有区块，不轻易新开大区块。
- 不写叙事式历史，不写一次性案例总结。
- 能归入现有摘要、12 个正式正文部分或 3 个扩展部分体系，就不要重复发明新层级。
- 新增内容要优先减少跑偏，而不是单纯增加篇幅。
- 如果内容很长、很低频、很维护导向，优先放 `references/`，不要把主 `SKILL.md` 前半段写重。

## 修改前检查清单
- 这条内容是否真的是高频、可复用规则。
- 是否和已有区块重复。
- 是否本来属于别的数模 skill。
- 是否会改变触发边界。
- 是否需要同步调整 `description` 或 `when_to_use`。

## 修改后检查清单
- frontmatter 是否仍然清楚说明“数模论文写作”而不是建模求解。
- 新内容是否放在了正确区块。
- 主 `SKILL.md` 是否仍然保持“摘要前置 + 12 个正式正文部分 + 3 个扩展部分”的稳定结构。
- 是否引入新的重复表述。
- 是否仍然清楚区分“论文写作”与“模型求解/评审复核”。

## 常见错误
- 把论文写作 skill 写成建模求解 skill。
- 把某个具体模型方法细节直接塞进写作主文。
- 增加新规范时破坏摘要前置或 12 个正式正文部分的固定结构。
- 只补写作要求，不补触发边界和入口说明。
- 增加内容后不检查 `description` / `when_to_use`。

## 维护时的默认原则
- 能少改就少改，优先最小改动。
- 先补触发与入口，再补写作细则。
- 先保证结构稳定，再补充扩展规范。
- 如果新增内容很长，优先下沉到 `references/`。

## 建议回归测试提示词
- “按摘要前置、12 个正式正文部分给我搭一篇数模论文框架。”
- “我现在只想写摘要和问题分析，你按数模论文口径来。”
- “帮我检查这篇数模论文的标题、排版和图表规范。”
