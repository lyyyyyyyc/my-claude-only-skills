# 符号说明写作要求

## 输出契约
- 正文默认只输出一个三线表，标题为 `四、符号说明`；除表格本身外，不写引导句、分项说明、示例说明或总结句。
- 表头默认固定为 `符号 / 说明 / 单位`，一行只解释一个符号或一组结构完全相同的下标。
- 表内只收录主要全局符号，篇幅通常控制在半页左右，内容较多时尽量不超过一页；不机械追求固定数量。
- 符号较多时，在同一张表内按“集合与下标 -> 基础数据 -> 评价模型 -> 预测模型 -> 优化模型 -> 输出指标”的顺序排列，不把所有局部变量堆成超长表。
- 表格使用标准三线表：无竖线，不使用底纹、逐行边框或大量内部横线。

## 生成前先做符号台账
起草符号表前，先扫描正文公式、变量定义、数据处理和结果说明，建立内部台账：

| 符号 | 含义 | 单位或取值域 | 首次出现位置 | 使用范围 | 是否收录 |
|---|---|---|---|---|---|
| [符号] | [本题中的完整含义] | [单位 / 取值域] | [章节或公式] | 全局 / 局部 / 程序内部 | 是 / 否 |

- 台账只用于筛选和一致性检查，不直接作为论文正文输出。
- 先删除已废弃符号，再处理一符多义、一量多符、下标漂移和单位不一致，最后生成三线表。

## 应该收录的符号
- 全文反复出现的核心决策变量、状态变量、预测变量和评价指标。
- 多个模型共同使用的样本数量、指标数量、时间变量、权重和基础参数。
- 目标函数、约束条件和核心推导中的关键参数，例如回归系数、增长率、转移概率、损耗率、惩罚系数和修正系数。
- 样本集合、指标集合、时间集合，以及 `i`、`j`、`t` 等贯穿全文的全局下标。
- 全文使用的向量、矩阵、张量、目标函数或价值函数。
- 论文自行构造并在后文持续使用的综合指数、校正参数、创新指标和新概念。
- 具有明确业务含义、物理含义、取值范围或计量单位的全局量。

## 不必收录的符号
- 只出现一次的临时变量，应在对应公式附近解释。
- 仅在某一局部模型或单个小节中使用的符号，可在该小节首次出现时定义。
- `min`、`max`、`sum`、`ln`、`exp` 等常见运算符，除非论文为其赋予了特殊含义。
- 模型修改后不再使用、仅为可能使用而预留的符号。
- 只在程序内部使用的循环变量、数组名、临时对象名和代码字段名。
- 为了显得复杂而列出的字母，以及正文和公式中没有实际用途的符号。

## 符号选取原则

### 优先采用通用符号
- 尽量遵循教材、经典模型和相关文献中的惯用表示，例如样本数量 `n`、指标数量 `m`、时间 `t`、权重 `w`、概率 `p`、均值 `\mu`、标准差 `\sigma`、误差项 `\varepsilon`。
- 经典模型的主符号应尽量保持惯例；改进模型优先通过上下标、上标或附加参数区分，而不是随意更换主字母。

### 不盲目追求生僻字母
- 根据变量属性选择领域中常见、容易辨认的符号，不用生僻希腊字母制造复杂感。
- 一般不直接用“成本”“销量”等中文字符充当公式变量；应选择清晰的拉丁字母或希腊字母，并在说明列写完整中文含义。

### 保持助记性但服从领域惯例
- 成本可优先考虑 `C`，距离可考虑 `d`，时间可考虑 `t`，速度可考虑 `v`，概率可考虑 `p`。
- 助记性不能凌驾于经典模型惯例，也不能造成同一字母在全文中承担多个含义。

## 单位与量纲
- 距离、速度、成本、时间、能耗、排放、质量、面积等有量纲变量必须注明单位。
- 集合、索引、无量纲系数和纯比例量统一在单位列写 `/`；全文不得在 `/`、`—` 和“无量纲”之间来回切换。
- 百分数若按百分比表达，单位列写 `%`；若按 `0` 至 `1` 的比例进入模型，单位列写 `/`，并在含义中说明取值范围。
- 符号表与正文必须统一元、万元、年、月、小时、千米、米、`km/h`、`kg` 等口径。
- 若正文发生单位换算，必须在数据处理或模型建立处说明换算关系，不能让符号表写“万元”而公式直接代入“元”。
- 目标函数各项相加、物理方程两侧或约束比较量应检查量纲是否一致；无量纲化后要明确新的变量是否仍沿用原符号。

## 符号一致性
- 一个符号只对应一个含义，一个变量尽量只使用一个符号。
- 严格区分大小写、标量与向量、普通体与粗体，例如 `x`、`X` 和 `\mathbf{x}` 不得混用。
- 固定 `i`、`j`、`t` 等下标的指代对象；不得在不同章节把 `i` 从样本下标改成指标下标。
- 避免同一个 `p` 同时表示概率、权重、价格或模型阶数；发生冲突时优先保留领域惯例，并为其他变量重新选符号。
- 上下标、撇号、帽子、星号和年份标记必须与正文公式完全一致；不能在符号表写 `x_i`，正文却主要使用 `x_{ij}`。
- 同一量经过标准化、预测、估计或优化后若含义已经变化，应使用清楚的上标或记号区分，例如原始值 `x_{ij}`、标准化值 `z_{ij}`、预测值 `\hat{y}_t`、最优解 `x^*`。
- 自定义综合指标、创新名词和修正系数必须给出明确含义，不能只写“综合指数”“修正参数”。

## 正文首次出现仍需定义
- 符号已经列入说明表，不代表正文可以直接使用而不解释。
- 每个关键符号在正文首次出现时仍应结合模型语境简短定义，尤其是带上下标、上标或取值域的符号。
- 推荐写法：`设 x_{ij} 表示第 i 个评价对象在第 j 个指标上的原始观测值。`
- 符号表负责集中检索，正文首次定义负责解释当前公式；两者功能不同，不能相互替代。

## 三线表模板
最终正文只保留下面这种表格，不输出本参考文档中的解释性文字：

| 符号 | 说明 | 单位 |
|---|---|---|
| `I` | 样本或评价对象集合 | `/` |
| `J` | 指标集合 | `/` |
| `i` | 样本或评价对象下标，`i \in I` | `/` |
| `j` | 指标下标，`j \in J` | `/` |
| `t` | 时间周期下标 | `/` |
| `x_{ij}` | 第 `i` 个对象在第 `j` 个指标上的原始观测值 | [实际单位] |
| `w_j` | 第 `j` 个指标的权重 | `/` |
| `\mathbf{x}` | 决策变量向量 | [实际单位或 `/`] |
| `f(\mathbf{x})` | 优化模型的目标函数值 | [实际单位] |

- 模板中的符号只是结构示例，必须根据实际论文删除、替换和补充，不能原样套用。
- 若某一符号的单位随指标而变化，例如 `x_{ij}` 对应多个不同量纲指标，可在单位列写“见指标定义”，并在数据或指标表中逐项标明单位。

## 常见错误
- 把所有临时符号、代码变量和数组名全部塞进表格，导致表格过长。
- 全文核心变量很多，表中却只列 `n`、`m` 等简单符号。
- 有量纲变量缺少单位，或单位与正文、数据表和公式口径不一致。
- 含义只写成“第 `i` 个值”“相关参数”等不完整表达。
- 同一符号表示多个含义，或同一变量在不同章节频繁改名。
- 上下标的指代对象在前后章节发生变化。
- 普通文本、公式编辑器和表格中的字母样式、粗体和上下标格式混乱。
- 用符号表完全代替正文首次定义，导致读者无法理解公式语境。
- 自定义指标和创新名词没有明确定义、计算口径或取值方向。
- 三线表出现竖线、底纹、逐行边框或过多内部横线。
- 将目标函数、约束条件、长段解释或模型推导塞入符号表。

## 完成前检查
- 表中是否只保留全局核心符号，局部和程序内部符号是否已剔除。
- 每个符号是否有唯一、完整且与本题对应的含义。
- 单位、量纲、百分比和无量纲表示是否全文一致。
- 大小写、粗体、上下标、估计值和最优值记号是否统一。
- `i`、`j`、`t` 等下标的指代对象是否固定。
- 表内符号是否都在正文实际使用，正文关键符号是否均已覆盖。
- 每个关键符号是否在正文首次出现时再次简要定义。
- 三线表是否控制在合理篇幅，是否没有竖线、底纹和冗余边框。

## 完成后专项审查
- 符号说明生成、重写或实质性修改完成后，必须立即暂停当前写作流程并询问用户：“符号说明已经写完，是否需要调用 `bzd-symbol-notation-checker` 进行审查？请回答是或否。”即使正在连续写整篇论文，也必须先完成本次询问与可选审查，再进入下一章节。
- 若用户明确回答“是”，必须调用 `bzd-symbol-notation-checker`；优先同时提供完整论文，若材料不足则至少提供符号表及相关模型正文，并明确哪些全文一致性项目暂时无法核验。审查完成后必须向用户返回结果，不得只给出调用建议，也不得改用其他通用评审 skill 代替。
- 若用户明确回答“否”，不得调用该 skill，可以继续后续写作流程。
- 若用户回答不明确，必须继续询问，直到得到明确的“是”或“否”；在得到明确回答前，不得默认选择、跳过询问或继续生成下一章节。
