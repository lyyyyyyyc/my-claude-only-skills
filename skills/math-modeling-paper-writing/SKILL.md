# 数学建模论文写作

## 概述
- 本 skill 用于把数模论文写作固定为“摘要 + 12 个正式正文部分”。摘要位于正文前且不计入正文编号；问题一、问题二、问题三的模型建立与求解分别作为第六、第七、第八个一级部分，第九部分为模型的检验与分析，第十部分为模型的评价、改进与推广，12 个正式正文部分不允许随意删减、合并或改名。
- 第一动作必须调用 `math-modeling-brainstorm`，先把题意、子问题关系、模型路线和写作边界对齐。
- 本 skill 负责“论文结构、论文规范与每部分内容要求”，不替代具体建模、代码求解或评委复核。
- 除了摘要和 12 个正式正文部分外，额外提供“排版规范”“标题写法”“图表规范”三个扩展部分，用于规范论文整体视觉呈现、标题命名和图表表达；它们都是补充要求，不替代任何正式部分。
- 正文落笔前，优先按评阅视角和答卷目标倒推写作重点，而不是写到哪里算哪里。
- 当进入任一题号或小问的正文写作时，默认先扫描当前问题目录下可复用的插图和表格资源，再决定正文中哪些位置应直接安放这些图表。
- 当进入摘要写作时，默认先建立“每个小问的结果证据表”，核对数字、单位、指标口径和来源；缺少证据的内容标记为“待核验”，不得由 AI 补造。
- 摘要中每个小问必须保留“针对问题 X”作为定位标识，但不得固定写“本问是[问题类型]问题，需[题目要求]”；中间段优先呈现“小问定位 -> 研究对象/任务 -> 方法及职责 -> 必要操作、阈值或选择理由 -> 关键结果 -> 验证、稳定性或实际含义”的自然链条。
- 摘要正文按“可选总体段 -> 每个小问的主体段 -> 可选收束段 -> 关键词”组织；总体段和收束段都不强制，不能为了补齐结构挤占各小问的核心结果。具体写法、篇幅建议和正反例读取 `references/01-abstract.md`。
- 摘要只压缩呈现核心方法、关键结果和必要的验证结论，不展开模型公式、完整超参数搜索或算法伪代码；详细内容分别交给模型方法、调参和图表相关 SKILL。
- 当进入“模型的建立与求解”部分时，默认要求数学公式写得足够完整，至少应覆盖：变量或统计量定义、关键关系式、目标函数、约束条件、归一化或评分口径、罚项或修正项；不要只给零散几条象征性公式。
- 对优化类、评价类或带算法求解的正文，默认优先把“目标函数 + 约束条件 + 中间指标/罚项”组织在相邻位置；若原文分散得较开，必要时主动整理出一个“集中公式表达”小节，方便评委一次看清完整模型。

## 什么时候优先用本 skill
- 用户要写整篇数模论文，或明确说“按数模论文结构来写”。
- 用户只要补某一个正式部分，例如摘要、问题分析、模型假设、符号说明、模型建立与求解等。
- 用户已经完成建模，希望把思路、结果和结论转成论文正文。
- 用户不是要重新求解，而是要按数模论文标准整理结构、标题、排版或图表表达。

## 第一优先动作
当本 skill 被触发时，始终先做以下三件事：

1. 判断用户要的是“整体论文规范”“整篇论文”还是“单个部分”。
2. 判断当前需求属于摘要、12 个正式正文部分中的哪一部分、3 个扩展部分中的哪一部分，还是属于“总规范总览”入口。
3. 只读取当前需要的参考文档，不把全部 `references/` 一次性展开。

## 摘要与固定的 12 个正式正文部分
摘要：正文前的独立部分，不计入正文编号。

1. 问题重述
2. 问题分析
3. 模型假设
4. 符号说明
5. 数据处理与分析
6. 问题一模型建立与求解
7. 问题二模型建立与求解
8. 问题三模型建立与求解
9. 模型的检验与分析
10. 模型的评价、改进与推广
11. 参考文献
12. 附录

## 总规范总览（辅助入口）
- 当用户要“整体论文规范”“完整格式要求”“总排版清单”“总检查表”时，优先读取 [references/00-paper-format-spec.md](references/00-paper-format-spec.md)。
- 该入口只做总览、汇总与快速检索，不替代摘要、12 个正式正文部分和 3 个扩展部分。

## 标题与编号默认规则
- 正文主体默认采用中文一级标题：`一、二、三...`
- 正文二级标题默认采用小数编号：`1.1`、`1.2`、`2.1`、`2.2` ...
- 默认将“摘要”单独写为 `摘要`，不并入中文一级标题编号。
- 必须将二者写成一级标题 `十一、参考文献` 与 `十二、附录`，以保证 12 个正式正文部分的编号完整；不得省略这两个一级编号。

## 正文图表前置扫描规则
- 当用户要求写某一题、某一小问或某一章节的论文正文时，先定位当前正在处理的题号目录或小问目录，再扫描其中已有的图表资源。
- 目录定位默认按“正文文件所在目录反推问题目录”执行：
  - 若当前正文文件位于 `Solve/问题X/docx/`，优先扫描 `Solve/问题X/result/`。
  - 若当前正文文件位于 `Solve/问题X/qY/docx/`，优先扫描 `Solve/问题X/qY/result/`；必要时再补扫上一级 `Solve/问题X/result/`。
- 图像资源优先扫描以下位置：
  - `result/论文正文插图/`
  - `result/`
  - 其他名称明确表明“正文插图、结果图、示意图、流程图”的子目录
- 表格资源优先扫描以下位置：
  - `result/` 下可直接支撑正文结论的 `csv/xlsx/xls/md`
  - 名称中带有“结果表、小表、汇总、对照表、参数表、验证表、敏感性表、稳健性表”的文件
  - 若存在图表清单文件，例如 `论文正文插图清单.csv`、`论文表格清单.csv`，优先读取清单，再定位实体文件
- 扫描后的目标不是“把文件列出来”，而是建立“图表用途 -> 建议章节 -> 对应文件”的映射，判断哪些图表适合放进当前正在写的正文。
- 若图表与当前章节内容高度匹配，则在正文写作时默认直接插入合适位置，并在图表后补一到两句解释说明其证明了什么；不要只把图表堆到文末。
- 若原始表格过长、过宽或明显更适合做附录，则先提炼成正文可承载的小表，再放入正文；不要把原始大宽表直接塞进正文。
- 若扫描后没有发现合适图表，可正常继续写正文，但应明确当前章节是“暂无可复用图表”，而不是跳过扫描步骤。

## 图表与解释的先后顺序硬规则
- 正文中的所有图、表必须放在其对应解释文字之前，固定采用“先展示证据载体，再分析证据”的顺序。
- 默认结构为：章节或小节标题 -> 图/表主体及题注 -> 对应文字解释与结论。
- 表格内部仍按“表题 -> 表格主体”排版；图片内部仍按“图片主体 -> 图题”排版。完整顺序分别为“表题 -> 表格主体 -> 解释文字”和“图片主体 -> 图题 -> 解释文字”。
- 不得先写“由图 X 可知”“由表 X 可知”等图表解释或结论，再在后文补放对应图表。
- 图表后的第一段应直接解释该图表展示的关键趋势、差异、数值、关系或结论，避免图表与解释跨越多个无关段落。
- 同一小节需要多个图表时，原则上逐一采用“图/表 -> 紧随其后的解释”；不得先集中写完全部解释，再集中堆放图表。

## 题型写作模板路由
- 这些模板负责把已经确定的模型、算法和验证结果组织成论文，不负责替代模型方法选择、数据预处理或画图。
- 进入问题一、问题二或问题三的“模型建立与求解”一级部分时，先判断当前问题的主模型属于哪一类，只读取 `references/07-model-building-and-solving.md` 中对应的套路；不要把四类套路全部展开到同一问题里。
  - 评价类：指标体系、指标方向与正向化、赋权过程、综合评价、排名或分级结果。
  - 预测类：特征工程证据、模型表达式、参数记录、验证结果与基线对比。
  - 优化类：决策变量、目标函数、约束条件、算法求解过程和方案对比。
  - 机理分析类：机理框架、关系方程、参数辨识、联立求解和真实数据验证。
- 进入“模型的检验与分析”且用户要求模型检验、误差分析、灵敏度分析或稳健性分析时，读取 `references/08-model-testing-and-analysis.md`；先依据模型之间的同质性确定统一汇总还是分别检验，再匹配数据结构选择 K 折、滚动验证、分组验证、独立测试或其他适用方法。
- 当“模型检验、参数敏感性与稳健性分析”正文已经正式写完并完成结果口径核对后，必须立即暂停并询问用户：“模型检验、参数敏感性与稳健性分析已经写完，是否需要调用 bzd-model-solution-checker 进行自查？请回答是或否。”该询问只在该正文完整交付后触发，不得在计划阶段、资料扫描阶段、局部修改阶段或普通结果检查阶段提前触发；询问后不得继续补写、润色或自动调用其他检查。用户明确回答“是”时，才调用 `bzd-model-solution-checker`；明确回答“否”时，不得调用；回答不明确时，继续要求用户明确回答“是”或“否”。
- 进入“模型的评价、改进与推广”时，只读取 `references/08-model-evaluation-improvement-and-promotion.md`，引用第九部分检验证据评价优点、局限、改进方向和推广场景，不在第十部分重复完整检验过程。
- 论文写作 SKILL 负责段落结构、证据表、图表位置和结果解释；`math-modeling-model-and-methods` 负责公式和方法路线；`math-modeling-data-preprocessing` 负责划分与防泄漏；`math-modeling-plotting` 负责图形生成。跨 SKILL 的后续调用只作为用户可选择的下一步，不自动替用户调用。

## 摘要质量控制入口
- 摘要正式起草前，先读取 `references/01-abstract.md` 和 `references/result-traceability-checklist.md`。
- 先从题目、小问关系、代码输出、CSV/Excel、验证表和正文结果中建立证据表，再生成摘要；不要先写一版“看起来完整”的摘要再倒推数字。
- 每个小问的摘要段必须以“针对问题 X”作为定位标识，后面直接写已执行的处理、方法、求解动作和结果，不加入“本问是[问题类型]问题，需[题目要求]”这一固定句式。
- 起草时先检查“任务、方法、结果”三个核心要素是否完整；只有存在真实的新框架、组合方法或对比证据时才补充创新点。可选总体段负责交代核心场景、矛盾和总体任务，中间段负责方法职责、必要理由、可执行步骤与结果，可选收束段只用于统一验证结论或有证据的创新特色；不要用背景空话填充篇幅。
- 数字必须能回溯到结果文件或可复算过程，并保留对象、指标、单位、方向、样本范围和小数位口径；没有证据时使用 `[待核验]`，不生成最终断言。
- 摘要中的方法、参数、验证方式和结果必须能在正文找到支撑；摘要不放公式、图表或完整算法步骤，但可以用一句话报告真实的验证结果。
- 摘要的篇幅、开头句数和数字数量是排版建议，不是奖项判定硬规则；没有模板要求时，关键词默认选 `4` 到 `6` 个，最终仍优先服从当届竞赛通知和实际内容。
- 摘要写作完成后，必须立即暂停摘要流程并询问用户：“摘要已经写完，是否需要调用 `bzd-abstract-checker` 进行检查？请回答是或否。”若用户明确回答“是”，必须调用 `bzd-abstract-checker` 对当前摘要进行审查，并向用户返回审查结果；若用户明确回答“否”，则不得调用该 skill。若回答不明确，必须继续询问，直到得到明确的“是”或“否”；在得到明确回答前，不得自动调用，也不得跳过询问。

## 使用规则
- 若用户要“整体论文规范”“总格式要求”“完整排版清单”，优先读取 `references/00-paper-format-spec.md`，再按需要跳转到具体 `references/*.md`。
- 若用户只要求某一个部分，仅读取对应的一个 `references/*.md`，不要把摘要、12 个正式正文部分和额外部分全部展开。
- 若用户写摘要，必须同时读取 `references/01-abstract.md` 与 `references/result-traceability-checklist.md`；若摘要涉及误差、灵敏度或稳健性，只追加读取 `references/08-model-testing-and-analysis.md`。
- 若用户写“模型假设”部分，正文最多写 `6` 条，并按重要性筛选真正影响模型结构、目标函数、约束条件、数据口径和结果解释的假设；不得为了凑数扩写或拆分同类假设。
- 模型假设正文必须采用截图式版面：标题后直接列出从 `1.` 开始的连续编号条目，编号到实际条数为止，且不超过 `6`；不得设置加粗小标题、二级小节、假设分类标题或专门的假设说明表。
- 每条假设控制在约 `40` 个汉字，允许因必要的数学符号或限定条件略有浮动；应使用一句简洁完整的话表达假设，不展开依据、作用、风险和检验过程。
- 模型假设默认省略引言和总结，直接列编号条目；只有用户明确要求时才增加一段简短引言，且不得写空泛套话。
- 若用户写“符号说明”部分，正文默认只保留一个三线表；除表格本身外，不额外写任何引导句、分项说明、示例说明、优缺点解释或总结句，除非用户明确要求保留其他文字。
- 若用户要求“整篇数模论文”或“完整论文结构”，按“摘要前置 + 12 个正式正文部分”顺序推进，逐部分写作。
- 固定 12 部分结构默认对应题目恰有问题一、问题二、问题三。若实际问题数不是 3，不得擅自增删模型一级部分或沿用错误编号，必须先询问用户是否调整正文结构及后续章节编号。
- 若用户正在写题号正文、子问正文或某一章节正文，起草前先执行一次“当前问题目录图表扫描”，优先收集当前目录下能直接支撑正文论证的插图和表格。
- 若用户正在写“模型的建立与求解”部分，除自然语言解释外，默认同时补齐足量数学公式；尤其是目标函数、约束条件、归一化、惩罚项和变量取值范围，尽量写在一起或前后紧邻，必要时主动整理成一个集中公式块。
- 若用户正在写“模型的建立与求解”部分，且目标函数、约束条件等同组公式较多、但不需要逐条长解释时，默认优先采用“一个大括号 + aligned”的集中写法，把同层级公式并列收在同一公式块中，再在公式后用简短文字解释关键符号与业务含义；不要把本可集中展示的公式机械拆成许多独立小公式。
- “模型的建立与求解”内部不得单独设置“变量与参数定义”小节，也不得制作专门的变量、参数、输入输出或符号定义表。变量和参数仍必须完整说明，但应融入“模型建立”小节，在其首次进入正文或公式时用连续文字就近解释；完整符号汇总由前文“符号说明”承担。若确需展示超参数、经济情景参数或求解器配置，只能制作服务于参数取值、比较或复现的参数表，不得用表格替代变量的正文说明。
- “模型的建立与求解”内部不得单独设置“本问结论”小节。本问的数值、方案、排名、预测或决策应直接写入“求解结果”或“结果分析”，避免与章节末尾重复总结；删除这两个小节后必须连续重排其余小节编号，不得留下空号。
- “问题分析”必须作为独立正式部分，不得并入“问题重述”。
- 若多个小问高度相似，允许采用“一个主模型 + 后续小问增加约束 / 改参数 / 改目标”的写法；但这种策略要在“问题分析”和“模型的建立与求解”两个部分都说明清楚。
- “排版规范”属于额外扩展部分，可以单独调用，也可以在整篇论文完成后作为统一排版检查表使用。
- “标题写法”属于额外扩展部分，可以在论文尚未起草前先调用，用于先定题目名；也可以在正文完成后反查标题是否准确概括模型与问题。
- “图表规范”属于额外扩展部分，可以单独调用，也可以在排版和润色阶段统一检查表格、函数图、结果图、图题和表题。
- 摘要中每个需要定量回答的小问优先选择 `1` 至 `3` 组最能区分结论的真实数字或对比证据，全文不设数字总量硬上限；定性建议题应报告明确建议及其数据依据，不得为了满足数字数量制造数字。
- 摘要中不展开公式、完整检验过程和超参数搜索；可报告与结论直接相关的验证方式和结果，例如测试集误差、排序差距或扰动保持率。
- 最终超参数由用户或建模流程确定；论文写作 SKILL 只负责记录和准确呈现，不擅自选择、修改或补全最终超参数。
- 若扫描到适合正文的图表，默认不是只给用户建议，而是在生成或修改正文时直接把图表放到对应段落附近，并保证“图表主体及图题表题 -> 正文解释”的顺序连续出现。
- 若用户后来增加新的辅助要求，例如页眉页脚规则，应继续作为扩展参考文档追加，不得改动摘要与 12 个正式正文部分的定义。

## 写作流程
1. 先调用 `math-modeling-brainstorm`，确定题目目标、子问题关系、建模主线和论文口径。
2. 判断用户是要“整体论文规范”“单个部分”还是“整篇论文”。
3. 若用户要整体规范，先读取 `references/00-paper-format-spec.md`；若用户要具体章节或具体规范专题，再读取对应参考文档，按其中的“写什么 / 不写什么 / 常见小节 / 常见扣分点 / 衔接方式”执行。
4. 若准备正式起草，先列清楚：题目要回答哪些问题、每个问题用什么形式呈现结果、每问需要哪些关键数据、每个量是一组结果还是多组对比结果。
5. 若当前任务涉及正文写作，先定位当前题号目录或小问目录，并扫描其中的 `result/论文正文插图/`、`result/` 以及可直接复用的结果表文件。
6. 若存在图表清单文件，优先读取清单；若没有清单，则按文件名与内容自行判断“图表用途 -> 建议章节 -> 插入位置”。
7. 在正式写正文时，将适合当前章节的图表直接嵌入对应位置，按“图/表主体及题注 -> 解释语句”的顺序连续排布；不得先写解释再补图表，也不把应当承担论证作用的图表留到最后统一堆放。
8. 若当前任务包含“模型的建立与求解”，则在正式落笔前先检查：目标函数是否明确、约束条件是否成组、关键统计量和归一化口径是否有公式支撑；若这些内容分散，默认在正文中主动补成一个集中公式表达小节。
9. 生成“模型的建立与求解”提纲时，不设置“变量与参数定义”和“本问结论”两个独立小节；变量、参数就近并入模型建立，最终答案并入求解结果或结果分析，其余小节编号连续排列。
10. 若用户写的是整篇论文，强制保持“摘要前置、12 个正式正文部分”的顺序；问题一、问题二、问题三的模型建立与求解分别作为第六、第七、第八个一级部分，第九部分单独写模型的检验与分析，第十部分再写模型的评价、改进与推广，不跳段、不合并。
11. 若用户要求检查视觉呈现、标题层级、图表、公式和留白，再额外读取“排版规范”部分。
12. 若用户要求拟定论文题目，或检查标题是否规范、是否准确体现核心模型，再额外读取“标题写法”部分。
13. 若用户要求规范表格、函数图、结果图、图题、表题和图例，再额外读取“图表规范”部分。
14. 整篇或关键章节完成后，必须调用 `math-modeling-judge-review` 做交付前复核。
15. 若当前任务是撰写“模型检验、参数敏感性与稳健性分析”正文，必须在该正文全部完成、结果已核对且文件已写入后立即暂停，向用户发送固定询问：“模型检验、参数敏感性与稳健性分析已经写完，是否需要调用 bzd-model-solution-checker 进行自查？请回答是或否。”固定询问必须是当前回复的最后一句，后面不得追加任何内容；在用户明确回答前不得调用该 skill，也不得把模型建立阶段的询问提前到本阶段之前。

## 常见错误
- 把“问题分析”写成问题重述的补充说明，导致正文少一个正式部分。
- 直接复制题目原文到“问题重述”，造成查重和表达扣分。
- 在“模型的建立与求解”里直接照搬教材或网页算法说明，没有解释符号、节点、目标值在本题中的实际含义。
- 在“模型的建立与求解”里公式过少，只写概念性文字，导致正文像思路说明而不是可核查的数学模型。
- 目标函数、约束条件、归一化和罚项分散在几页不同位置，却没有再整理成一个集中公式块，导致评委无法快速看到完整模型。
- 把“变量与参数定义”单独设为二级小节，或在模型建立部分制作“变量定义表”“参数定义表”“主要量定义表”等同类表格，重复前文符号说明并割裂变量与公式；应在模型建立中用连续文字随公式就近解释。
- 在每问末尾单设“本问结论”小节，重复求解结果和结果分析；应把最终答案直接落在结果段中。
- 在“模型假设”里写空话或常识，不能真正服务模型简化。
- 参考文献写法混乱，或正文引用和文末条目对不上。
- 附录里贴外部代码原文，或只改变量名却不改思路与实现。
- 当前问题目录下明明已有可复用的结果图、结果小表或插图清单，却在正文写作前没有扫描，导致正文中该有的图表缺位。
- 找到了图表资源，却只在对话里口头建议，不在正文文件里实际安放，导致“图表资源存在但论文正文没用上”。
- 先写“由图 X 可知”或“由表 X 可知”等分析结论，后放对应图表，导致读者在看到证据前先读解释；必须调整为“图/表及题注 -> 解释文字”。
- 摘要使用“本问是[问题类型]问题，需[题目要求]”作为固定模板，造成题意重复、模板感强且挤占结果篇幅；必须保留“针对问题 X”，直接衔接实际处理和结果。
- 摘要中的数字没有来源、单位或指标口径，或把一个小问的结果错放到另一个小问。
- 把模型公式、完整超参数表和算法伪代码塞进摘要，导致摘要失去压缩和定位功能。
- 在没有真实验证结果时写“模型有效”“结果可靠”“结果稳健”等结论性评价。
