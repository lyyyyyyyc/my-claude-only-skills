# 模型建立阶段自然化

本文件对应原模块 B，用于把已经确定的数学模型写成有作者判断、公式衔接和适用边界的论文叙述。
它不负责选择模型，也不允许在没有记录时虚构模型选择历史。

## 1. 先保护公式，再写叙述

在改写前登记：

- 状态变量、决策变量、参数、下标、单位和符号约定。
- 方程、目标函数、约束、初始条件、边界条件和公式编号。
- 公式对应的题目对象、输入、输出和验证方式。

改写后逐项核对公式和文字是否一致。不能为了语言自然而改变量名、改变符号方向、删掉约束、改变参数含义或
把“近似”等级改成“精确”。

## 2. 每个子模型的作者视角说明

在有足够证据时，为每个子模型补一段连贯的建模思路，建议覆盖：

1. 题目中的对象如何被抽象成变量或状态。
2. 为什么当前模型结构能表达题目要求。
3. 关键假设如何导致相应的方程、目标或约束。
4. 选择该方法的实际依据，以及它的代价或适用边界。
5. 公式如何把输入传递到输出，以及后续怎样验证。

不要把它写成“步骤 1 -> 步骤 2 -> 步骤 3”的流水账，也不要只堆模型名称。可以先给直观出发点，再说明数学
约束，最后指出容易误解的分支或边界条件。

## 3. 方案比较必须有真实依据

只有用户或记录确实提供过备选方案比较时，才写“我们没有采用……”。比较至少说明：

- 备选方案解决什么问题。
- 它与本题数据、离散结构、边界条件或计算预算哪里不匹配。
- 试算、文献、题面条件或量级分析提供了什么依据。
- 当前方案牺牲了什么，以及如何验证这种取舍的影响。

如果没有真实的历史试算记录，使用当前决策表述：

> 本文采用离散模型，因为题目将对象定义为若干独立单元；连续介质近似可能无法保留单元间约束。该取舍的影响在……中检验。

不得把当前推理伪装成已经发生的失败实验。

## 4. 假设风险要落到模型上

每个重要假设至少连接一个后文对象：目标函数、约束、概率分布、参数、边界条件或结果解释。可以用以下结构：

> 假设内容 -> 采用依据 -> 对模型的影响 -> 可能失效的条件 -> 验证或敏感性分析。

“题目没有给出摩擦系数，所以取 0.3”不够完整。应明确 0.3 的真实来源；若只是经验设置，标记为经验设定，
并报告适用范围和敏感性分析，不能包装成实测标定。

## 5. 公式之间要有连接句

- 先说明公式要表达的关系，再给公式，再解释新增符号和结果含义。
- 公式后不要重复逐字翻译公式；只解释本题中特别容易误读的变量、约束或边界。
- 从一个方程进入下一个方程时，明确指出是代入、递推、离散化、线性化、归一化、优化化还是统计估计。
- 对同一组目标函数和约束，优先集中展示并解释，不拆成大量只有符号变化的句子。
- 写出算法名称时，同时说明它处理的是哪个数学对象、为什么需要它以及输出如何进入下一环节。

## 6. 可以使用的叙述形态

> 建立运动学模型的出发点是驱动端的位置和速度已知，未知量是约束如何逐节传递到后续单元。相邻铰接点之间的距离
> 保持为给定长度，因此第 i 个单元的位置必须同时满足距离约束和运动方向约束。由此得到递推方程；递推完成后，
> 再用连续性条件排除几何上可行但方向突变的分支。

如果“方向突变曾经在实际计算中出现”，可以继续写排查过程；如果没有记录，只能写成模型设计中的分支处理，不能
写成已经发生过的错误。

## 7. 从内容层降低模板感

模型建立部分最容易出现“只报模型名、不交代判断”的问题。改写时优先补齐已有证据能够支持的内容：

- **模型选择理由**：不要只写“本文采用随机森林/XGBoost/线性回归”，要说明题目目标、数据结构、非线性、样本量、可解释性、
  约束或计算预算与选择之间的关系。若有实际比较，说明为什么没有采用备选模型；没有比较记录时，不虚构“试过后失败”。
- **参数来源**：学习率、窗口长度、惩罚系数、阈值、初值或边界必须注明来自网格搜索、验证集、文献、经验规则、数据分布或题面条件中的哪一种。
  “经验取值”可以写，但不能包装成实测标定。
- **失败方案**：只有在实验日志、代码版本或用户记录中确实存在时，才写尝试过的方案、失败现象、放弃原因和修正结果。
  没有记录时改写为“备选方案的潜在限制”或“拟验证事项”。
- **边界条件**：明确模型在哪些时间范围、参数范围、数据分布或业务条件下有效，在哪些场景可能失效。边界应连接到假设、约束或验证方案。

这四项比“增加高级术语”更能体现真实的建模判断。每一项都必须落到当前题目的变量、公式、数据或算法上。
