# 数学建模代码注释自然化

本文件对应原模块 D，适用于 Python、MATLAB、R 或伪代码。代码注释要帮助未来的作者理解实现决策，不能靠添加大量“踩坑故事”制造个性。

## 1. 注释写为什么，不重复写是什么

- 函数名、变量名和类型已经清楚表达“是什么”时，注释解释“为什么这样做”。
- 说明边界条件、数值稳定性、单位换算、数据口径、算法取舍和不可随意修改的顺序。
- 删除 `This function computes...`、`This variable stores...` 等只复述代码的模板注释。
- 注释应短而具体，和紧邻代码保持一致；不要把论文段落复制到代码里。

示例：

```python
# 先 unwrap 再求相邻角度差，避免 theta 穿过 pi 时产生人为的大跳变。
theta_raw = np.arctan2(y_points, x_points)
theta = np.unwrap(theta_raw)
```

## 2. “踩坑注释”必须真实

可以在关键代码处记录真实发生过的错误、排查结果或容易复现的陷阱，例如角度跳变、单位混用、索引偏移、
数据泄漏和边界条件遗漏。但必须来自代码提交、实验日志、用户说明或可复核结果。

没有真实记录时，改写为中性的风险提示：

```python
# 注意：这里使用训练集统计量进行标准化，避免把验证集信息泄漏到训练过程。
```

不能编造“这里曾经导致结果错误”的故事，也不要求每个项目固定加入三处踩坑注释。

## 3. 保持代码和论文一致

- 注释中的变量名、单位、时间范围、模型名称和公式编号必须与论文一致。
- 解释实现细节时不能偷偷改变算法、超参数或数据划分。
- 说明一个修正时，同时指出修正影响了哪一项结果；没有重跑结果时标记为“待验证”。
- 代码注释用中文还是英文，服从项目已有风格；不要为降模板感随意混用语言。
