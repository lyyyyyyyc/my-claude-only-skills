# 结果分析阶段自然化

本文件对应原模块 C。核心顺序是“数据观察在前，解释在后”，让结果分析来自表格、图形和指标，而不是泛泛的教科书式结论。

## 1. 每段先给数据锚点

在解释趋势、机制或异常前，尽量明确：

- 数据来自哪张表、哪幅图、哪一列/组/条件。
- 至少一个实际数值或区间，以及它的单位和样本范围。
- 变化方向和幅度，例如增加多少、下降多少、相对变化多少。
- 与前文预测、假设、基线或理论值的关系。

“结果表明系统性能逐渐提高”不能作为完整分析。应改成类似：

> 在图 4 的测试集结果中，温度由 20 °C 升至 60 °C 时，MAE 从……变为……，相对下降……。这一变化与……假设一致，
> 但在……区间出现……偏离，说明……解释需要限定在……条件下。

示例中的数字必须换成真实结果；没有图表或结果来源时使用 `[待补证据]`，不得补数字。

## 2. 从观察到解释的五层问题

对每组结果按需要回答，不要求每段机械覆盖全部项目：

1. **变化趋势**：线性、非线性、饱和、阈值、拐点或单调性是什么。
2. **影响因素**：哪个变量主导，是否存在竞争、耦合或交互作用。
3. **异常现象**：哪一个点偏离整体规律，偏离幅度有多大。
4. **机制联系**：解释是否来自已声明的物理、统计或业务机制。
5. **对比意义**：与基线、理论、文献或其他实验是否一致，差异可能来自哪里。

解释强度必须匹配证据：相关数据只能支持“与……一致”或“可能反映……”，不能直接升级为因果结论；没有机制
证据时不要使用“证明了根本原因”。

## 3. 保持自然的段落节奏

- 不要每段都以“图 X 显示……”开头；可以从关键变化、对比对象或问题切入，再回指图表。
- 不要连续使用“结果表明”“可以看出”“说明了”而没有新增信息。
- 先报告最能区分结论的观察，再补解释、限制和验证。
- 重要结果可以用短句强调，复杂机制用完整长句说明；不强制固定句长或固定数字数量。
- 结论性评价应有范围，例如“在测试集和当前扰动范围内保持稳定”，不要写无条件的“模型始终可靠”。

## 4. 真实异常或调试过程

如果用户提供了实际的异常现象和排查记录，可以在结果分析或验证章节写出：

1. 初始结果和具体异常。
2. 为什么它与题面、物理直觉、假设或基线冲突。
3. 检查过的中间量、函数、方程、参数或数据切片。
4. 定位到的真实原因以及修正措施。
5. 修正前后的可核验差异。

如果没有这些记录，不得为了“降低 AI 率”编写两段虚构的意外发现。可以改写为“潜在风险与检查方案”，
明确它是预防性分析，而不是已经发生的调试经历。

## 5. 验证话术的边界

- 有真实对比数据时，报告误差、差距、置信区间、显著性或稳定性指标，并指出条件。
- 只有单一结果时，不把它包装成“优于现有方法”；至少需要同目标、同数据划分、同指标和可比预算的基线。
- 没有做灵敏度、消融或重复运行时，不写“经灵敏度分析证实”或“结果具有高度稳健性”。
- 图表中的趋势可以描述，但机制解释要标明理论、文献或实验依据。

## 6. 结论必须粘在证据上

写任何结论前先回答“证据在哪里”。一条结论至少应能回指以下一种材料：

- 数据表中的数值或区间。
- 图中的曲线、峰值、拐点、排名或误差分布。
- 公式、约束或量级计算。
- 代码输出、日志或可复算结果。
- 真实引用文献。
- 真实的异常样本或排查记录。

如果没有证据，就不要写成肯定句；使用 `[待补证据]` 或改成待验证的研究问题。尤其不要用“显著提升”“证明有效”“具有重要意义”
替代具体指标。

## 7. 异常点、敏感区间和极端场景

结果分析不需要强行制造失败，但有真实材料时应主动检查并呈现：

- 最大误差或最偏离基线的样本。
- 排名发生变化的条件或阈值。
- 参数扰动区间内的稳定和不稳定区域。
- 极端输入、边界条件或稀疏样本下的表现。
- 结果与前文估计、理论或假设不一致的地方。

每个异常都要区分“观察到的事实”和“可能的解释”。解释证据不足时，写“可能与……有关”，不要直接宣布根因。

## 8. 用自己的图倒逼文字

当论文已有结果图时，先只看图和图注，再写文字；不要先套用 AI 生成的泛化段落。建议按以下顺序：

1. 写三条肉眼可核查的观察，例如“图 4 中 4--6 h 的增长最快”“参数超过 1.2 后曲线趋于平稳”“方法 B 在高噪声条件下排名下降”。
2. 回到程序输出、表格或原始数据，确认观察中的数值、范围、峰值和时间点，避免只靠目测估计。
3. 将每条观察分成两层：数据直接支持的结论，以及需要理论、文献或额外实验才能支持的可能解释。
4. 最后补一句与模型决策相关的结论，例如选择某一参数、方案或约束，并明确它适用于什么条件。

图能约束文字的具体性，但不能替代统计检验或机制证据。没有读图或没有程序输出时，不要声称“从图中可以证明”。
