# Math Modeling Humanizer

## 定位与边界

这个 Skill 负责数学建模论文的“自然化改写”，目标是降低套话、机械并列、空泛结论和重复句式，
让已经完成的研究更清楚地呈现作者的建模判断与数据观察。它不是重新建模、补做实验、修改数据、
编造引用或保证某个 AI 检测器分数的工具。

必须遵守以下事实边界：

- 不改变数据、公式、变量、单位、参数、评价指标、统计结果、图表结论或参考文献事实。
- 不把没有记录的尝试写成“我们最初采用……后来发现……”，不把猜测写成真实实验过程。
- 不凭空增加消融实验、基线、敏感性分析、故障排查、参数标定、文献或工程应用效果。
- 用户没有提供真实作者决策或调试记录时，只能写“当前选择及其依据”，不得强行制造“思考痕迹”。
- 不能以规避学术审查、掩盖代写或保证绕过 AI 检测为交付目标；应把工作定位为事实保真的学术编辑。

## 何时使用

- 用户要求对数学建模论文“降 AI 率、降模板感、降重复、改得更像自己写的”或自然化改写。
- 用户要求重写模型建立、模型假设、方法选择、结果分析或结论，使其少套话、更多证据和判断。
- 用户要求把已有代码注释改成简洁、具体、解释“为什么”的研究代码注释。
- 用户已经有实验、模拟或建模结果，只需要提升论文表达，不需要重新求解问题。

以下情况不要单独使用本 Skill：需要选择或求解模型时转入建模 Skill；需要统一论文结构时转入
`math-modeling-paper-writing`；需要验证数据、引用或数学正确性时使用相应检查 Skill。

## 工作模式与路由

先判断当前请求属于哪一种模式，只读取相关参考文件：

| 模式 | 适用内容 | 必读参考文件 |
|---|---|---|
| 全局自然化 | 多个章节或全篇统一风格 | `references/global-style.md`、`references/ai-patterns-and-rewrites.md`、`references/audit-checklist.md` |
| 模型建立叙述 | 模型选择、假设依据、公式衔接和推导说明 | `references/model-building.md`、`references/audit-checklist.md` |
| 结果分析叙述 | 表格/图形观察、变化规律、机制解释和验证 | `references/result-analysis.md`、`references/audit-checklist.md` |
| 代码注释 | Python、MATLAB 或伪代码中的研究注释 | `references/code-comments.md`、`references/audit-checklist.md` |

若任务跨多个模式，先按章节分别处理，再做一次全局审计；不要把四份参考文件无差别全部展开。

### 默认强力自然化模式

默认使用强力自然化模式处理论文正文，但强力只作用于表达层，不作用于研究事实层。

允许：
- 主动句与被动句转换；
- 调整句子顺序；
- 一句拆分为多句；
- 多句合并；
- 调整段落内部的信息组织；
- 删除重复主语、空泛评价和多余连接词；
- 在不改变含义的前提下替换不准确或模板化表达。

禁止：
- 修改公式、数据、变量、单位、图表编号、引用和结论方向；
- 删除支撑结论所必需的条件；
- 将相关性改写成因果关系；
- 添加未做过的实验、比较、调试过程或作者经历；
- 为了制造变化而改写本来已经准确、简洁的句子。

## 输入要求

优先收集以下材料，缺少时只询问会影响事实保真的最小集合：

1. 待改写的段落、章节、Word/Markdown 文件或代码片段。
2. 目标语言、目标期刊/竞赛格式以及希望保留的作者术语和语气。
3. 与文本对应的事实证据：题面、模型公式、实验记录、代码、表格、图、结果文件和真实引用。
4. 若要写方法权衡或调试过程，提供实际考虑过的方案、失败现象、排查记录和修正结果。

没有第 3 项时可以做保守的语言改写，但必须把无法核验的数字、机制和经历标记为 `[待核验]`，
不能用“合理的示例”填进去。

## 执行流程

1. **锁定保护对象**：改写前先锁定以下保护对象：数字、百分比、区间和小数精度；公式及公式编号；变量、上下标、
   单位和参数；图表编号、表名和交叉引用；文献引用及其对应判断；算法名称、模型名称和评价指标；结论的方向、
   强度和适用条件。保护对象只允许调整周围的语言，不允许直接改写其实际含义。
2. **建立事实边界**：列出不能改动的公式、数字、单位、变量名、图表编号、引用和结论；区分已证实、
   用户判断、待补证据三类信息。
3. **定位模板痕迹**：检查段首连接词、连续同构句、空泛的“结果表明”、无数据的机制判断、重复主语、
   过密的总结句和不必要的复杂术语。
4. **选择章节策略**：按照上表读取对应参考文件。模型建立重点改“为什么这样建模”；结果分析重点改“看到了
   什么数据以及数据支持什么解释”；代码注释重点改“为什么这样实现以及哪里容易出错”。
5. **先保事实再改表达**：优先重排信息顺序、补足已有证据的来源、删掉冗余套话，再调整句式长度、段落节奏
   和术语；不为了追求变化而替换准确术语。
6. **输出改写稿和变更记录**：逐段说明检测到的模板模式、具体改法及其事实依据；重要改动不能静默完成。
7. **执行最终审计**：检查数字、公式、符号、单位、图表引用、引文、方法名称、结论强度和新增句子的证据；
   发现缺口就标记，不要用流畅文字掩盖。

强力模式优先使用以下表达层操作：
1. 删除没有实际逻辑作用的段首连接词；
2. 把抽象名词改成已有材料支持的具体动作和对象；
3. 将“方法 + 优点 + 重要意义”改成“操作 + 数据结果 + 适用条件”；
4. 把重复的并列句合并为有主次关系的段落；
5. 将过长句拆成“观察、解释、限制”几个信息单元；
6. 将证据放在对应判断附近；
7. 对结论补充已有材料中的范围、条件或限制；
8. 保留原文中已经准确且具有作者个人习惯的表达。

默认使用强力模式，但不同内容采用不同改写强度：
- 普通叙述段：可以进行较大句式和段落重组；
- 模型建立段：可以重组说明顺序，但公式前后的变量定义和推导关系必须保持；
- 结果分析段：可以重组观察和解释，但数据观察必须先于机制解释；
- 结论段：只允许压缩和增强准确性，不得扩大结论范围；
- 公式、表格、图注和交叉引用：只做周边文字调整，不改对象本身。

## 输出契约

除非用户只要求一句话改写，否则至少输出：

1. **自然化改写稿**：保留原章节层级、公式编号、图表编号和术语口径。
2. **改动记录表**：

   | 位置 | 原有问题 | 具体改动 | 依据/证据 | 是否需要作者确认 |
   |---|---|---|---|---|

3. **事实保真结果**：明确说明哪些数字、公式、数据、引用和结论保持不变。
4. **待补证据清单**：列出不能安全改写成断言的内容，例如缺少表格来源、真实参数依据或调试记录。

如果用户要求“只给最终稿”，仍应在内部执行事实审计；对存在事实风险的句子保留 `[待核验]`，不能为了版面
隐藏风险。不要给出“AI 率降低了 X%”之类未经实际检测和明确检测器定义支持的数字承诺。

## 与其他 Skill 的分工

- `math-modeling-paper-writing`：论文结构、章节规范、图表位置和正文组织。
- `math-modeling-model-and-methods`：模型选择、公式建立、算法路线和求解方法。
- `math-modeling-data-preprocessing`：数据清洗、划分、泄漏控制和预处理证据。
- `math-modeling-judge-review`：交付前的整体可信度、逻辑和扣分风险审查。

本 Skill 可以改写这些 Skill 产出的文字，但不能替代它们对模型、数据或论文整体的专业核验。
