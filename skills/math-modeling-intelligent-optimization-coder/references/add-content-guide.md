# 为 `math-modeling-intelligent-optimization-coder` 新增内容的维护指南

## 用途
这份文档是给 Codex 在后续继续扩展 `math-modeling-intelligent-optimization-coder` 时使用的维护规程。以后如果需要继续往这个 skill 里新增触发词、补提问规则、扩参数分支、加代码生成约束或修正常见跑偏行为，优先先读这份文档，再决定改哪里、怎么改。

## 什么时候应该新增内容
以下情况适合继续新增到这个 skill：
- 出现新的高频“写 GA/PSO/SA/DE 代码”口语表达，导致当前 `description` 或 `when_to_use` 覆盖不足。
- 需要补新的前置提问规则、参数分支、停止条件说明或输出要求。
- 需要补新的随机种子、贝叶斯调参、收敛曲线、日志输出等代码生成约束。
- 发现新的常见跑偏错误，例如没问清就写代码、把不同调参模式混写。

以下情况通常不应该直接加到这个 skill：
- 只适用于某一个具体题目或一次任务的专属设定。
- 只属于建模思路分析、不属于代码生成阶段的内容。
- 更适合放到 `math-modeling-brainstorm`、`math-modeling-objective-function-builder` 或其他专门数模 skill 的内容。
- 完整复制外部通用 `skill-creator` / TDD / benchmark 工作流。

## 新内容应该加到哪里
新增内容时，先判断它属于哪一类，再放到对应区块：

| 新增内容类型 | 应放位置 |
|---|---|
| 触发词、用户口语表达、何时应该调用本 skill | frontmatter 的 `description` / `when_to_use` |
| 触发后第一步该确认什么 | `什么时候优先用本 skill` / `第一优先动作` |
| 速度与准确率权衡、证据链要求 | `时间与准确率优先级` / `证据链与逻辑严谨性` |
| 编码前必须确认的信息 | `必须前置步骤` / `前置必问清单` |
| 不同调参模式下的提问分支 | `第二轮提问分支规则` |
| 算法专属参数问法 | `七个问题（GA 专用）` 或后续新增算法分支 |
| 易跑偏行为 | `Common Mistakes` |
| 低频长说明、维护导向规则 | `references/` |

## 新增内容的判断流程
以后新增内容时，按下面顺序判断：

1. 先判断这是“触发优化”还是“代码生成规则补充”。
2. 再判断它是“通用规则”还是“某一算法专用”。
3. 如果是通用规则，优先补到主 `SKILL.md` 的现有区块。
4. 如果只是低频长说明，优先放进 `references/`，主文只留入口。
5. 如果这条内容会改变触发边界，必须同步检查 `description` 和 `when_to_use`。
6. 如果它更适合别的数模 skill，就不要硬塞进本 skill。

## 写法规范
- 解释“为什么这样做”，不要只堆“必须”。
- 保留“先问清、后写代码”的主原则，不要让新内容削弱这一点。
- 新规则优先补到已有区块，不轻易新开大区块。
- 不写一次性案例总结，不写叙事式历史。
- 对算法专属内容要写清适用范围，避免把 GA 的规则错误扩展到所有算法。
- 如果内容很长、很低频、很维护导向，优先下沉到 `references/`。

## 修改前检查清单
- 这条内容是否真的是高频、可复用规则。
- 是否会改变触发边界。
- 是否和现有区块重复。
- 是否本来属于别的数模 skill。
- 是否需要同步调整 `description` / `when_to_use` / `第一优先动作`。

## 修改后检查清单
- frontmatter 是否完整，触发边界是否更清楚。
- 新内容是否放在了正确区块。
- 主 `SKILL.md` 是否仍然以“先确认需求，再进入七问”为主线。
- 是否引入新的重复表述。
- 是否把通用规则和算法专属规则混在了一起。

## 常见错误
- 还没确认用户是否真要写智能优化代码，就直接开始设计算法。
- 把固定参数设定和贝叶斯范围搜索混在一起。
- 跳过前置七问，或把七问拆成零散追问。
- 把某一算法的细节写成所有算法的通用规则。
- 增加内容后不检查 `description` / `when_to_use`。

## 维护时的默认原则
- 能少改就少改，优先最小改动。
- 先守住“先问清、后编码”的入口逻辑，再补具体算法规则。
- 先减少跑偏，再增加覆盖面。
- 如果新增内容很长，优先下沉到 `references/`。

## 建议回归测试提示词
- “帮我生成 GA 代码求解这个优化模型，先问我需要补哪些信息。”
- “我想用 PSO 落地这个数模优化模型，你先确认算法类型、输入和输出要求。”
- “给我写 DE 代码，但先别急着写，先把前置信息一次性问全。”
